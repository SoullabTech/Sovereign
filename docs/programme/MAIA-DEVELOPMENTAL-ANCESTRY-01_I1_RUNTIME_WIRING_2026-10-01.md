# MAIA-DEVELOPMENTAL-ANCESTRY-01 — I1 RUNTIME WIRING

**Date:** 2026-10-01 / 2026-10-02 UTC
**Standing:** implementation candidate
**Class:** A — memory/consciousness enforcement paths
**Canonical prerequisite:** I0 carrier admitted and I0A custody deviation recorded

## 1. Sole job

For future developmental memories only, preserve the exact UUID identity of the member↔MAIA conversation exchange that produced the derived memory.

I1 may:
- carry an explicit optional `exchangeId` through `MaiaConsciousnessInput`;
- pass the existing `/list` exchange UUID into `MemoryWriteback`;
- mint one UUID per accepted `/between` HTTP attempt before generation;
- reuse that same UUID for `/between` writeback and later conversation persistence;
- persist that UUID into `developmental_memories.source_exchange_id`;
- add falsifiers for these invariants.

I1 may not:
- backfill historical rows;
- infer lineage from content, time, embeddings, similarity, or session proximity;
- change retrieval, ranking, significance, memory content, or prompt participation;
- redesign cross-request retry/idempotency;
- weaken Sanctuary;
- deploy or promote production.

## 2. Identity contract

The durable source object is one conversation exchange:

`conversation_turns.exchange_id UUID`

The same UUID must be used by:
1. the accepted conversation attempt;
2. developmental-memory derivation;
3. the persisted exchange pair.

Identity domains remain distinct:

`exchange_id UUID ≠ reqId audit token ≠ numeric learning/logging turn id ≠ conversation_turns row UUID`

No conversion between these domains is authorized.

## 3. Route-specific behavior

### /list

The route already establishes `exchangeId` before generation. The server fallback `requestId` is itself generated by `randomUUID()`.

I1 therefore only propagates the existing UUID into `MemoryWriteback`.

### /between

The route previously had no exchange identity before `generateMaiaTurn`.

I1 mints one `crypto.randomUUID()` after message acceptance and carries it explicitly into:
- `generateMaiaTurn({ exchangeId })`;
- `MemoryWriteback`;
- `addConversationExchange(..., { exchangeId })`.

Cross-request retry identity remains out of scope.

## 4. Storage rule

`MemoryWriteback.writeDevelopmentalMemory` writes the optional exchange UUID into:

`developmental_memories.source_exchange_id`

If no exchange identity is supplied by a legacy/internal caller, the value remains NULL.

NULL means unknown ancestry. It is not an error and must never trigger inference.

## 5. Falsifiers

The candidate fails if:
1. `/list` generates a second lineage identity instead of reusing its exchange UUID;
2. `/between` uses different UUIDs for derivation and persistence within one attempt;
3. `reqId` is stored as source exchange provenance;
4. missing provenance becomes anything other than NULL;
5. historical rows are updated or backfilled;
6. Sanctuary write refusal is weakened;
7. retrieval, ranking, significance, or prompt semantics change.
