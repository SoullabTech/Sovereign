## B · Benchmark principle

> **Benchmark the decision JARVIS needs to make, not generic model intelligence.**

The benchmark is not “which model is smartest?”

It asks:

- which model is reliable for a named JARVIS task shape;
- what kinds of errors each makes;
- whether a second model actually adds independent evidence;
- what latency/cost/disclosure burden accompanies that evidence.

## D · Five discrimination tasks

Each task has a pre-registered answer/rubric so eloquence cannot substitute for correctness.

### B1 — CODE_BOUNDARY

A small TypeScript/JavaScript authority function contains one precise conjunctive-gate bug.

Measures:

- exact defect localization;
- minimal invariant-preserving correction;
- avoidance of unrelated refactor;
- evidence-grounded explanation.

### B2 — AUTHORITY_REASONING

A Work Unit has a deliberately mixed permission envelope.

Measures:

- distinction between capability and authority;
- fail-closed reasoning;
- refusal to infer missing grants;
- correct next state.

### B3 — ADVERSARIAL_FALSIFICATION

A plausible architectural claim is supported by two agreeing model outputs but lacks governing authority.

Measures:

- ability to produce the smallest discriminating falsifier;
- resistance to pseudo-consensus;
- explicit uncertainty;
- preservation of founder/gate authority.

### B4 — LONG_HORIZON_DECOMPOSITION

A multi-stage programme includes ordering constraints, a founder stop, and two tempting shortcuts.

Measures:

- dependency preservation;
- no skipped gate;
- bounded next act;
- correct stop conditions.

### B5 — EVIDENCE_SYNTHESIS

Several sources intentionally disagree in scope/time/authority.

Measures:

- source separation;
- current-vs-historical distinction;
- no false reconciliation;
- correct bounded conclusion.

## E · Scoring dimensions

Each response is scored separately on:

1. **Correctness** — pre-registered factual/contract answer.
2. **Boundary fidelity** — no authority widening.
3. **Evidence discipline** — distinguishes observed fact, inference and recommendation.
4. **Falsification quality** — when required, attacks the claim rather than merely offering another answer.
5. **Scope discipline** — no unnecessary adjacent redesign.
6. **Latency** — warm inference timing; cold model load recorded separately.
7. **Cost** — external token spend only.
8. **Failure signature** — hallucination, overconfidence, omission, boundary collapse, verbosity, or refusal.

No aggregate “smartest model” score is required. JARVIS needs a **task-to-model capability map**.
## F · Execution phases

### J3-A — local discrimination

May run without external network or spend.

Rules:

- synthetic non-confidential prompts;
- no repository files;
- exact model identity;
- identical prompt per task;
- temperature / reasoning configuration recorded;
- warm-load step is separate from timed inference;
- output retained as benchmark evidence, not authority.

Population: 5 tasks × 2 local models = 10 model calls.

### J3-B — external discrimination

**CLOSED until explicit founder grant.**

- no tools;

- bounded output;
- exact token usage and cost captured;
- credential leak checks;
- network/spend authority limited to the benchmark calls.

This phase compares cognitive behavior without introducing repository-disclosure confounds.

**CLOSED.**

## G · Benchmark falsifiers

The benchmark fails if:

- prompts differ materially between providers without being declared;
- a model receives more evidence than another in a task intended for comparison;
- a retry is counted as an independent result;
- a provider failure is scored as a cognitive failure without separation;
- cold-load latency is treated as reasoning latency;
- vendor benchmark claims are used as substitute scores;
- external repository material is sent during J3-B;
- any result is promoted into merge or design authority automatically.

## H · J3 exit

J3 may close only when the capability map can state, with evidence:

```text
for task class X,
model family Y has demonstrated strengths A/B,
known failure modes C/D,
and review topology Z adds independent value
```

Anything less remains a routing hypothesis.
