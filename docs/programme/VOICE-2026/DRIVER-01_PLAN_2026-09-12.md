## 0. The answer to the founder's flagged question first

**XCUITest does not require rebuilding the harness.** A UI-test bundle drives any installed app by bundle identifier — `XCUIApplication(bundleIdentifier: "life.soullab.voicekernel.k00")` — and needs no test hooks, no launch arguments, no linkage to the app, and no change to the app's source or signature. The UI-test bundle must be hosted by *some* app target in its own Xcode project; that host is a **separate, empty placeholder app** (the driver's host), not the harness. The device therefore carries three signed bundles: the untouched harness (`24a6fcfa1`, dylib `CC0D3604-7902-373E-A2BB-2C093D9BF804`), the driver host, and the XCTest runner. The organism measured is the exact organism already measured.

Two things must be said plainly, because they are the driver's own divergences from the manual protocol, and they are recorded as strata, not hidden:

- **Launch authority.** A manual sample is launched by SpringBoard from an icon tap. An XCUITest sample is launched either (Mode I) by the driver tapping the harness icon on SpringBoard through `XCUIApplication(bundleIdentifier: "com.apple.springboard")` — the closest reproduction of the manual act — or (Mode L) by `XCUIApplication(bundleIdentifier:).launch()`, where testmanagerd launches the process. Mode L is a different launch path from the icon; it is not a debugger and injects nothing, but it is not SpringBoard either. **Mode I is the primary design; Mode L is the fallback if Mode I proves unreliable in calibration.** Whichever runs is named in every ledger row (`AUTOMATED-COLD-ICON` / `AUTOMATED-COLD-LAUNCH`).
- **Termination.** `XCUIApplication.terminate()` sends the app a kill through testmanagerd; a manual force-quit is a swipe in the app switcher. Both end the process. The cold precondition is not inferred from either; it is **verified** (§3).

## 2. Constraint compliance (founder's eight)

1. **External control only.** The test bundle's whole vocabulary: launch/activate, terminate, read `app.state`, read button labels, tap `Enter conversation` / `Leave` / `Export journal` / the VP button, dismiss the export share sheet (`Cancel`/`Close` on the system sheet). No VoiceKernel API, no internal state, no `UserDefaults`, no fault injection, no app-side hook.
2. **No debugger, no hidden launch conditions.** No `launchArguments`, no `launchEnvironment` on the `XCUIApplication` (asserted in the source gate). Xcode's test runner attaches to the **runner**, never to the harness. Mode L's testmanagerd launch is listed here as the one launch-condition difference; the founder accepts or rejects it by choosing Mode I/L.
3. **Cold process demonstrated, not assumed.** Before every sample the orchestrator runs on the Mac `xcrun devicectl device info processes --device A0736AC8-…` and requires **no** `VoiceKernelHarness` process; the test additionally asserts `XCUIApplication(bundleIdentifier:).state == .notRunning` before launching. If either check fails the sample is recorded as `PRECONDITION-FAILED` with the offending process list and **is not repaired and is not counted**; the batch continues to the declared N so no selection is introduced. Generation 1 is verified from the journal (`graph_started generation 1`, no prior generation).
4. **Mac owns orchestration and custody.** `k00-driver-batch.sh <stratum-label> <N> [--vp on|off] [--w4 <ms>]`: for i in 1…N → precondition check → `xcodebuild test-without-building -only-testing:DriverUITests/OneSample` (one sample per invocation; the strongest precondition evidence, ≈ 30–45 s overhead each) → list `tmp/` in the app container → copy the one new `kernel00-*.jsonl` → SHA-256 → `k00-ledger.py` row → append to `…/ledger/<stratum>.md` and keep the file beside it. The classifier is invoked after the batch decision was already made; it never steers. **The declared N is finished.** (Alternative, faster: one test method looping N samples with only the in-test `.notRunning` check — offered as an option; not recommended, because the Mac-side process check between samples is what the founder asked for.)
5. **Strata never merged.** `MANUAL-COLD` (run 6 + Stage 1/2: 7 of 9 gen-1 starts took) is closed and stays its own row. Every automated sample carries `AUTOMATED-COLD-ICON` or `AUTOMATED-COLD-LAUNCH`. The record shows the strata side by side; convergence or divergence between them is itself a finding.
6. **Explicit reinstall boundaries.** Stage A: N cold launches on the current installation, no reinstall. Stage B: reinstall the exact same product (`devicectl device install app`), capture install output + `dwarfdump --uuid` of the product (must read `CC0D3604-…`) + post-install `installed / not running`, then N cold launches. The orchestrator refuses to run Stage B without those three artefacts written into the ledger directory. No reinstall inside a stage.
7. **W4 from the journal.** The W4 test method taps `Enter conversation`, sleeps a target (default 500 ms), taps `Leave`, waits 3 s, taps `Export journal`. **PASS-for-exercising the condition = journal `leaveConversation` command time − `enterConversation` command time ≤ 2000 ms**, computed by the ledger script from the JSONL, never from the driver's sleep. The W4 verdict itself (nothing after `session_released`; orphan-free replay) is read from the same journal. If the automation cannot get under 2000 ms, that is recorded as a limitation of the UI/test path.
8. **No VoiceKernel decision-logic change.** Nothing in `ios/VoiceKernel/` or `ios/VoiceKernelHarness/` moves. The source gate pins a content hash of both trees at `24a6fcfa1` and fails on any change; it also asserts the driver imports only XCTest, never `VoiceKernel`, and sets no launch arguments/environment.

```
VP-OFF        an optional matched control batch (N declared before running) is available with --vp off; not part of A/B unless the founder adds it
```

**Why 30.** The manual stratum shows 2 gen-1 failures in 9 (≈22%). With N = 30 per stage, an underlying 20% rate yields ≈ 6 failures; a stage with 0 failures against another with ≈ 6 is a gross difference the eye can see without a test, while differences of a few percentage points are **not** resolvable at this N and will not be claimed. N is fixed here; it is not chosen after seeing outcomes, and no early stopping exists.

## 4. Classifier (mechanical, closed vocabulary)

`k00-ledger.py` per journal: SHA-256 · session id · record count · subject check (gen-1 trace = 13 steps, `input_format_before_vp` absent) · cold check (`app_lifecycle didBecomeActive` first; `graph_started generation 1`) · class:
- `gen-1 listen` — first `floor_transition → listening` in generation 1 with no prior `recovery_requested`;
- `failure then recovery` — no gen-1 listen; `listening` reached in a later generation;
- `failure then degradation` — no listening; floor reaches `degraded`;
- `other observed shape` — anything else, with the reason printed (truncated export, interruption, precondition failure, …).
Plus evidence columns: `is_running_immediate`, `graph_started.engineRunning`, first-callback ms, listening ms, generations, hold seconds, and for W4 the Enter→Leave delta. It prints Markdown rows; it changes nothing.

## 5. What the driver cannot do, stated now

- It cannot make an icon tap identical to a human's; Mode I is the nearest reproduction and is labelled as its own stratum.
- It cannot read anything the harness does not show; if a needed control is not visible, that is reported, not worked around.
- It cannot prove the harness process was cold on the audio-server side; "cold" means process-absent, as in the manual protocol.
- It adds two signed bundles to the device; their presence is recorded as an environmental difference from the manual stratum.
