### D1 — `[Native] stopped_backoff` → `hands_free_restart` (CC:3086–3285)

**Trigger.** `listeningState` event with `status==='stopped'` (CC:3086) and `wantsToListen = isListeningRef || wantsContinuousConversationRef` (CC:3090).

**Sequence, in order.**
1. `nativeStatusRef='stopped'`, `isRecording=false`, `onRecordingStateChange(false)` (CC:3067–3073) — parent `setIsListening(false)` (OC:1822).
2. If `isListeningRef && accumulatedTranscript` → **commit** as `native_stop` dispatch + `onTranscript` (CC:3093–3101). *(Not gated on `isProcessingRef`; not gated on `isSpeakingRef`.)*
3. Grace check: `msSinceStart = now − lastNativeStartAtRef` (CC:3108); if `< 1200` → "Idle stop within grace — not counting as failure" (CC:3111–3113); else `consecutiveRestartCount++` (CC:3116).
4. If `consecutiveRestartCount > 10` → `isListening=false`, `wantsContinuous=false`, `onRecordingStateChange(false)`, counter reset, **return** (CC:3122–3130). No MicState write here.
5. **`setMicState('IDLE','listeningState:stopped')` unconditionally** (CC:3133) — including from `PLAYING_TTS` while MAIA is still speaking.
6. `isConversationAlive` (CC:3136–3140; windows 30 s transcript / 15 s audio-end / 10 s mic-tap, CC:88–90) and `authorityGuard(source:'listeningState_stopped')` (CC:3142–3149).
7. If `allowed && handsFreeActiveRef && conversationAlive && !isSpeakingRef && !isProcessingRef` (CC:3151):
   - if `backoffStepRef >= 3` → `[HandsFreeFallback] backoff_exhausted`: `isListening=false`, `wantsContinuous=false`, `handsFreeActiveRef=false`, `listeningModeRef='PUSH_TO_TALK'`, `IDLE`, `backoffStepRef=0`, `onHandsFreeFallback()` (CC:3154–3177) — parent `setIsHandsFreeMode(false)` + toast (OC:10429–10433). **Return.**
   - else `delay = [800,1500,2500][backoffStepRef]`, `backoffStepRef++`, **`restartInFlightRef=true`** (CC:3181–3184), log `stopped_backoff` (CC:3186–3193).
   - `setTimeout(delay)` (CC:3195): **`restartInFlightRef=false` first** (CC:3196); then if `wantsContinuous && handsFreeActive && !isSpeaking && !isProcessing && micState==='IDLE'` (CC:3198): `ARMING` `'hands_free_restart'` (CC:3200); arm 3000 ms ARMING watchdog (CC:3223–3238: native `stop()`, `IDLE`); `await requestRestart('recognition_stopped', {forceOverride:true})` (CC:3247) → `startListening({forceOverride:true})` → **pre-emptive native `stop()` (CC:2764)** → listeners removed/re-added → `start()` (CC:3306). `finally restartInFlightRef=false` (CC:3268). Else "Conditions changed" + `backoffStepRef=0` (CC:3270–3272).
8. Else-if push-to-talk and not speaking → `isListening=false`, `onRecordingStateChange(false)` (CC:3274–3280). Else-if guard blocked → log only (CC:3281–3283).

## 5. Authority findings

**F1 — Things that can start native recognition on iOS.** One call site pair (CC:3306/3330), reachable only through `startListening` (CC:2644). But `startListening` is reached by **eleven** distinct requesters: `toggleListening` (CC:3917), imperative handle (CC:4092) — which fans out to parent P1, P2, P3 (×9 attempts), P4 — D1 (CC:3247), D2 (CC:2075), D3 (CC:2038), D6 (CC:3982), D7 (CC:4072). Eight of these are automatic. `requestRestart` (CC:3669) sits between them and `startListening`, but (i) `forceOverride` bypasses `authorityGuard` (CC:3728) and is set by D1 (CC:3247) and by `requestRestart` itself for every delegated start (CC:3735), and (ii) the 500 ms debounce is bypassed for forced calls (CC:2672).

**F2 — Things that can stop native recognition.** Seven native `stop()` sites (CC:1991, 2764, 2946, 3231, 3807, 3954, 4050) plus listener removal at two sites (CC:2866–2889, 3813–3847). Of these, CC:2764 runs on **every** start, so every requester in F1 is also a stopper of whatever engine is live — including an engine that has not yet reported `started`.

**F3 — Parent restarts are classified as user gestures.** `hooks/useVoiceSession.ts:78–82` calls `ref.startListening()`; the handle (CC:4091–4092) turns that into `requestRestart('user_tap')`. Consequences from source: `staleLatchesToClearForTap` clears `restartInFlightRef` and `isStartingRef` (CC:3684–3693); `restartPolicy` skips the push-to-talk refusal for `user_tap` (`restartAuthority.ts:102–105`); `authorityGuard` skips `push_to_talk_no_auto_restart` for `user_tap` (CC:148). P1–P4 therefore carry gesture-level authority without a gesture. **[INFERENCE]** The declared rule "only requestRestart may initiate" (CC:52–60) holds syntactically; the *policy* it applies is source-labelled by the caller, and the parent labels every automatic restart `user_tap`.

**F4 — D4 has no native guard.** CC:656–686 is commented "WEB path only" (CC:653) but tests only `isListening/isRecording/isProcessing/handsFree`; on iOS `isListening` is true from CC:2849. Its 600 ms callback runs `ensureFreshAndStart` → `initializeSpeechRecognition` unless a native `started` has already set `isRecordingRef=true`. Either outcome (§2 D4 a/b) writes CC state from the web path while the native path is live: (a) `MicState ERROR` + `isListening=false` + parent `setIsHandsFreeMode(false)`; (b) a second, web-side recogniser. Which one obtains is §6 Q1.

**F5 — `LISTENING_STOOD_DOWN` is a web-path verdict.** `CAPTURE_REASON_CODES.inactivity` (`micLiveness.ts:129`) is emitted only by `handleCaptureLoss('inactivity')`, whose sole caller is web `onend` (CC:1379). `handleCaptureLossFnRef` has no native caller (callers: CC:1331, 1379, 1412, 1694, 1706, 1774, 1788; the liveness effect returns early on native at CC:1748; the track listeners attach only to a web `getUserMedia` stream at CC:2506). Its action is `MicState ERROR`, `isListening=false`, `wantsContinuousConversationRef=false`, `restartInFlightRef=false` (CC:1652–1665) — which silences D1 (`wantsToListen` false unless `isListeningRef`) and D2 (`wantsContinuous` false), and parks the mic until a `user_tap` (`authorityGuard` admits `ERROR`, CC:143). It reports `level:'info'` (CC:1662; `micLiveness.ts:267–268`), which the parent ignores except via `onRecordingStateChange(false)` (OC:10440, OC:1822).

**F6 — Things that can discard captured text (`accumulatedTranscript`).** Twelve writes. *Commits* (text leaves via `onTranscript`): CC:2208 (`process_accumulated`), 2939 (`native_silence` 2.5 s), 3037 (`native_audio_silence` 1.5 s), 3096 (`native_stop`), 3783 (`manual_stop`). *Salvage to parent draft*: CC:1533. *Silent discards*: CC:814 (web `onstart` non-continuation), **1971 (`isSpeaking` true: "Discarding accumulated transcript (MAIA started)")**, 2149/2176 (dedup), 2197 (echo block). *Replace*: **CC:2923 `accumulatedTranscript.current = transcript`** — every native partial overwrites the accumulator with the plugin's latest `matches[0]`; there is no append and no segment carry on this branch. **[INFERENCE]** A recogniser that re-segments mid-task and emits a shorter partial therefore shortens the accumulator; the subsequent 2.5 s/1.5 s timers commit only what the last partial held (the E16 long-utterance mechanism). Four sites (1971, 2149, 2176, 2197) discard without salvage.

**F7 — No single place knows the whole state.** The lifecycle is spread across: `micStateRef` (declared "single source of truth", CC:354–357) which is written from 27 sites and never records `CAPTURING`/`WAITING_FOR_TTS`; `nativeStatusRef` (declared "single source of truth for native listening state", CC:337) read by only two sites; `isListening`/`isListeningRef`/`isRecording`/`isRecordingRef` duplicated as state+ref and written from >30 sites; `wantsContinuousConversationRef`, `handsFreeActiveRef`, `listeningModeRef` (three overlapping mode flags); `restartInFlightRef`/`restartRequestInFlightRef`/`isRestartingRef`/`isStartingRef` (four in-flight latches); plus the parent's own `isListening`, `isMicrophonePaused`, `isAudioPlaying`, `isResponding` and `voiceSession.state.phase` (hooks/useVoiceSession.ts:167) which P3 and P4 use to *verify* restarts. Native engines have **no generation identity**: `recognitionEpochRef` increments only in web `onstart` (CC:771); the `listeningState` payload is `{status}` (CC:3058); listeners are torn down and re-added per start (CC:2866–2889, 3058), so any `stopped` arriving after re-attachment is processed by the new closure as if it belonged to the new engine (consistent with E16.5; the plugin side is outside this census).

**F8 — The conversation-alive gate self-refreshes.** `lastMicTapAtRef=Date.now()` is written at CC:2668 on **every** `startListening`, including forced restarts from D1/D2/D3/D6/D7/P1–P4. `isConversationAlive` (CC:81–92) is true for 10 s after that write. **[INFERENCE]** While restarts are occurring at sub-10 s intervals the gate cannot expire, so it cannot terminate a restart storm.

**F9 — `isSpeaking` fan-out.** One prop transition (`isAudioPlaying || isMicrophonePaused`, OC:10421) drives: on `true` — transcript discard (CC:1971), two timer clears (1976–1981), `PLAYING_TTS` (1984), native `stop()` (1991), `isRecording=false` (1997), `isProcessingRef=false` (2020); on `false` — D3 immediately, D2 at 800 ms, D4 at 600 ms, and (for the same underlying event) P1/P2/P3 from the parent at 300/200/0 ms + rAF. Up to six restart requests per turn boundary from source alone; which of them are refused depends on timing that `restartRequestInFlightRef` (CC:3676) serialises only for overlapping requests.

**F10 — Native audio session.** CC never calls the `AudioSessionManager` plugin (import CC:10; refusal comment CC:3288–3292). The parent calls `prepareForSpeaking` per TTS turn (OC:2006) with a 5 s timeout. Nothing in CC or OC calls `prepareForListening`/`stopAllAudio` on the `/maia` path (other callers listed in §1 #34 are not established as reachable from `/maia`).
