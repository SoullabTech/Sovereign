## 4 · Deterministic-first restored without breaking purity

J5 requires deterministic capability first.

Canonical R3 did not represent deterministic capability in its routing contract.

The repair does not import the deterministic registry into the pure router.

Instead MAIN:

1. reads the requested capability;
2. checks it against canonical `deterministic.mjs`;
3. passes only the structured fact:
   - capability name;
   - registered true/false;
4. invokes the import-free router.

A registered deterministic capability produces:

- no model family;
- no challenger;
- no provider transport;
- `execution_disposition: deterministic`.

This preserves both J5 and canonical R3 purity.
