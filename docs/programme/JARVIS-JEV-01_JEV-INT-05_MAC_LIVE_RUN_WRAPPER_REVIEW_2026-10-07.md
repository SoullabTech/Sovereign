## Independent, synthetic-only findings — require bounded correction before activation
The portable witness `independent-live-wrapper-probes.mjs` takes repository/output/T7 paths as arguments and saved `independent-probes.json` (SHA-256 `8fbd95da27b4603f2c2cc372861186d95741645521371a77472c79155a3c4d4b`). Its ordinary exit 0 means measurements completed, NOT that the negative findings passed.

**LW1 — remote-grant transport substitution falsifies provider provenance.** Under a *synthetic* `EXTERNAL_PINNED` grant and temporary test-only open gate, a caller-supplied `deps.createTransport` returned a made-up valid reply without contacting TypeSafe. The wrapper reported `ran:true` and recorded a provider-shaped observation. One injected fake send, zero actual provider sends. The grant pins the URL passed to the transport factory but does **not** enforce which transport the caller returns. This test does not imply a real provider was contacted. *Correction:* permit injected transport factories only for explicit loopback-mock runs, never for `EXTERNAL_PINNED`; the remote path must select the reviewed hardened adapter itself, with a test that a forged factory cannot populate a remotely authorized ledger.

**LW2 — history loss during response escapes as an unstructured exception.** After a localhost request reached the disposable server, the witness renamed its synthetic ledger to `.preserved` before returning the reply. The wrapper threw `LEDGER_NOT_INITIALIZED` instead of returning a content-free stopped result. The original ledger bytes were preserved in the disposable test directory until normal fixture cleanup. One localhost request, zero provider calls. This contradicts the wrapper's expected-refusal / stop semantics; no extra request was observed. *Correction:* preserve the attempted/uncertain crossing and return a sanitized `HISTORY_UNAVAILABLE` stop without claiming the observation was persisted; do not create, repair or resend.

**LW3 — distinct-volume guarantee is checked only at preflight.** Starting with the actual Mac and T7 devices, after the first valid mock settlement a synthetic checkpoint directory was renamed and replaced by a symlink to an equally named checkpoint copy on the Mac volume. The two-store hashes still agreed. A **second local HTTP request was allowed**, even though the checkpoint had moved onto the **same device** as the ledger and the grant required `DISTINCT_DEVICES`. The witness restored only its disposable paths after the measurement. This is an after-preflight configuration-change case, not a literal T7 power-loss or unmount test. *Correction:* revalidate physical device identity and mountpoint before each reservation and again immediately before dispatch, with conservative refusal on replacement, symlink, remount or unavailable storage; retain the existing hash-chain/checkpoint ordering and no-retry rules. Merely rechecking the anchor hash does not establish physical independence.

**LW4 — lower-than-minimum free-space setting is accepted.** The wrapper advertises `MIN_FREE_BYTES=67,108,864`, but exposed `checkStorage(... minFreeBytes:0)` accepted the reduced threshold. The default threshold also passes on this well-provisioned Mac; the problem is caller override, not a reported real disk shortage. *Correction:* enforce a nonnegative safe-integer config and an effective minimum no lower than the stated 64 MiB. Test that zero/NaN/negative values cannot disable the actual minimum.
