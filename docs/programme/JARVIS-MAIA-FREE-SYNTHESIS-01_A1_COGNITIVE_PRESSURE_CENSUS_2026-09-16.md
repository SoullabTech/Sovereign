## 1. Executive finding

MAIA does not have one cognitive environment. FAST, CORE and DEEP assemble materially different forms of cognition and different amounts/types of behavioral direction.

The source supports a serious prompt-pressure hypothesis, but does **not** yet establish that prompt pressure caused the founder-observed loss of gestalt. That is reserved for controlled replay / ablation.

Two concrete structural findings require no subjective judgment:

1. CORE exposes up to **28 conditional addendum channels** and then appends four standing blocks unconditionally through `appendAllContextAddenda()`.
2. CORE has at least **five literal duplicate-injection paths**: MAIA mode, Scribe-session discussion, Wu Xing, Astrology and Studio can be injected by the shared addenda builder and appended again afterward in `corePathResponse()`.

## 4. Tier composition

### FAST

FAST builds its own system prompt directly in `maiaService.ts`. It carries the large runtime prompt and many dynamic interpolations: user identity, place, mode adaptation, time awareness, cognitive scaffolding, relationship context, Selflet, Sanctuary, wisdom, knowledge field, epistemic path, Spiral/Wu Xing/framework/lens/governor/mode, astrology, Studio/Practice Field, Member Web, field wisdom, recall, episodes, atoms, divination, relational context, state vector and youth context when present.

Its separate user-input context can additionally carry a memory bundle, recent thread, AIN knowledge, recall instruction and sensitive-content instruction. Policy adaptation and field intelligence may then extend the system prompt.

### CORE

CORE uses `buildMaiaWisePrompt()`: relational identity blocks → complexity voice → temporal context → wisdom adaptation → consciousness context → mode-specific guidance → cognitive scaffold → awareness-language rules → recent 4-exchange aperture → relationship memory → optional self-awareness → shared addenda.

After that builder returns, `corePathResponse()` may append more content again: user identity, MAIA-mode, Scribe-session, Wu Xing, Astrology, Studio, Practice Field, wisdom routing, state-vector contract, policy adaptation and field intelligence.

**Confirmed duplicate candidates:** MAIA-mode, Scribe-session, Wu Xing, Astrology and Studio are already fields in `ADDENDA_SPECS` and are then manually appended again when present.

### DEEP

DEEP primary is structurally different: its first cognition stage is `consciousnessWrapper.processConsciousnessEvolution()` over a `ConsciousnessContext`, with a 5-exchange history aperture. It does not use the FAST or CORE system-prompt composition seam.

The DEEP repair path does use `buildMaiaComprehensivePrompt()` and therefore joins the shared addenda channel. This means a repaired DEEP answer can be produced under a materially different instruction environment from the original DEEP draft.
## 5. Post-generation pressure

All three serving tiers call the shared Socratic validator. The validator evaluates five layers: Opus axioms, Elemental alignment, phase awareness, caution compliance and language resonance.

FAST supplies no regeneration function, so validation is effectively observational there; its draft then passes through the mode-language filter and Selflet delivery guard.

CORE and DEEP can regenerate when the validator returns `REGENERATE`. CORE regeneration rebuilds through `buildMaiaWisePrompt()` but does not replay all of the manual post-builder additions used for the original draft, creating a second composition asymmetry within one tier.

`filterModeLanguage()` is narrower than its name suggests: substantive responses over 60 characters pass unchanged; it mainly replaces short greeting/service-language responses. `applySelfletDeliveryGuard()` is conditional on a required past-self acknowledgment.

Every model-generated path finally reaches `finalizeMemberFacingText()`: sanitize / internal-contract stripping → conditional Presence-mode constraints → identity-predicate guard. Presence mode scans five categories with four patterns each (questions, new concepts, next edges, reframing, advancement) and can convert trailing questions to statements and remove advancement phrases.

Therefore not every post-generation layer mutates every turn. The architectural fact is instead that multiple independent layers retain authority to reshape or regenerate an answer under different conditions.
## 6. A1 findings versus hypotheses

### Established by source census

- Three tiers do not share one cognitive composition architecture.
- FAST has a very large known static prompt before dynamic context.
- CORE has 28 conditional addendum channels plus four unconditional shared blocks.
- CORE contains five confirmed duplicate-injection paths.
- CORE regeneration does not reproduce the original composition sequence exactly.
- DEEP primary and DEEP repair operate under different context architectures.
- Several independent systems can constrain, regenerate or rewrite output after first generation.

### Not yet established

- That any one block is unnecessary.
- That raw prompt size alone causes lower relational quality.
- That duplicate injection caused the founder-observed loss of gestalt.
- That removing instructions improves MAIA.
- That relational geometry or a Gestalt Projection outperforms a simpler narrative representation.

Those are A5/A6 questions and require controlled comparison.

## 7. Immediate research implications

A2 should select historical "Alive MAIA" examples before any prompt diet is designed. A3 should distinguish constitution from behavioral coaching rather than merely shortening text. A5/A6 must include an ablation specifically for duplicated CORE addenda and another for inquiry/closing-question pressure.

The strongest current hypothesis is therefore narrower than "MAIA is over-prompted":

> MAIA's current cognition contains enough independent context and behavioral authorities that integration cost, duplicated direction and tier-specific composition are plausible contributors to reduced gestalt. Controlled ablation is required before any removal is justified.
