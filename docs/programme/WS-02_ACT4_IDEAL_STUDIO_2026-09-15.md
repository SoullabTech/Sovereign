## 1 · What the Studio is

> **Writer's Studio is the one place a writer returns to a Work and stays inside
> it** — writing it, thinking with MAIA about it, developing it, weighing
> possibilities, choosing what belongs, gathering what is emerging, and preparing
> it to leave — **without ever needing to know where Soullab keeps those
> capabilities.**

The test of every ruling below: *does this let Kelly stay in Chapter 10?*

## 2 · The proposed Studio — two places, not four

```
                        WRITER'S STUDIO
                              │
                       ┌──────┴──────┐
                       │             │
                  STUDIO HOME    THE WORK
                  the shelf      one Work, one room
                  + return
```

Everything else stops being a **place** and becomes something that **appears
around the Work**. That is the whole recommendation in one line:

> ⭐⭐ **Four addresses and ~8 surfaces become TWO places and ONE locus.**

### The Work room, conceptually

```
ELEMENTAL ALCHEMY
Chapter 10                                    ← the locus. Everything is about this.

   THE WRITING                    MAIA
   section · whole                one presence, continuous
   ─────────────                  ───────────────────────
   write / revise                 talk about this passage
                                  read this Work developmentally
                                  offer wording — never apply it

            POSSIBILITIES          what has been authored here
            compare · choose       passage-as-opened vs any version
                     │
                   ADOPT           the one gesture that changes the book
                     │

   around the Work, when wanted:
   structure · materials · collections · emerging · prepare
```

⛔ **Not "everything on one screen."** One *intelligible place*, with a locus,
and capabilities that arrive because the writer is standing somewhere.

## 3 · Rulings, at the human-job level

### 3.1 · Writing

| Job | Ruling | Where it lives |
|---|---|---|
| write / revise at **section** scale | **KEEP** | the Work room, primary |
| write / revise at **whole-Work** scale | **KEEP** | the Work room, a view of the same locus |
| type into a pre-conversion continuous draft (Worktable) | **RESHAPE** | not a third editor — the **unconverted state** of the whole view, which says so |
| `/press/manuscript` **draft** tab | ⛔ **RETIRE the surface** | the capability is not lost: it is literally the same row through the same client |

⭐ **Section and whole are two genuine creative scales and both survive.**
Worktable is **transitional, not a scale** — the difference the writer should see
is *"this Work isn't in sections yet"*, not *a third editor*. And the
server-chosen mount should **say which scale it gave her and why**, since the
choice is partly not hers.

### 3.2 · MAIA — the evidence supports the expected collapse

| Today | Ruling |
|---|---|
| `StudioConversation` | ⛔ **RETIRE the surface** — it is the forgetting incarnation of the same seat |
| `EditorialConversation` | **KEEP + CONVERGE** — it becomes *the* conversation, not a second one |
| `MaiaColumn` | **RESHAPE** → the **arrival / empty state** of that one seat |
| `AskMaia.tsx` | ⛔ **RETIRE** — mounted nowhere |
| `/develop` readings | ⭐ **KEEP as a distinct FUNCTION · CONVERGE the surface into the Work room** |

⭐⭐ **`/develop` is genuinely different and the evidence says why**: a reading is
bound to `(draft_id, revision_number)` and **frozen**, assessed three-state
(current · superseded-say-which · unmeasured). It is *a reading of a revision*
that stays true while the draft moves. **That is a different relation to the
Work, not a different assistant** — so it becomes a **developmental lens on the
same MAIA presence**, in the same room, and stops being an address.

> The writer never chooses between `StudioConversation` and
> `EditorialConversation`. Those are implementation facts, and ACT 3 showed they
> are two incarnations of one intended presence.

⚠️ **One thing the convergence must not flatten:** live editorial exchange is
about **a passage** and a developmental reading is about **a frozen revision of
the Work**. Same presence, two honest scopes. Collapsing the scopes would be
convergence destroying meaning.

### 3.3 · Return

| Job | Ruling |
|---|---|
| remember the Work | **KEEP** — already works |
| remember the **place in the Work** | ⭐ **ADD (connector)** — a section identity on the Return link; the parameter already exists |
| find the editorial relationship I was in | ⭐ **ADD (read + choice surface)** |
| remember comparison selection | ⛔ **KEEP AS IS** — presentation state, cheap to lose |

**Recommended behaviour** (not UI):

```
Elemental Alchemy
Last worked  yesterday · Chapter 10

Open work here
  · an editorial conversation about this passage      [open]
  · 3 authored versions                               [see]

[ Continue where I left off ]          [ Open the Work ]
```

⛔⛔ **And the constitutional restraint stands, unweakened.** Where the locus is
**unambiguous**, restore it. Where **more than one legitimate relationship
exists**, ⛔ do not choose — **show them and let her choose.** UI-01A refused a
most-recent guess for a reason, and "meaningful return" must not become that
guess wearing a friendlier name. *Restore what is unambiguous; offer what is not.*

### 3.4 · Adoption — the one real ADD

```
compare  →  choose  →  EXPLICIT ADOPTION GESTURE
                              │
                    authorizeVersion()        ✅ already built
                    evaluateExecutionFit()    ✅ already built
                    executeAuthorization()    ✅ already built
                              │
                       manuscript changes
                              │
                    provenance stays visible
```

**ADD, minimally:** one route and one member control. ⛔ No magical overwrite,
⛔ no silent adoption — and equally ⛔ **no standing promise of an act with no
control capable of doing it.** Today the Studio says *"Nothing changes until you
explicitly adopt a version"* on every screen and offers no way to do so; that
sentence should become true in both directions.

### 3.5 · The capabilities inside `/press/manuscript`

| Tab | Capability ruling | Surface ruling | New home |
|---|---|---|---|
| manuscript | **KEEP** | ⛔ RETIRE | the Work room (outline / whole view) |
| draft | **KEEP** | ⛔ RETIRE | the Work room (same row, same client) |
| keeps | **KEEP** · **CONVERGE** with *marked lines* | ⛔ RETIRE | around the Work + Studio Home |
| **collections** | ⭐ **KEEP — exists nowhere else** | RESHAPE | around the Work — member-authored containers of keeps |
| **emerging** | ⭐ **KEEP — exists nowhere else** | **CONVERGE into the locus** | beside the section: it is already a **per-section, member-pulled** act |
| **export** | ⭐ **KEEP — the only export path** | RESHAPE | *Prepare*, a mode of the Work room |
| **book** | ⭐ **KEEP** | RESHAPE | *Prepare* |

⛔ **`/press/manuscript` does not survive as a member concept. Every capability
inside it does.** That is the distinction ACT 3 earned, and it is the single most
important ruling in this document after adoption.

⭐ **Emerging deserves special notice.** It is *member-pulled, verbatim-verified
recognition over one section* — it was already a per-section act living in
another product. Putting it beside the section is not a redesign; it is putting
it where it always belonged.

  `/develop` and *adding* to it.
