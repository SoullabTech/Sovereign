## 4. The architectural finding ACT 1 established, as the founder characterized it

> **The repository has developed sophisticated human-readable authority distinctions without a
> corresponding machine-readable authority substrate.**

The distinctions the repository genuinely knows:

```
recorded ≠ ratified      draft ≠ frozen      executed ≠ accepted
live ≠ designed          canonical ≠ programme record
```

⛔ None of which an agent can reliably determine — so standing gets inferred from filenames, prose,
location, recency, headings, words like `COMPLETE`, conversational context, and remembered
instructions. ⭐ **Those are precisely the conditions under which a capable agent becomes
confidently wrong about standing** — which is worse than being uncertain, because confidence
suppresses the check.

⭐ Founder's framing of F7, recorded for the eventual write-back design: git records one verb,
`WRITE`, while governance requires `record · propose · adjudicate · ratify · supersede · close ·
accept baseline · alter runtime · alter schema`. The `typecheck:baseline --accept-current` pattern
matters because it inserts refusal at an authority transition:

```
ordinary execution → REFUSAL → explicit authority-bearing gesture → standing changes
```

⛔ Recorded as a question ACT 1 earned, **not** as a mechanism authorized. Not for ACT 2.
