Do not start with a giant pattern prompt. First define the **epistemic layers** and hold them
apart structurally.

```text
DOMAIN OBSERVATION        what actually occurred, in which domain, when — no inference
       ↓
DOMAIN-LOCAL PATTERN      what repeats WITHIN a domain — dream motif recurrence, decision cycle,
```

### Worked example — six claims, and MAIA must know which one she is making

| Layer | Claim |
|---|---|
| **Domain observation** | On 14 May the member recorded a dream of standing at a doorway. On 2 June the member said they had postponed the decision again. |
| **Domain-local pattern** | The doorway image has appeared in three recorded dreams. The commitment has been postponed four times. |

The first opens consciousness. The second colonizes interpretation.

### Relation types — a taxonomy of what can be recognized

"Pattern" is not one thing. UNDERSTAND must define, at minimum, and DECIDE must encode as a closed
enum:

```text
RECURRENCE       the same movement repeats
DEVELOPMENT      the movement changes over time
COMPENSATION     one domain expresses what another suppresses
SYNCHRONY        different domains enter similar phases simultaneously
POLARITY         two domains occupy complementary positions
TRANSITION       multiple systems reorganize around a threshold
INTEGRATION      previously separated patterns become consciously related
NOVEL EMERGENCE  something appears that the prior pattern does NOT explain
```

⭐ **NOVEL EMERGENCE is first-class, not an error path.** A bad pattern system becomes a machine
for proving its own theories. A good one must be able to return: *this person is becoming
something the previous model does not explain.* Otherwise MAIA turns development into prediction.

### Process ontology — what Spiralogic adds

Spiralogic makes this different from "these things are similar." MAIA can ask *what movement is
occurring?* — and different areas of life may occupy different positions at once:

```text
Career          FIRE  / emergence
Relationship    WATER / dissolution
Writing         AIR   / differentiation
Body            EARTH / consolidation
Dream life      threshold imagery
```

Relations among **processes**, not among topics. *"Your work is moving into Fire while your
relational life appears to be asking for Water. The tension may not be that one is wrong; you may
be living two developmental movements simultaneously."*

⛔ Elemental vocabulary is MAIA's, inside MAIA, in its established member-facing meaning. It does
not migrate to the JARVIS graph (R4), and a recurring elemental phase never becomes a trait.

## 3. DECIDE — the first bounded object

Do not try to map all of consciousness at once. The first object, as a **candidate** for DECIDE to
ratify or reject:

```ts
type NonEmptyArray<T> = readonly [T, ...T[]];

interface DomainObservation {
  id: string;                     // durable — later member acts must be able to refer back
  domain: Domain;                 // closed enum from UNDERSTAND; a domain keeps its epistemology
  occurredAt: string;             // when it happened in the member's life
  recordedAt: string;             // when it entered the system
  source: 'member_authored' | 'member_confirmed' | 'system_derived';
  ref: EvidenceRef;               // recoverable pointer; no prose duplicated here
}

interface PatternHypothesis {
  id: string;
  relation: RelationType;         // RECURRENCE | DEVELOPMENT | COMPENSATION | SYNCHRONY | POLARITY
                                  // | TRANSITION | INTEGRATION | NOVEL_EMERGENCE
  evidence: NonEmptyArray<DomainObservation>;   // ≥ 2 distinct domains — enforced, not requested
  domains: NonEmptyArray<Domain>;
  temporalSpan: { from: string; to: string };
  structuralForm: string;         // the movement, in process language — never a trait
  possibleMeaning?: string;       // optional by design — an honest hypothesis may stop before this
  authoredBy: 'MAIA';
  authority: 'SYSTEM_INFERENCE';  // literal type — cannot be promoted by any code path
  confidence: number;
  contradictions: DomainObservation[];
  alternativeInterpretations: string[];
  memberStance: 'none' | 'exploring' | 'recognized' | 'rejected' | 'modified' | 'complicated' | 'unresolved' | 'endorsed';
  history: NonEmptyArray<HypothesisEvent>;      // noticed → explored → … → current; append-only
  provenance: HypothesisProvenance;             // model, prompt contract hash, version, surfaced-under-consent ref
}
```

Load-bearing properties, each different in kind:

- **`evidence` is non-empty by type, and cross-domain by invariant.** An empty array does not
  satisfy the invariant; a single-domain array does not either. A hypothesis that cannot be
  constructed without ≥ 2 domains of evidence cannot be serialized without them.
- **Evidence and interpretation are separate fields.** `structuralForm` names a movement;
  `possibleMeaning` is optional. MAIA does not have to manufacture meaning because the schema has
  a slot for it.
- **`authority` is a literal, not an enum.** There is no `MEMBER_FACT` value on this object. Member
  endorsement changes `memberStance` and may produce a *separate*, member-authored object in the
  conscious map — it never mutates `authority`. ⭐ *No representation may acquire more authority
  by being copied into a more durable store.*
- **`history` is append-only.** Reformulation adds an event; it never rewrites the one before.
  The map keeps its own archaeology.
- **`NOVEL_EMERGENCE` and `none` are complete results.** A run that finds no cross-domain
  resonance returns nothing and is not a failure. A run that finds material the prior hypothesis
  does not explain returns `NOVEL_EMERGENCE` against that hypothesis, and is the most valuable
  result the system can produce.
- **Identity is durable.** A member's later explicit act — *"yes, that one"*, *"no, that's not
  it"* — must be able to refer to exactly the hypothesis and the evidence it was shown.

DECIDE also rules: which of readings A/B/C this object implements; the `Domain` enum; the
`EvidenceRef` shape (reuse the Writer's Studio triad if FIND confirms it fits); and what the
**conscious-map object** — the member-authored counterpart — is called and who may write it.

## 5. PROVE — falsifiers

Real member material (founder's own, under authenticated load, or a consenting tester), real
hypothesis, real rejection, real contradiction. The unit is not proven by a fixture that cannot
fail. **Zero identity claims.**

```text
F1   NO HYPOTHESIS WITHOUT ≥ 2 DOMAINS
     construct with single-domain evidence → type-level or DB-level refusal, never a 500.
F2   NO IDENTITY RENDERING
     no code path can render a PatternHypothesis as "you are X" / "you have X" — the
     formatter emits movement language + question form only; pinned by test.
F3   REJECTION HOLDS
     member rejects → memberStance = rejected persists → the same hypothesis is not
     re-surfaced; evidence is not deleted; a NEW hypothesis on new evidence may still form.
F4   CONTRADICTION IS NOT IGNORED
     new evidence contradicting a hypothesis lowers confidence, appends to contradictions[],
     appends a history event, and is visible at next encounter.
```
