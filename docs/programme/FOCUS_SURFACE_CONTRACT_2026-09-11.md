# FOCUS SURFACE CONTRACT

**Authored 2026-09-11 · branch `claude/focus-surface-design` · ⛔ NOT AUTHORIZED FOR BUILD.**

Synthesized from the nine accepted records, in the founder's read order. This contract states what
the visible Focus experience **must be**, not what a prototype happened to do.

> ⭐⭐ **Absence from the prototype cannot repeal a charter obligation, and presence in the prototype
> cannot create one.**

---

## 0 · How to read this document

Every substantive clause carries four fields:

```text
source              the accepted record and section the clause comes FROM
status              BINDING · AMENDED · IMPLEMENTATION EXPRESSION · UNRESOLVED · CONFLICT
amended_by          the later ruling that changed it, or `none`
prototype_evidence  where the 113KB prototype record bears on it, or NONE
```

**Status vocabulary — the whole point of the apparatus:**

| status | meaning | may a developer build from it? |
|---|---|---|
| **BINDING** | ratified obligation from charter, field/orbit, shared focus, creative learning, or scale coherence | yes |
| **AMENDED** | binding, in its amended form; the superseded form is named so it cannot return | yes, in the amended form |
| **IMPLEMENTATION EXPRESSION** | one lawful way the prototype expressed a binding clause. **Evidence of feasibility, never a source of authority.** A different expression that satisfies the binding clause is lawful | yes, but it is not the law |
| **UNRESOLVED** | a founder ruling is owed before this can be built | **no** |
| **CONFLICT** | two accepted records pull against each other and the reconciliation is not ruled | **no** |

⛔ **`prototype_evidence` never upgrades a clause's status.** The prototype is 113KB against the
charter's 17KB, and quotation density is not authority. Where the prototype is the only source for a
requirement, the clause is **IMPLEMENTATION EXPRESSION** or **UNRESOLVED** — never BINDING.

⭐ **One exception, stated so it is not smuggled:** the prototype record contains **founder rulings
made during the prototype's life** (F-SCOPE §9, arrival vs standing authority §11, the amended orbit
law §23.2, the conversation's home §27.1, WS-ROOM-01/02 §31–32). Those are rulings that happen to be
recorded in that file. They are BINDING as rulings, and each is marked as such — ⛔ never because the
prototype implemented them.

# 1 · MUST BE VISIBLE

What the writer must be able to perceive in the room. Perceptible means **in every channel that
carries meaning** — visual, keyboard, screen reader, touch, cognitive.

### FOCUS-SC-01 · The Work is the visual centre and does not compete for it

```text
source              D9_FIELD_AND_ORBIT §1, §6 (F-ORBIT), §9.3
status              BINDING
amended_by          none
prototype_evidence  §1 (FIELD), §13.1 (rail witness POSITIVE), §25.3 ("ARRIVAL YES")
```

The writing field is the room. Every other capability is perimeter. *The Work commands attention;
the room reveals possibility; the field invites creation.*

### FOCUS-SC-02 · Capability is perceptible without being solicitous

```text
source              D9_FIELD_AND_ORBIT §5 (Legible Form), §5.1, §7
status              BINDING
amended_by          D9_FIELD_AND_ORBIT §5.1 narrowing — see below
prototype_evidence  §1 (RAIL), §13.1 founder witness: "you can tell where the power is
                    without feeling asked to use it"
```

**The walkable audit is the acceptance instrument, element by element:** read each visible element as
a sentence addressed to a writer mid-paragraph.

```text
⭐ PASSES   "I am here when you need me."
⛔ FAILS    "Use me. You may be neglecting something."
```

**AMENDED (founder, in place, D9_FIELD_AND_ORBIT §5.1):** the earlier absolute *"a number is always a
demand"* is superseded. The operative rule is: **in the creative field, UNSOLICITED numbers behave as
demands.** A section count inside Structure, summoned by the writer, is lawful. The same count
sitting beside them while writing is not.

⛔ **Therefore forbidden in the composing field:** badges · counts · progress indicators · urgency
cues · unread markers · "N pending".

### FOCUS-SC-03 · The held focus must remain perceptible for as long as it is operative

```text
source              PROTOTYPE §9 (F-SCOPE, founder ruling — BINDING as a ruling)
status              BINDING
amended_by          PROTOTYPE §14 (acknowledgement, not repetition)
prototype_evidence  §7 (the defect), §21.2 (the strip's form), §14.1 (accessible state)
```

**F-SCOPE, verbatim:** *FAIL when a scope the system holds as the writer's chosen or authorized
boundary remains operative while that scope is no longer perceptible to the writer.*

**Two-condition test — both load-bearing:** (1) is the scope **attributed to the writer**? (2) is it
**operative** — does the system act under it? Both yes → it must remain perceptible. Either no → not
F-SCOPE, and F-SCOPE must not be read as a demand to expose all cognition.

**AMENDED by §14:** F-SCOPE requires *perceptibility*, **not repetition**. A screen-reader writer
must have an equivalent perceptible form — ⛔ **not a spoken reminder.** Repeated reminders are
F-REACTIVE; solving F-SCOPE by repetition migrates the violation.

### FOCUS-SC-04 · Shared attention survives the transfer of keyboard focus

```text
source              PROTOTYPE §8.3, generalized into F-SCOPE §9 (BINDING as a ruling)
status              BINDING
amended_by          none
prototype_evidence  §7 — the browser's native selection was being treated AS the focus state;
                    clicking the composer collapsed it while MAIA remained scoped
```

⭐ **The focus state is not the browser selection.** It must survive the composer taking keyboard
focus, an orbit opening, and scrolling. ⛔ **An invisible scope is indistinguishable from no scope,
and worse than none, because the system acts on it.**

### FOCUS-SC-05 · The focus strip states the writer's attention; it does not whisper metadata

```text
source              PROTOTYPE §21.2 (founder witness ruling — BINDING as a ruling)
status              BINDING
amended_by          none
prototype_evidence  §21.2 — 15.2px → 17.9px, frame's own gold, manuscript serif for the
                    excerpt, click scrolls back to what was framed
```

The strip is the writer's own attention carried into the conversation, not a metadata chip. **The
type sizes, colours and serif are IMPLEMENTATION EXPRESSION.** The binding part: *frame and strip
read as two manifestations of one thing*, and the strip is actionable back into the Work.

### FOCUS-SC-06 · Every arrival is the quiet room; standing authority is the exception

```text
source              D9_FIELD_AND_ORBIT §9.2; PROTOTYPE §11 (founder ruling — BINDING)
status              BINDING
amended_by          none
prototype_evidence  §3 ("arrival is quiet — all three panels carry `hidden`", 0 localStorage)
```

> **Reset the room. Preserve the permission. Show only what is still in force.**

```text
INHERITED TOOL STATE  → RESET on arrival          "Structure was open yesterday"
STANDING AUTHORITY    → REMAINS PERCEPTIBLE       "You may restructure this chapter"
```

**Duration boundary (§11.2, BINDING):** explicitly standing authority may cross sessions; a
session-bounded request ends with the encounter; **an ambiguous one defaults to the NARROWER
authority** and is never silently promoted. A too-narrow authority is recoverable; a too-broad one is
not.

### FOCUS-SC-07 · Legible form must be delivered in more than one perceptual channel

```text
source              D9_FIELD_AND_ORBIT §5.3, §7
status              BINDING
amended_by          none
prototype_evidence  §4 (keyboard/SR/touch/cognitive), §15 (structural pass ≠ AT witness)
```

```text
VISUAL         quiet but unmistakable affordance · ⛔ no badges, counts, urgency
KEYBOARD       predictable tab order · visible focus states · ⛔ nothing hover-dependent
SCREEN READER  same capabilities named and reachable · ⛔ never announced as obligations
TOUCH          44px minimum · ⛔ no tiny edge gestures required
COGNITIVE      plain language · ⛔ no hidden mode knowledge, no spatial memory required
```

⛔ **The COGNITIVE row rules out spatial memory as the discovery mechanism** — *a room learned by
memorizing its corners is a room that must be operated.*

### FOCUS-SC-08 · Atmosphere may shape presence; it may never carry information

```text
source              D9_FIELD_AND_ORBIT §8.4, §8.5, §9
status              BINDING
amended_by          none
prototype_evidence  NONE — the prototype records no atmospheric behaviour
```

```text
⭐ LAWFUL     world-side and observable: time of day · session duration · where the
              writer is in the Work · what they explicitly opened or highlighted
⛔ UNLAWFUL   inference about the person: "you seem anxious" · "you appear blocked"
⛔ UNLAWFUL   atmosphere AS SIGNAL — colour, dimming or texture conveying state,
              progress, urgency, or MAIA's view
```

⭐ Atmosphere is exempt from the five-channel rule **precisely because it says nothing.** The moment
it means something it must be available in every channel — and at that moment it has stopped being
atmosphere.

# 2 · WRITER AUTHORITIES

What the writer may do. Each is an act the system must make available and must not simulate,
pre-empt, or perform on their behalf.

### FOCUS-SC-09 · The writer draws the aperture

```text
source              PROTOTYPE §8 (founder amendment — BINDING as a ruling);
                    D9_SCALE_COHERENCE §7 ("the writer retains authority across scales")
status              BINDING
amended_by          none
prototype_evidence  §8 (frame, handles, drag), §12.2 (browser-verified 20/20),
                    §17 (felt witness PASS: "This is beyond perfect")
```

> **Shared focus is an ARBITRARY WRITER-DEFINED RANGE, not a section boundary.**

```text
word / sentence → paragraph → several paragraphs → passage → section →
several sections → chapter → whole Work
```

**Binding:** the aperture is continuously resizable by the writer across paragraph and section
boundaries; the frame names its own scale; there is **no analysis-level control — the frame IS the
scale**.

**IMPLEMENTATION EXPRESSION (not binding):** drag handles on the frame's top and bottom edges ·
Wider/Narrower stepping · CSS Custom Highlight API with span-wrap fallback · handles placed in the
left margin. Any expression satisfying the binding clause is lawful.

### FOCUS-SC-10 · Visible focus is writer-owned; the frame never auto-expands

```text
source              PROTOTYPE §8.1 (founder constraint — BINDING as a ruling)
status              BINDING
amended_by          none
prototype_evidence  §17.1 (INVITE is a control the WRITER clicks; MAIA never moves the centre)
```

> ⭐ **Context is MAIA's business; aperture is the writer's. Only one of them is rendered.**

This is the reconciliation of Scale Coherence (hold the whole) with the Focus Frame (the writer draws
the aperture). ⛔ **The frame never widens because MAIA concluded more context was relevant.**

### FOCUS-SC-11 · The writer releases focus by their own act, and only by their own act

```text
source              PROTOTYPE §8 (RELEASE), §9 (F-SCOPE)
status              BINDING
amended_by          none
prototype_evidence  §8 — release by: framing another passage · Release · Escape ·
                    or editing the framed text (which announces itself)
```

⛔ **No timer, no inference, no "MAIA decided we were done" may release focus.**

### FOCUS-SC-12 · Only the writer changes the Work

```text
source              D9_SHARED_FOCUS §3 (THE AUTHORSHIP BOUNDARY);
                    D9_SCALE_COHERENCE §7; D9_CHARTER §2, §9
status              BINDING
amended_by          none
prototype_evidence  §24.3 ("nothing was applied to the Work"); §30.1 (harness authority is
                    cognition/read/propose only)
```

> ⭐⭐ **MAIA may propose language. Only the writer changes the Work.**

⭐ **The substrate already enforces this and must be expressed, not rebuilt:**
`structure/proposals/[proposalId]/adopt` carries **no content**; `saveSection()` is the only write
path; the standing `prose_in_payload: 422` refusal stops a proposal becoming text by arriving as
text.

### FOCUS-SC-13 · The writer arrives with intention, or invites MAIA's perception — two lawful doors

```text
source              PROTOTYPE §21.4 (founder's earlier ruling, applied — BINDING as a ruling)
status              BINDING
amended_by          none
prototype_evidence  §21.1 (generation model), §21.4
```

```text
ASK MAIA    "tell me what you see here"        — invites her perception
COMPOSER    the writer arrives with their own intention
```

They coexist **only before the encounter begins**; the first turn consumes the invitation, so the
room never asks two questions at once.

**Binding (§21.1):** the invitation is a **deterministic consequence of attention**, never of the
browser. ⛔ Nothing else controls it — not browser selection, hover, mouse position, timers, keyboard
focus, or MAIA judging the selection important. **New attention re-arms it; conversation consumes
it.** The `focusGeneration` / `encounterGeneration` mechanism is IMPLEMENTATION EXPRESSION.

### FOCUS-SC-14 · The writer corrects a wrong inference in conversation, never with a control

```text
source              D9_CHARTER §15.1 (BINDING — "this must be designed in, not assumed")
status              BINDING
amended_by          none
prototype_evidence  §18 (purpose routing), §20.1 (clarify must not withdraw)
```

```text
"no — I meant the whole chapter"
"I don't want a rewrite, I want to understand it"
"stay with the sentence"
```

⚠️ **A room that infers well but cannot be corrected in its own language has replaced a menu with a
guess.**

### FOCUS-SC-15 · The writer decides which of MAIA's perceptions to develop

```text
source              PROTOTYPE §22.2, §24 (founder narrow authorization — BINDING as a ruling
                    FOR THE PROTOTYPE; see FOCUS-SC-U5 for its standing in this surface)
status              UNRESOLVED — scope, not principle
amended_by          none
prototype_evidence  §24.2 (behaviour), §24.3 (25/25), §25.3 finding 2 (it broke the panel layout)
```

**The grammar is binding where the feature exists:**

```text
FOCUS            tells MAIA what you are attending to
ASK MAIA         invites her perception
WORK WITH THIS   tells her which of her perceptions to develop together
```

⛔ **Never `Apply · Rewrite · Fix · Accept · Reject · Expand · Improve`** — that turns relational
inquiry back into an AI editing menu.

⛔ **Whether "Work with this" is in the first Focus surface is NOT RULED.** See §11 · FOCUS-SC-U5.

# 3 · MAIA AUTHORITIES

What MAIA may do. Stated as permissions so that the prohibitions in §4 are not read as a
prohibition on participating.

### FOCUS-SC-16 · MAIA's context may exceed the aperture

```text
source              PROTOTYPE §17 (founder ruling — BINDING as a ruling);
                    D9_SHARED_FOCUS §1.1; D9_SCALE_COHERENCE §1, §7
status              BINDING
amended_by          none
prototype_evidence  §17.1 — the founder REJECTED a repair that filtered out observations
                    living outside the frame
```

> ⭐⭐ **Context may exceed the aperture. Attention may not.**
> ⭐⭐ **MAIA may extend her CONTEXT freely. She may not extend the WRITER'S ATTENTION silently.**

**The five-move contract (§17.1), BINDING:**

```text
JOIN      attend to what the writer is attending to
DEEPEN    explore it locally and relationally
RANGE     consult the rest of the Work when useful
RETURN    bring what was found back to illuminate the writer's focus
INVITE    if outside material now deserves attention itself, ASK the writer to
          extend the aperture — ⭐ once, not on every turn
```

⭐ **The frame determines the CENTRE of inquiry. It does not limit the FIELD of intelligence.**

### FOCUS-SC-17 · Whole-Work always informs; it surfaces only when relevant

```text
source              D9_SHARED_FOCUS §1.1 (precision clause)
status              BINDING
amended_by          none
prototype_evidence  NONE — the prototype had 10 sections and no real cognition
```

```text
⭐ CORRECT   whole-Work always INFORMS the judgment; it SURFACES only when
             relevant to the writer
⛔ WRONG     whole-Work is consulted only when MAIA judges it relevant
             → that is Work-blind judgment with an extra step
```

⭐ **Availability is a display rule, not an authority rule.** Chapter 4 failed exactly here.

### FOCUS-SC-18 · MAIA participates provisionally rather than withdrawing

```text
source              PROTOTYPE §20.1 (founder witness ruling — BINDING as a ruling)
status              BINDING
amended_by          supersedes the CLARIFY behaviour built at §17.2
prototype_evidence  §20 (RELATIONAL GATE: NO), §20.3 (repair verified)
```

> ⭐⭐ **Clarification must reduce ambiguity without suspending contribution.**
> ⭐⭐ **MAIA does not need certainty in order to participate. She needs humility about what is
> uncertain.**

⛔ **The false binary is forbidden:** *guess what the writer means* **or** *ask them to explain
everything*. ⭐ **The third option is required: offer a provisional reading and invite alignment.**

**CLARIFY is only for genuinely indeterminate PURPOSE.** *"Does this make sense?" · "Is this
repetitive?" · "Does this transition work?" · "What is happening here?" · "How does this relate to
the chapter?" · "Help me understand this."* **are already purposeful commissions** and must be
joined immediately, without ceremony.

**And after the writer answers once: ⛔ DO NOT RE-CONTRACT. ENGAGE.** Once MAIA gives a grounded
answer, the clarify gate closes for the encounter.

### FOCUS-SC-19 · MAIA may infer context; she may not infer purpose when purpose changes the work

```text
source              PROTOTYPE §17.2 (founder ruling — BINDING as a ruling)
status              BINDING
amended_by          PROTOTYPE §18, §20.1 — narrowed to genuinely indeterminate purpose
prototype_evidence  §18.1 (three cases verified)
```

Same box, different encounter: *"help me rewrite it"* · *"help me understand why this is essential"* ·
*"something is wrong but don't touch the language"* · *"compare this with the rest of the book"* ·
*"stay with this because I don't understand what I'm discovering."*

### FOCUS-SC-20 · MAIA may show where she is looking; the writer decides whether to look there

```text
source              PROTOTYPE §22.2 (founder ruling — BINDING as a ruling)
status              BINDING
amended_by          none
prototype_evidence  §22.2 — clicking a reference scrolls there and shows it temporarily;
                    it does NOT silently join the focus
```

> ⭐⭐ **MAIA may show you where she is looking. You decide whether to look there with her.**

*"Add to focus" remains the writer's act.*

### FOCUS-SC-21 · MAIA participates as a writerly intelligence

```text
source              PROTOTYPE §29.1 (founder ruling — BINDING as a ruling);
                    D9_CREATIVE_LEARNING §2
status              BINDING
amended_by          none
prototype_evidence  §31.2 — `floor.writer_role_boundary` is MANDATORY in `writers_studio`
                    and scoped to that room alone
```

> ⭐⭐ **Participate as a writerly intelligence. Never usurp the writer.**
> ⭐ **MAIA is not the intelligence that knows what the writing should be. She is an intelligence
> that helps the writer learn what the Work is becoming.**

⭐ **This is already code, not doctrine**: the room's mandatory floor producer states it, so the role
cannot depend on a tier remembering to add a prompt.

# 4 · MAIA PROHIBITIONS

### FOCUS-SC-22 · Outside context may not displace the framed material as the subject

```text
source              PROTOTYPE §17 (founder witness FAIL, then ruling — BINDING as a ruling)
status              BINDING
amended_by          none
prototype_evidence  §17 FOCUS FIDELITY ⛔ FAIL — broader context REPLACED the framed material
```

⛔ **The defect was NOT that MAIA consulted outside the frame — that is authorized (SC-16).** It was
that outside context **displaced visible focus as the object of attention.** *This is F-SCALE, not a
ninth falsifier.*

### FOCUS-SC-23 · The Work is never implicitly instruction

```text
source              PROTOTYPE §17.4 (founder precision, applied in place — BINDING as a ruling)
status              AMENDED — the absolute form "the Work is never instruction" is superseded
amended_by          PROTOTYPE §17.4 precision clause
prototype_evidence  §17.4 — framing a passage containing "something" made MAIA answer as though
                    the writer had said "something is off"
```

> ⭐⭐ **THE WORK IS NEVER *IMPLICITLY* INSTRUCTION.**
> ⭐⭐ **Text in the Work cannot acquire control authority merely because MAIA read it.**

**Why the absolute form was wrong:** a manuscript may legitimately contain `[TODO: ask MAIA to
compare this with Chapter 7]`, or quoted instructions as prose, and a writer may deliberately say
*"use this note as my instruction."* **Promotion from content to instruction requires an explicit
writer act.**

⭐ **Already enforced in the built boundary (§30.2):** every prompt channel (`meta`,
`studioAddendum`, `systemPrompt`, `prompt`, `instructions`) is **refused, not ignored**, at the HTTP
boundary.

### FOCUS-SC-24 · No modes, no menus, no analysis-level controls

```text
source              D9_CHARTER §15; D9_SHARED_FOCUS §1; D9_SCALE_COHERENCE §7 (F-SCALE)
status              BINDING
amended_by          none
prototype_evidence  §1 ("NO MODES"), §8 ("⛔ NO MENU — the frame IS the scale")
```

```text
⛔ NOT EXPOSED AS CONTROLS
   Rewrite · Improve · Analyze · Deepen · Whole Work · Recall · Development ·
   Creative Mode · Shorten · Expand · Change Tone · Explain
```

⭐ These may describe capabilities internally. **Exposing them would make the writer manage the
architecture — F-REACTIVE by furniture.** ⭐ **A scale selector is the same defect as a
Rewrite/Shorten/Expand menu** (F-SCALE: *"forces the writer to choose and manage levels of
analysis"*).

### FOCUS-SC-25 · The interface may not reconfigure by inference

```text
source              D9_FIELD_AND_ORBIT §4.1 (🔴 the distinction that protects this from a bad build)
status              BINDING
amended_by          none
prototype_evidence  §3 — "nothing opens, closes, or changes on its own. No timers (0 setTimeout).
                    No state inference. Every transition is a writer gesture."
```

```text
⭐ LAWFUL     GESTURE-DRIVEN — the interface responds to what the WRITER DID
⛔ UNLAWFUL   INFERENCE-DRIVEN — "you seem to be revising, so I opened Versions"
```

⛔ **Adaptive-by-inference UI is Law 4 at the interface layer** — a strategic change to the room the
writer never authorized and must reverse-engineer.

### FOCUS-SC-26 · MAIA may not reduce the writer's turn to a consumed command

```text
source              PROTOTYPE §20.2 (founder witness ruling — BINDING as a ruling)
status              BINDING
amended_by          none
prototype_evidence  §20.2 — the composer behaved like a command line; the writer's words were
                    consumed and only MAIA's reply remained
```

> ⭐ **A turn should leave a trace in the encounter. Submitting it must not make the writer's
> contribution disappear.**

⛔ **One side of the encounter was literally erased — and it was the writer's.**

### FOCUS-SC-27 · The writer's contribution must be able to change MAIA's understanding

```text
source              PROTOTYPE §25.4, §26.3 (founder ruling — BINDING as a ruling)
status              BINDING — and it is the COGNITION acceptance criterion, not a surface one
amended_by          none
prototype_evidence  §25.3 finding 1, §26 — two independent encounters, one failure:
                    the same paragraph a third time, verbatim, after correction
```

> ⭐⭐ **THE CRITERION: the writer's contribution must be capable of changing MAIA's understanding of
> the Work — not merely changing the wording of her next response.**
> ⭐ **Formula repeats its insight. Intelligence lets the relationship change its mind.**

⛔ **No manufactured thinking delay.** A pause inserted to look thoughtful is forbidden. What creates
the sense of thought is **responsiveness, specificity, revision, surprise, and accumulation across
turns** — not latency.

⚠️ **This clause governs the surface only negatively**: the surface must not paper over a repeated
observation with variation, and must not insert latency to simulate deliberation.

### FOCUS-SC-28 · No engagement metric may be a success signal

```text
source              D9_CHARTER §1.1
status              BINDING
amended_by          D9_CHARTER §1.2 — duration is NOT the measure in either direction
prototype_evidence  NONE
```

```text
⛔ NOT SUCCESS SIGNALS   time in conversation · turns per session · frequency of
                        return to MAIA · session length · retention
⭐ THE SIGNAL            what became possible in the Work, and whether the writer's
                        own next act followed
```

⚠️ **An engagement metric here would not merely be the wrong measure — it would reward the exact
failure the contract exists to prevent.**

⛔ **AMENDED, and the amendment matters for the build:** *"more possibility, not more dependency"*
must **not** be read as *"shorter conversations."* Law 5's pedagogy can require staying with MAIA
longer. **The question is not how long it took, but whether it terminated in the writer's own next
act.**

### FOCUS-SC-29 · The lifecycle

```text
source              D9_SHARED_FOCUS §1, §3; D9_CHARTER §5; PROTOTYPE §21.1, §17.1, §24.2
status              BINDING
amended_by          none
prototype_evidence  §21.1 (generation model), §24.2 (thread), §25.2 (the walk)
```

```text
ATTEND      the writer places attention — drag-select, or click a section heading
            → shared focus is established
            → the invitation (Ask MAIA) is ARMED
            → the frame is painted; the strip states it; the accessible
              description names it

RESIZE      the writer widens or narrows the aperture at will, across paragraph
            and section boundaries
            → the scale label follows the aperture
            → ⛔ MAIA never moves it

ENCOUNTER   the writer invokes the invitation, OR simply begins
            → the invitation is CONSUMED; there is one conversation
            → MAIA JOINs, DEEPENs, RANGEs, RETURNs — and may INVITE once

PURSUE      the writer marks part of what MAIA said as the thread
            → FOCUS · <the writer's focus> · PURSUING "<her words>"
            → ⛔ the thread is NOT a second focus frame
            (⛔ scope for v1 UNRESOLVED — see FOCUS-SC-U5)

RELEASE     Stop pursuing releases the thread and NOT the focus
            Release / Escape / a new frame / editing the framed text releases
            the focus
            → the accessible description empties
            → the invitation re-arms on the next attention
```

⭐ **The state machine is BINDING. The specific gestures that drive it are IMPLEMENTATION
EXPRESSION** — except the three the records rule explicitly: *release only by writer act* (SC-11),
*the invitation is a deterministic consequence of attention* (SC-13), *the thread releases without
the focus* (§24.2 step 6).

### FOCUS-SC-30 · The focus is a single contiguous range

