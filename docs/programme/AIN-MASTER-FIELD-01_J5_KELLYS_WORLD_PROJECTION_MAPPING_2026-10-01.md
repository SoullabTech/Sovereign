## Room mapping

### Today — What requires Kelly now?

Foreground only when one of these is true:
- founder authority required
- consequential condition unresolved
- boundary conflict requires adjudication
- rupture repair requires founder participation
- explicit decision is due

Presentation hierarchy:
1. Needs Kelly
2. In motion
3. Watching

Every Needs Kelly item must answer:
- Why am I seeing this?
- What requires me?
- What evidence supports it?
- What happens if no action occurs?

### Work — What is being carried?

Represent unresolved continuity:
- origin
- programme
- current standing
- owner
- authority
- next lawful act
- evidence
- resolution condition
- lineage

A task alone is insufficient. Work should preserve why the work exists.

### Monitor — What is happening now?

Represent current effective state:
- healthy
- degraded
- action required
- automatic control active
- unconfirmed
- failed
- recovering

Historical persistence must not masquerade as current state.

### System — What makes this possible?

Represent mechanism:
- service
- transport
- dependency
- failure domain
- runtime state
- policy
- permission source
- implementation version

System should expose technical truth without manufacturing founder urgency.

### Graph — How did this become what it is?

Represent lineage and transformation using a minimal relation vocabulary:
- DERIVED_FROM
- AUTHORIZED_BY
- SUPPORTED_BY
- CONTRADICTED_BY
- TRANSFORMED_INTO
- GAVE_RISE_TO
- WITNESSED_BY
- ACTED_ON_BY
- SUPERSEDED_BY
- CORRECTED_BY

Graph must distinguish:
- historical observed state
- current effective state
- possible future state

## Consequence projection

Never render stronger language than the delivery witness supports.

Examples:
- DETECTED -> "condition detected"
- DELIVERY_REQUESTED -> "delivery requested"
- TRANSPORT_ACCEPTED -> "provider accepted delivery"
- CHANNEL_REACHED -> "delivery confirmed"
- HUMAN_ACKNOWLEDGED -> "acknowledged by human"

Logging or persistence alone must never render as "notified."
