## ⭐⭐ The specification hinge — **RULED**

> **Is the current MAIA turn a second copy of the historical observation, or is "current" merely the present visibility of the same historical event?**

**Ruled: presentness is a standing, not a copy.**

```text
AT MAIA'S RESPONSE
  historical process event   written IMMEDIATELY · durable · ONE identity
  current presentation       POINTS TO IT

AT THE WRITER'S NEXT TURN
  historical event           UNTOUCHED
  current presentation       RELEASES IT
```

**Nothing moves from present to history. History already exists. Only presentness changes.**

**The same holds for the writer's sentence** — *"something feels off here"* is a historical fact immediately **and** carries present authority now. When that authority ceases, the sentence does not *become* historical; **it already was.** Only its standing changes.

> ### Presentness is not a second copy of content. It is a standing over something whose history is already durable.

**Why the copy reading fails**: until the writer's next turn the process history would not yet be durable, so a reload could erase something that actually happened; identity would need reconciling across two objects; and provenance would reopen exactly the atomicity problem D5 §6A closed.

⚠️ **This hinge was invisible in A, B and C** — each conflated identity with its organizer in a different way. **The amended architecture is the first to separate them enough for the question to arise.**

## Three consequences

### 1 · ⭐ The five classes are **three stores and two standings**

```text
STORED       manuscript / revision state       canonical, append-only
             historical process context        append-only — writer AND MAIA events
             durable creative orientation      writer-authored, Work-level

STANDING     current MAIA turn                 which event is presently shown
             present inquiry                   which writer utterance presently
                                               carries authority
```

⭐ **Directly serves criterion 11**: fewer stored types means less ontology available to leak. *(Whether creative orientation shares a store with the manuscript is an implementation question, not settled here.)*

### 2 · ⭐⭐ "Clears" is the wrong verb — **nothing is ever destroyed**

Class 3 does not clear. **The standing moves.**

> **C's evanescence risk is not mitigated — it is structurally impossible, because the architecture contains no destructive operation anywhere.**

That is the positive form of the hinge, and it is stronger than anything C could offer.

### 3 · ⭐ D5 atomicity becomes easy instead of precarious

C made provenance a knife-edge: the turn cleared, so ancestry uncaptured at adoption was gone forever. **Under the hinge, the process event is durable from the moment MAIA speaks** — so by the time an adoption occurs, **the process context it references already exists and is stable.** Atomicity is satisfied by ordinary sequencing rather than by racing a deletion.

## ⚠️ One collision to name now — **Sanctuary Mode**

The architecture's premise is that **every writer utterance and every MAIA observation is written durably at the moment it occurs.** That is content retention.

```text
SANCTUARY MODE (project vow)
  "No content retention — sanctuary sessions are not stored, indexed, or
   used for pattern formation."
  "Absolute boundary — nothing can be saved, extracted, inferred, or
   converted into long-term memory, under any circumstances, including
   by user request during the session."
```

⛔ **A Writer's Studio process history is exactly what Sanctuary forbids.** The two cannot both be unconditional.

**Not a defect of the amendment — a boundary that must be ruled**, and it has three possible shapes, none chosen here:

```text
Sanctuary is unavailable inside Writer's Studio
Writer's Studio has a sanctuary-equivalent in which nothing is written
  (and in which, necessarily, none of M2-M4's continuity exists)
Sanctuary suspends process-history writing, and the writer is told
  plainly what they lose while it is on
```

⚠️ **Flagged now rather than discovered at implementation**, because the durability premise is load-bearing for M2, M3 and M4 — **the same premise that makes the architecture work is the one Sanctuary forbids.**

*(Adjacent, already consistent: consent-for-memory. D6 treats process persistence as given and threads already persist server-side, so this adds no new consent question beyond the Sanctuary boundary.)*
