---

## 0 · WHAT WENT WRONG

A **repository census was treated as a product census.**

A source census can establish what code exists, what routes are live, what data
models are present, and where contradictions are. It cannot establish what
Notes, Goals, Discover, Insights, Suggestions, Timeline, Word Web or Threads
should MEAN in Writer's Studio.

The census made product inferences from implementation state — "presumptively
obsolete", "remove candidates", "defer or rename" — and the adjudication then
ruled on those inferences. **The direction of authority was inverted.**

> **Founder-ratified R&D intent governs the product.
> Repository state reports implementation reality.
> Implementation reality may reveal that the product has failed to embody the
> R&D; it does not silently repeal the R&D.**

---

## 1 · BINDING LANE RULE — FOUNDER / R&D AUTHORITY

```text
FOUNDER / R&D AUTHORITY

1. Founder-ratified R&D intent is authoritative product truth.

2. A technical census may:
   - establish what is implemented
   - establish what is absent
   - reveal contradictions
   - identify duplicate or unreachable implementations
   - identify technical constraints

3. A technical census may NOT:
   - retire a founder-ratified capability
   - redefine its purpose
   - substitute another capability for it
   - collapse two concepts because the current code overlaps
   - infer that absence of implementation means absence of intent

4. Where code and ratified R&D disagree:
      CODE IS THE DEFECT
   unless the founder explicitly reopens the R&D decision.

5. Reopening requires a founder act.
   Jarvis, census agents, implementation agents, and code state
   have no authority to perform that act.
```

### The discriminator that does the most work

> **"We cannot find why this exists" is a RETRIEVAL problem before it is a
> product-design problem.**

If Discover, Insights, Suggestions, Notes, Goals, Timeline, Word Web or Threads
came out of earlier R&D, the next act is to **recover that R&D and reconstruct
the intended function** — not to decide their fate from what happens to be
implemented today.

The founder should not have to recreate their own thinking because retrieval
failed.


**That is useful engineering evidence. It is not product truth.**

Every capability-level classification in the census — Packet assignment,
"presumptively obsolete", "reclassified into Packet A", DEFER / REMOVE
candidates — is **withdrawn as product judgement** and survives only where it
states an implementation fact.

## 4 · THE CORRECTED LANE FLOW

```text

   Find the prior R&D, founder rulings, specs, experiments,
   conversations and product intent for each destination.

2. RECONCILE
   Compare intended product with current implementation.

      what we previously decided
      what exists now
      where they diverge
      what remains genuinely unresolved

4. FOUNDER ACT
   Only the founder decides whether prior R&D stands, evolves,
   merges or retires.

5. BUILD
   Implement the resulting ruling.
```

This replaces the census-first sequence. **RECOVER is the current act.**
