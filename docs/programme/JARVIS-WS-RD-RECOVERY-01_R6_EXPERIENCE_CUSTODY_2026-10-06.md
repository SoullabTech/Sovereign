# JARVIS-WS-RD-RECOVERY-01 · R6 — Experience Custody
## Anti-drift operating contract · 2026-10-06

The Studio already has strong technical custody. This document adds **experience custody**.

## 1. Product change template

Every substantial Writer's Studio interaction change must state:

1. **R&D authority** — which ratified law requires or permits the change?
2. **Human subject** — which scenario/persona is improved?
3. **Relational state** — which R / I / S / P / E dimensions change?
4. **Non-change contract** — which dimensions must remain untouched?
5. **Golden-journey impact** — which G1–G11 step changes?
6. **Defeat condition** — what visible experience would prove the implementation wrong?
7. **Founder witness need** — technical-only or experiential?

A PR without these answers may still be valid infrastructure, but it cannot claim to improve the Writer's Studio experience.

## 2. Experience regression gates

The following become required acceptance assertions for the relational slice:

### X1 — Witness is not cosmetic
Given the same evidence, Witness must not spontaneously prescribe before invitation.

### X2 — Collaborator is not cosmetic
Given invitation, Collaborator may surface meaningful possibilities more actively than Witness.

### X3 — Writer response changes the next turn
A writer clarification or disagreement must become visible in subsequent reasoning.

### X4 — Intimate constrains disclosure
Intimate does not render a multi-item diagnostic/recommendation dashboard by default.

### X5 — Register preserves substance
Plain and Expert preserve the same evidence, uncertainty, and authority.

### X6 — No inferred writer class
No runtime policy labels the writer novice/expert/academic/technical from prose style.

### X7 — Scale continuity
Moving Chapter → passage preserves conversation and return address.

### X8 — Section evidence is not an exact edit locus
A section-level observation cannot become model-chosen exact replacement wording without writer passage selection.

### X9 — Proposal is not adoption
No text mutation before an authored act.

### X10 — Develop remains understanding-first
Develop may hand off to Write; it does not become the replacement-text desk.

### X11 — Review remains test/compare
Review does not silently become another writing or grading loop.

### X12 — MAIA field is not decorative
When the primary next act is relational, the active continuation occurs in the MAIA field, not as another static center report.

## 3. R&D custody rule

At the end of any substantial R&D session, freeze together:

```text
LAW / CONSTITUTION
STATE MODEL
GOLDEN JOURNEY
REGRESSION / DEFEAT GATES
```

Design decisions that exist only in chat are not sufficiently custodied for long-lived implementation.

Conversation-derived founder decisions may enter a recovery packet, but become canonical only through explicit founder adjudication or a duly governed ratification path.

## 4. Implementation precedence

Before modifying a Writer's Studio interaction:

1. read the current programme board;
2. read the governing constitution;
3. read the relevant golden-journey step;
4. inspect current implementation;
5. implement the smallest coherent change.

Never reverse steps 2 and 4.

> **Do not derive product intent from code and then use that inferred intent to justify the code.**

## 5. Founder witness rule

Founder experiential witness is mandatory for:

- primary room composition;
- relational posture behavior;
- intervention-depth behavior;
- first-contact Develop experience;
- passage → Focus / revision journey;
- major changes to Working with MAIA;
- changes that materially affect novice/non-craft accessibility;
- changes that materially affect professional/technical depth;
- any claim that a golden journey is complete.

## 6. Close condition

R6 becomes binding only after R7 founder adjudication.

Until then it is the proposed anti-drift operating contract for this recovery lane.
