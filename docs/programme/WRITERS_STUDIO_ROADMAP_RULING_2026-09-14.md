## The one place the ruling meets a constitutional act

Step 3 is described as muscle rather than bone. It contains **one irreducible bone**:

EW-01A's load-bearing law is *"the browser does not send the edit back"* — `/accept` reads
no body at all. Editable staged proposals **require** writer-authored text to travel from
the browser. That law must be reopened **deliberately, inside Step 3**, not discovered
mid-build.

⭐ **The naming ruling has already prepared exactly the ground this needs:**

```
replacement_text        → the PROPOSAL version      (may be authored by the writer)
expected_text · target
· base Work state       → the AUTHORIZATION         (never writer-supplied)
```

*Changing what should replace the text must never silently change what text the
authorization is allowed to replace.* That separation is what lets a writer-edited
candidate travel without `/accept` becoming a generic text-mutation endpoint — the
founder's own Step 3 condition: **this candidate, this proposal, this version, this locus,
exactly what the writer witnessed.**

⛔ So the "no new constitutional lanes" posture holds, with one named exception already
scoped and already half-ruled. It is not a new lane; it is the last act of this one.

## The boundary being reopened, stated exactly

```
EW-01A today            browser may authorize
                        browser may NOT supply the mutation

Step 3 introduces       browser MAY supply writer-authored candidate text
```

⭐ **Candidate text is not authority.** Reopening the boundary does not weaken `/accept`
into *"send me some text and I'll mutate the manuscript."* It allows a writer-authored
candidate to travel **while the server independently retains the exact authorization
envelope the writer witnessed.**

```
PROPOSAL VERSION
  replacement_text          └─ may originate with the writer

AUTHORIZATION
  expected_text
  target / locus
  base Work state
  proposal identity + version
                            └─ NEVER derived from writer-supplied replacement text
```

## ⭐⭐ New requirement: version identity becomes indispensable

Once the writer can edit MAIA's proposal, the thing authorized **can no longer be
"proposal X."** It must become:

> **this exact candidate version, for this exact proposal, against this exact base state,
> at this exact locus.**

⛔ **Otherwise editing the candidate could accidentally mutate the scope of the
authorization** — the failure the naming ruling's separation exists to make unreachable,
arriving instead through version ambiguity.
