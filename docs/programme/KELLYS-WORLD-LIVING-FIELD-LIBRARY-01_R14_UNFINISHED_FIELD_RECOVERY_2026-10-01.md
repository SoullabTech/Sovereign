## Purpose

Recover older programme threads that carry concrete unfinished evidence without equating age, recency, or machine salience with importance.

## Recovery standing

The Library now projects **Unfinished threads · recovery candidates**.

Every candidate has standing:

`RECOVERY_CANDIDATE_UNREVIEWED`

and law:

`DORMANCY_DOES_NOT_CREATE_IMPORTANCE`

The machine may say: “there is evidence this lineage was left unfinished.”
It may not say: “this is important” or “this should resume.”

## Admission rules

A recovery candidate requires:
- at least 36 hours since the record's last Git touch; and
- structural unfinished evidence, not loose keyword co-occurrence.

Admitted structural signals are:
- an **Exact next boundary / Next act / Next step** heading;
- an **Owed / Outstanding / What remains open / Pending** heading;
- an explicit current **State / Standing / Status** line carrying OPEN / NOT CLOSED / PENDING;
- an explicit pending founder ruling / decision / witness.

## Closure suppression

Recovery is lineage-aware.

A later strong closure / supersession record in the same programme lineage suppresses an older unfinished marker.

Records explicitly named as closure / supersession are not recovery candidates.

The detector therefore refuses looser historical phrases such as ordinary uses of “pending,” “unresolved,” or “owed.”

The earlier loose census produced 219 record-level hits.
The structural lineage-aware census produces **12 candidates**.

A known negative control — `WS2-06A_RUNTIME_WITNESS_2026-09-02.md`, which says “Nothing is owed” — is excluded.

## Member interaction

Each candidate shows:
- programme / record title;
- the structural signal type;
- approximate time since last Git touch;
- the exact evidence sentence;
- exact `path:line`;
- **Trace this thread**.

Trace re-enters normal Grokker retrieval. It does not create a Work Unit, run a model, change standing, or mark the thread important.
