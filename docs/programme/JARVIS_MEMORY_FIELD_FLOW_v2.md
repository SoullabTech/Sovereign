## 1. Operating sequence

**1 · Bind to reality first.** Before every cut, identify the live member surface, live route, serving model, canonical SHA, deployed SHA, authenticated member identity, relevant store, loader, participation path, and the actual prompt/cognition seam. Never infer route or runtime from source alone.

**2 · Diagnose every miss at the first broken link.**

```text
REMEMBERED → RETRIEVABLE → AVAILABLE → ADMITTED → USED → EXPERIENCED AS CONTINUITY
```

Never say "memory failed." Name the first link that failed and repair only there.

**3 · Finish existing capability before inventing new capability.** If a store or loader exists, wire it into the live MAIA surface before designing another subsystem. A new memory class is authorized only when the census reads `NOT YET BUILT` — not merely "not currently visible."

**4 · One participation spine.** No route-specific memory architecture. `/between/chat`, `/list`, Now What, Writer's Studio, voice and future surfaces may hold different room policies, but memory entering cognition must converge through the same provenance and participation vocabulary.

**5 · Availability is not the sovereignty lever.** For lawful member-owned memory, bias toward availability. Sovereignty is expressed through attribution, consent, restriction, retraction, Sanctuary, authority and relevance — never by making MAIA artificially forgetful.

**6 · Preserve authorship all the way into cognition.**

```text
MEMBER SAID · SYSTEM INFERRED · PRACTITIONER OBSERVED
SYSTEM COMPUTED · HOUSE AUTHORED · COLLECTIVE CONTRIBUTED
```

These must not collapse into one undifferentiated "memory about the member."

**7 · Every cut needs a positive and a negative witness.**

```text
NEGATIVE   no lawful material exists → the loader truthfully emits nothing
           → no hallucinated continuity
POSITIVE   material exists → retrieved for the correct member
           → admitted under correct provenance → reaches cognition
           → MAIA uses it correctly
```

**8 · After each technical cut, force a lived witness.** Ask a real question that requires MAIA to use the memory naturally. Never supply the answer in the prompt. Record false positive, false negative, attribution error, relevance error, or genuine continuity.

**9 · Do not optimize for one successful recall.** Once Pass 1 wiring is substantially complete, run a longitudinal witness across five or more turns deliberately touching conversation, relationship, symbolic event, decision, developmental change and saved/marked material. The goal is not six retrievals; it is whether MAIA understands the relationship among them.

**10 · Continuity Mode is the member-level contract.**

```text
Use what I have shared and saved with MAIA to maintain continuity
across conversations. I can narrow, seal, retract, or exclude anything.
```

Domain-level narrowing, not object-by-object permission fatigue.

**11 · Score the organism, not just the code.** Per memory class: Stored · Retrievable · Available · Admitted · Used · Experienced as continuity · false-positive rate · false-negative rate · attribution integrity · member control present. Unknown is `UNWITNESSED`, never assumed green.

**12 · Pass 3 begins only after Pass 1 and lived Pass 2 evidence.** Then: explicit recollection · cross-domain association · temporal change reasoning · correction and retraction over time · relationship history · developmental trajectory · salience intelligence · "who I was then → what changed → where I am now."
