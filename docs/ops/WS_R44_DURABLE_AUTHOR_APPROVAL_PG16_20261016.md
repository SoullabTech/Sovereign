The new, deliberately unmounted `heldDurableAuthorApprovalR44.ts` verifies a strictly fictional member/consent tuple, exact server-supplied decrypted R35 section view, and R37 *pure* changed-passage review. SQL stores only a secret-keyed token HMAC, secret-keyed complete choice HMAC, member/Work/section/choice identifiers, generation and consent/session digests, issued/expires timestamps, and monotonic `prepared → spent` state. No review prose, private Source, filenames, key bytes or raw token is stored in SQL.

The held-only CLAIM validates a fresh trusted-server-supplied current encrypted view, exact choice, member/session/notice/consent epoch, issuer root and 120-second server-supplied lifetime. One PostgreSQL conditional UPDATE transitions exactly one `prepared` row to `spent`; all duplicate, expired, stale, foreign, altered-choice or withdrawn-consent attempts refuse. SQL triggers reject DELETE, reuse of spent records, changed metadata and backwards state transitions. The approval remains SPENT **even if a future downstream save fails**; resolution must be explicit, not automatic token replay.

**This is a durable claim about an attempted author-approved change, not proof of a real human click or authorization to save.** It does not call R39, R35 Write, an actual auth/consent service, an independent Work-key issuer or an operational revocation fence. ## Remaining architectural and operational STOP

1. **No R43→R44→R39 live integration.** R43’s process-local author witness is a separately owned in-progress branch. R44 only proves a one-use SQL CLAIM. The browser must send *only* a token under real host/origin, CSRF, current-auth and current consent; the trusted server must reconstruct the exact section/choice from the encrypted Work and bind an observed explicit author gesture before the approved ciphertext mutation. A valid token or same-origin POST alone cannot prove a human clicked.
2. **No independent Work commit/deletion fence.** PostgreSQL single-record CAS is not distributed Work-key and revocation atomicity. A newly revoked Work must not remain eligible through copied keys, old backups or delayed writes. A spent token before an interrupted downstream write must become HELD until independently reconciled, never retroactively represented as a completed save.
3. **Production safety remains separate.** All historical plaintext Source/draft/revisions/keeps/editorial/log/WAL/offsite backup paths, old reader/rollback images, orphan encrypted files, KMS separation, deletion highwater, offsite restore, import/export and actual MAIA privacy boundaries must be qualified; real signed image and physical Mac/iPhone browser review, independent Class A custody review and founder exact-source/image/participant cutover GO are mandatory.
4. **Security limits:** a caller-provided structural admission and nowMs are test fixtures, not real trusted session/time or consent. PostgreSQL is operated by one fake `fict` owner; there is no independent admin separation. The 32-byte issuer root is same-Mac, not a separately managed production secret. Literal member, Work, section and option UUIDs in SQL are still metadata and would require production retention/access review.
