- AWS KMS supports `ECC_NIST_EDWARDS25519` signing keys; `ED25519_SHA_512` uses KMS `Sign` with `MessageType=RAW` (not a prehashed digest mode). https://docs.aws.amazon.com/kms/latest/APIReference/API_Sign.html and https://docs.aws.amazon.com/kms/latest/APIReference/API_CreateKey.html

Historical key and ciphertext retention must be assessed separately. https://docs.aws.amazon.com/kms/latest/developerguide/deleting-keys.html
- DynamoDB supports conditional writes and strongly consistent *table reads*, but GSIs and global replication have different consistency rules. Conditional epoch advancement and current nonrollbackable read authority must be demonstrated with real independently administered permissions, not booleans in a config file. https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/read-write-operations.html and https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadConsistency.html
