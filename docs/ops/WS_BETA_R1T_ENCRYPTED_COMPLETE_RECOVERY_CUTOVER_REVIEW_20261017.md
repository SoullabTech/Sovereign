## What R1T adds, and precisely what it proves

- `scripts/ops/wsBetaR1TCompleteEncryptedRecoveryFixture.sh`: **FICTIONAL ONLY** (hard gate `WS_R1T_MODE=fictional-only`, exact `ws-r1t-src-XXXXXXXX` PG16 fixture Docker label, no mounts/network, exclusive private T7 evidence directory and test-only file vault). There is **no production execution mode** and it cannot target `maia-postgres`, NAS, cron or a live vault.
- The fixture streams actual PostgreSQL custom-format `pg_dump` into **GPG public-recipient AES-256 encrypted ciphertext**, then streams an entire synthetic vault through `tar | gpg` **without staging plaintext `.sql` or tar archives**. The writer's GPG keyring contains **only the public encryption key**; the ephemeral private recovery key is in a separate test-only homedir.
- The writer keeps a newly generated generation directory under `.r1t.pending.*`. It records a manifest with **both ciphertext SHA-256 hashes and byte sizes**, plus explicit `productionCutoverApproved=false`, SQL/WAL/vault/source-coherence unproven and no claims of independent offsite custody. It publishes a single `complete/<generation>/` directory **atomically only after PostgreSQL ciphertext, vault ciphertext and the manifest all exist**. Failures after SQL, after vault or before final publication leave no complete recovery point and clean their own staging directory. A DB-only or media-only artifact is never a complete point.
- `scripts/ops/wsBetaR1TCompleteEncryptedRestorePG16.py`: owns two new Docker containers on an isolated, network-disabled PostgreSQL 16 image, three fictional vault files and separate GPG public/private homes. It tests default-off, wrong source/recipient, symlink attacks, all three failure stages, ciphertext integrity/permissions and completed-generation publication. It **destroys the fictional source DB and source vault first**, then streams GPG decryption directly into **another new** PostgreSQL instance and a private restore directory. It confirms exactly two fictional DB rows and all three file checksums, and removes private test keys, restored plaintext and containers.
- `scripts/ops/wsBetaR1TVerifyCompleteRecoveryPoint.py`: **read-only/fictional-only** strict complete-generation verifier. It validates exclusive filenames, directory and file permissions, SHA-256/bytes, private scope and manifest status flags, but neither decrypts nor certifies that a signature proves the manifest owner. Ordinary SHA-256 without a signed manifest can detect accidental damage, **not prevent a malicious backup operator replacing both ciphertext and hashes**.
- `scripts/ops/wsBetaR1TVerifyRecoveryFixture.py`: mutates only disposable **copies** of an accepted fictional generation. It refuses missing vault or manifest, unrecognized files, changed ciphertext, altered hashes, forged GO flags, symlinks, weak permissions, truncated ciphertext, wrong generation and nonfixture/disabled mode. It cleans every negative copy and preserves the genuine accepted generation.

**The candidate protects only the two explicitly included sources in the fixture. It is NOT a replacement production backup writer yet.** These tests do **not** show a cross-store coherent production database/WAL/Source-vault capture, attachment coverage, NAS replication, old-backup retention/legal hold, deletion nonresurrection or actual off-host key recoverability.

2. **Choose durable recovery identities and storage.** Founder authorizes a real **off-machine recovery-key custodian**, verified public recipient fingerprint, isolated key lifecycle, backup storage with tamper-evident retention and separate read permissions. A GPG key generated for this disposable test is NOT a recoverable operational key. Verify recovery/rotation and a genuine second-site restore without depending on the backup machine, and authorize all GPG/KMS/S3/NAS costs separately.
3. **Source coverage census (required before a live `--run`).** Enumerate all relevant current manuscript Source bytes (DOCX/PDF/TXT/MD pending/unclaimed, vault originals, session continuity, immutable source revision ledger), working drafts, attachments and media, account consent/one-use author receipts, SQL tables and committed WAL, file metadata, external or exported replicas, deleted-Work tombstones and restored database->vault relationships. R70.16B still held missing unclaimed Source and attachment scope; a PostgreSQL dump alone is never sufficient.
4. **Snapshot coherence barrier.** Document a quiesce/checkpoint or versioned filesystem snapshot protocol that captures **PostgreSQL DB state + vault/media + transactions/WAL and erasure ledger at one consistent point**. Verify before/after DB/vault version/manifest checkpoints and refuse if any Work commits/withdrawal/deletion changes during an unaudited split capture. R1T synthetic fixture has no real concurrent filesystem workload and does NOT qualify such a barrier.
5. **One production writer with correct publication order.** An independently reviewed, server-specific stream-to-encryption writer can be staged only after approvals. It must use `pipefail`, bounded permissions, an exclusive operational lock, verified recipient public key with no decrypt private key on host, source scopes and durable checksum/signature validation. Publish a **complete point only AFTER** both encrypted DB and vault/source artifacts, a complete manifest and independently verified offsite durability. Avoid `rsync --delete` and old-file retention/pruning before a new fully independently restored point is accepted. Failure of either component after partial data must quarantine/delete only **new** pending bytes, never old valid archives.
6. **Separate replacement of BOTH live jobs.** Decide under founder operator authority whether root cron becomes the sole writer and user cron is disabled, or an alternative orchestration is used. Prove exactly one approved schedule and no old gzip writers, with a rollback that restores **backup continuity but does not reinstate insecure real-writer claims**. No cron/service/script swap is allowed without separate exact source SHA authorization. The existing R20 installer STOP must not be bypassed.
7. **Independent cold restore before real writers.** From ciphertext held off the active server, prove restore of original Source, complete Work, media/attachment references, auth/consent/latest versions, undo/replay refusals and key rotation; verify deletion/nonresurrection under the current erasure ledger and no access to other members' material. Cross-check *all* old active/NAS/recycle/snapshot/offsite replicas against retention/legal requirements before considering irreversible erasure. Backups and restores must not silently downgrade any already stronger-protected Work.
8. **Observed real canary and release custody.** Qualify actual Mac Safari authenticated Work/consent/MAIA provider source and precise Apply/Undo with no plaintext fallback. Capture exact image digest, strict build, visible errors/alerts, a real post-cutover backup and separate recovery approval, and a rollback drill. The founder is sole release operator until he delegates; independent reviewer evidence remains required. **No five-person live manuscript admission until a separately authorized GO.**
