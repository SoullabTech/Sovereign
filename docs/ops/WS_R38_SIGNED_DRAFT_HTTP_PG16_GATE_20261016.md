## Limits which must not be blurred

1. **Fictional signers only.** R38 uses three Ed25519 test keys and a synthetic HMAC binding secret, all generated in an isolated test process; nothing independently provisioned, governed, or retired. No real KMS SDK, cloud signer, offsite deletion high-water or key operator is called. Passing signature verification is not proof of operational independence.
2. **Work fence is local.** The PostgreSQL `r38_fixture_work_fence` row lock rechecks consent and identity before the R35 transaction. It does **not** implement a cross-service nonrollbackable key-release/withdrawal fence. A signer at another administrative domain and a distributed Work coordinator are mandatory before real author writes.
3. **Browser cookie and real first-invitation untested.** The physical test uses the existing `x-session-token` fallback with actual fictional `auth_sessions` queries and mocks only the Next.js cookie context. It does not qualify real Safari/WebKit, a first user login, approved notice/click, Personal Portal or genuine MAIA inference.
4. **Legacy plaintext writers remain active in real application.** R35 is unmounted. Existing Source, ordinary Draft PUT/revisions/checkpoint, section saves, Apply/Undo recovery and derived editorial writes still use normal SQL columns, with historical WAL/backups and provider retention outside this prototype. Prior bounded inventory: 51 lower-bound SQL write candidates/19 source files, of which 30 were draft/revision candidates. No real content migration, old-reader rollback or full ciphertext coverage is achieved here.
5. **Cryptographic old-key erasure and full recovery remain unproven.** If an old raw Work key is copied with an old ciphertext backup, it can decrypt offline despite newer checkpoint revocation. Independent offsite restore of PostgreSQL, original Source vault, encrypted history and separately governed keys, plus a historical key-inventory and orphan reconciliation policy, remain required.
6. **Author-facing HTTP parity incomplete.** The adapter returns structural held-fixture responses, not exact legacy `updatedAt` timestamps or full draft/revision endpoint response formats. It refuses unapproved live writes; real integration must preserve R34's full idempotency, section partition and checkpoint response contracts with independently serialized commits.
