## User-experience contract

The manuscript is primary. The writer selects exact Unicode-codepoint text in a current section, then chooses between unranked alternatives. Simply selecting a suggestion does not request or apply anything.

Read this revision in context is an explicit action. A synthetic server fixture rereads the current R35 AES-GCM protected Work under R38 fictional authenticated-session and accepted-notice consent. R43/R37 validate the exact passage and choice, and R44/R46 record a durable one-use, metadata-only Apply approval. Original and proposed words are displayed together before any edit.

Apply this revision is a second distinct action. The browser sends ONLY an opaque token; it does not submit replacement prose, owner identity, Source custody, Work keys or idempotency authority. R46 spends the R44 approval in PostgreSQL before R39's signed fictional consent/Work fence and R35 Save. UI success requires reopening the exact encrypted next generation. A failed or ambiguous commit is held; no silent retry.

After a page refresh the newly encrypted generation is loaded again. If it is the latest Apply, the separate Review Undo control remains available. R47 independently rereads the current Apply and preceding ciphertext, creates a NEW durable Undo authorization and restores the original wording as another immutable generation only after Confirm Undo. An old Apply token cannot mean Undo. The component requires an owning controller callback to reconcile the actual manuscript view after a verified save or restoration.

The small in-memory UI state is cancelled on selection changes or component loss. The server-held proposal approval lifetime is bounded by the separately accepted R53 two-minute rule; loss cannot authorize a guessed retry.
