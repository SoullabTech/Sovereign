Content is written via the hardened immutable fsync/readback fileVault, **never passed as a normal SQL parameter**.

- Work-key-HMAC-protected idempotency token and request-body digest are placed into **the same SQL transaction** as the new cipher manifest and structural head version. An identical older request replays its original structural result, even after later saves; a reused key with different content is refused. No previous cached author-prose response is returned.
- Exact-authorized synthetic restore appends a **new encrypted generation**, recovering prior plain/section content without guessing section boundaries. Ordinary SQL rows contain no reconstructed manuscript prose.
- The PostgreSQL Work lock is held during vault fsync and SQL manifest/receipt publication. **This does NOT provide atomic file-vault + PostgreSQL durability or a cross-domain distributed KMS/deletion fence.** Failure after filesystem publication can leave an unreferenced encrypted object; R35 deliberately leaves it for future custodied reconciliation, not silent deletion.
