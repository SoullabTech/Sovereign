## Bottom line

**YES — substantiated, but gated behind one env var.** In the codebase's **default configuration**, **25 method handlers across 16 route files** under `app/api/admin/` are **`unguarded`** (no in-handler auth AND not gated by middleware). A further **5 handlers across 4 files** are protected only by a **forgeable `x-member-id` header** (no session verification) — risk-equivalent to unguarded for an attacker.

There are **0 `middleware-only`** routes here — because the gate that everyone *assumes* exists (admin role enforced by `middleware.ts` via `config/accessMatrix.ts`) **does not match `/api/admin/*` at all** (see "Decisive mechanism").

The team admin routes (`/api/team/admin/stats`, `/channels`, `/members`) are correctly **`role-gated`** — confirming the `impersonation-routes.test.ts` 401/403 expectation.

### ⚠️ The single determining factor: `ACCESS_CONTROL_MODE` — VERIFIED LIVE
The `unguarded` verdict holds **only in the default permissive mode**. `getAccessMode()` (`config/accessMatrix.ts:485-487`) returns `permissive` unless `process.env.ACCESS_CONTROL_MODE === 'strict'`. In **permissive** mode, unmapped routes pass through (`accessMatrix.ts:526-527`) → unguarded handlers are **reachable**. In **strict** mode, unmapped routes return **404** from middleware (`accessMatrix.ts:522-524`) → they become unreachable (denied, though as a blunt 404, not a real auth gate).

## Decisive mechanism (why unmapped → `unguarded`, not `middleware-only`)

1. **Matcher covers it.** `middleware.ts:370` matcher `'/((?!_next/static|_next/image|favicon.ico).*)'` runs on `/api/admin/*`.
2. **But there is no matching rule.** `matchRule()` (`accessMatrix.ts:431-447`) does first-match `exact` (`===`) / `prefix` (`startsWith`) / `regex`. The only `/api/admin` rule is `{ prefix: '/api/admin/beta-testers', rolesAnyOf:['admin'] }` (`accessMatrix.ts:417`). The page rule `{ prefix: '/admin', rolesAnyOf:['admin'] }` (`:356`) does **not** match `/api/admin/...` because `'/api/admin/x'.startsWith('/admin')` is `false`. No `/api` or `/api/admin` catch-all exists.
3. **Unmapped + permissive default = allowed.** `checkAccess` (`:522-527`) returns `{ allowed: true }` for unmapped routes when `getAccessMode()` is `permissive` (the default; `:485-487`). Middleware then falls through to `NextResponse.next()` (`:327`), reaching the handler with no auth applied.
4. **Handler has no auth** → request succeeds. Hence `unguarded`, not `middleware-only`.

Corroboration: `lib/beta-testers/requireAdmin.ts` doc comment explicitly states it "deliberately do NOT replicate the **unauthenticated write pattern found in `app/api/admin/command-center/*`**."
