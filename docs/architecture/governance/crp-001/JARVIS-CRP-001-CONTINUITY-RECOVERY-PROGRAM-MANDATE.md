# JARVIS — MAIA CONTINUITY RECOVERY, REPAIR & UPGRADE PROGRAM

## Mission

Bring MAIA from a collection of memory mechanisms to a demonstrably
functioning continuity system.

The objective is not:

> improve retrieval.

The objective is:

> When something from a member's history materially matters to the present
> encounter, the correct information survives the entire cognition path,
> reaches the final model context, is used appropriately, remains temporally
> and relationally truthful, respects corrections, and improves the member's
> experienced continuity.

No subsystem may be declared working merely because its upstream mechanism
exists.

---

# 1. Established MIR evidence

Treat the sealed MIR result as independent diagnostic evidence, not as a
specification.

Current evidence has established or strongly indicated:

* retrieval was healthy in the sampled production turns;
* the sampled retrieval path returned non-empty context with no observed
  timeout or failure;
* substantial candidate reduction occurs after retrieval;
* the selection/compression rule is materially thinner than continuity
  requires;
* heterogeneous scoring regimes are ranked together without an established
  common scale;
* the designed `facetMatch` signal is inert on the observed live route because
  the required facet is not supplied;
* recency decays aggressively;
* no explicit ranking terms represent corrections, supersession, unfinished
  threads, decisions, breakthroughs or relational load-bearingness;
* deduplication may collapse distinct memories sharing the same first 100
  normalized characters;
* final-context participation is not currently witnessed sufficiently to
  establish `USED`;
* correction propagation has an apparent dormant/unwired path and requires
  direct remediation proof;
* continuity substrates fail at different stages and must not be collapsed
  into one "memory failure";
* member-facing consequences of several mechanism defects remain UNKNOWN until
  measured.

Do not broaden any mechanism-level finding into a member-experience claim
without evidence.

---

# 2. Governing epistemic rule

For every memory class, prove:

EXISTS
→ ELIGIBLE
→ RETRIEVED
→ SELECTED
→ ASSEMBLED
→ FINAL MODEL REQUEST
→ USED
→ OBSERVABLE IN RESPONSE

A proof at one stage establishes nothing automatically about a later stage.

A database row is not continuity.

A retrieval hit is not continuity.

A selected memory is not final-context participation.

A final-context item is not necessarily model use.

A model response is not longitudinal continuity.

# 7. Diagnose selection/compression

Do not assume candidate reduction is itself defective.

Determine:

WHICH memories are dropped?

WHY?

Are load-bearing memories disproportionately discarded?

Evaluate the existing selection rule against the frozen benchmark.

Specifically test:

## 7.1 Score commensurability

Some candidates arrive with precomputed semantic scores while others receive a
local composite score.

Determine whether these numerical scales are empirically commensurable.

If they are not, ranking them directly in one list is a PROVEN ranking defect.

Do not fix by normalization guesswork without evidence.

## 7.2 Facet signal

Determine whether facet-aware ranking should exist in the live member path.

If it is intended and justified, wire and prove it.

If it is obsolete, remove the dead design rather than preserving an inert
signal.

## 7.3 Recency

Test the existing exponential recency decay.

Determine whether older but load-bearing memories are being displaced by newer
but irrelevant memories.

Do not remove recency.

Establish an evidence-based weighting.

## 7.4 Significance

Determine how significance is authored.

Do not treat absent significance as equivalent to genuine medium significance
unless that semantics is intentional and proven.

## 7.5 Dedupe

Test the first-100-character normalized hash against:

* templated entries;
* repeated openings;
* recurring relational notes;
* structured observations;
* episodic records.

Distinct memories must not disappear merely because their opening text
matches.

architecture.

Do not change the model merely because retrieval/selection was defective.

# 18. Acceptance

This program does not close when tests are green.

It closes when evidence demonstrates that MAIA can reliably:

* retrieve relevant memory;
* preserve load-bearing memory through selection;
* place it in final context;
* respect current vs historical truth;
* propagate explicit corrections;
* maintain relational provenance;
* carry unfinished threads and meaningful decisions;
* appropriately withhold irrelevant memories;
* explain why a relevant memory was included or excluded;
* recover after leaving and returning;
* improve actual member-experienced continuity.

The final non-technical question is:

> Can we explain from evidence why MAIA remembered what mattered in this
> encounter, why irrelevant history stayed silent, and how a member's
> correction changed what MAIA knew next time?

If the answer is no, the system is not yet complete.

---

# 19. Stop conditions

STOP rather than continue when:

* referent cannot be bound;
* evidence becomes ambiguous;
* instrument controls fail;
* current authority does not permit the next act;
* privacy/consent boundaries are implicated;
* two materially different repairs remain plausible;
* migration is required;
* an irreversible operation appears;
* a supposed missing primitive already exists elsewhere;
* a repair would weaken another memory class;
* member-facing consequences remain unmeasured but are being asserted;
* model/prompt tuning is proposed before upstream context delivery is proven.

A legitimate stop is evidence.

## A.2 Control-plane rules are not skills

JARVIS must never be able to route around:

**authority · custody · scope · concurrency · referent binding/rebinding ·
irreversible-action stops.**

Those structurally wrap every execution. The skills are the instruments inside
that envelope.

## A.3 The MAIA continuity skill library

Each as a versioned `SKILL.md` with a claimed-sensitivity statement,
positive/negative controls, blind spots, output schema, and
contraindications.

| Skill | Exact job |
| --- | --- |
| `trace-memory-path` | Trace one memory from storage through retrieval, selection, assembly, final request and response |
| `trace-final-context` | Establish whether a particular memory actually entered the final model request |
| `trace-selection-compression` | Explain which candidates survived, which were dropped and why |
| `audit-ranking-calibration` | Test whether heterogeneous scores are actually comparable before ranking together |
| `audit-dedupe-loss` | Detect distinct memories collapsed by deduplication |
| `trace-correction-propagation` | Follow explicit member correction into supersession, retrieval and future cognition |
| `trace-temporal-truth` | Distinguish current, historical, superseded and disputed memories |
| `trace-relational-continuity` | Trace person/relationship-specific context without cross-relational contamination |
| `trace-episodic-continuity` | Establish where episodic memory fails: eligibility, retrieval, gating, assembly or use |
| `trace-continuity-state` | Recover unfinished questions, decisions, commitments, changes and active threads |
| `design-discriminating-probe` | Construct the smallest test that separates competing failure hypotheses |
| `reconcile-contract-runtime` | Compare what architecture promises with what runtime actually does |
| `production-continuity-witness` | Run the final real-member evidence chain |
| `record-finding` | Persist bounded evidence with non-claims and counterevidence |
| `classify-evidence-state` | Apply precedence-ordered evidence classification |

Positive/negative control validation belongs in the **validation plane**, not
as an optional router choice. Every diagnostic instrument must answer:

> Can it detect a known true condition **and** reject a known absent condition
> across the actual boundary it claims to observe?

If not: **INADMISSIBLE TO TEST.**
