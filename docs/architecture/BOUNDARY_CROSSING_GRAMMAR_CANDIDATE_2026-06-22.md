# Boundary Crossing — Candidate Constitutional Grammar (HELD)

- **Date**: 2026-06-22
- **Status**: **CANDIDATE — held, not canon.** Grants no authority; authorizes no build; canonizes no grammar. A *register entry* submitted to the constitutional maturation method (§4), not a doctrine.
- **Class**: Cat 1 — Preserved direction (held, not authorized).
- **Working name only**: "Boundary Crossing Doctrine" is the name this would *earn* if it passes §4 — not a name it may assume now (earn-before-name, applied to the Constitution's own growth).
- **Origin** (recorded, not credited): Kelly 2026-06-22, generalizing the executor work (`docs/specs/MESSAGE_EXECUTOR_SPEC_2026-06-22.md`). Promotion is decided by architectural consequence, not origin.

> **The hypothesis.** The recurring constitutional question across the platform may be a single one: **"What boundary is this feature capable of crossing, and what process governs that crossing?"** The Contained/Released executor work would then be the *first concrete expression* of a more general grammar — not a doctrine unto itself.

---

## 1. The unifying question (the candidate)

| Boundary | Constitutional question |
|---|---|
| **Memory** | Does this remain inside the person's sovereign field, or enter retention? |
| **Interpretation** | Does this cross from observation into assertion? |
| **Relationship** | Does this cross from accompaniment into influence? |
| **Agency** | Does this cross from proposal into action? |
| **Identity** | Does this cross from possibility into definition? |
| **Communication** | Does this cross from contained into released? |

The appeal is real: instead of accumulating parallel rule-sets, every feature is met with one question first — *what boundary?* — before any domain-specific rule applies.

---

## 2. The load-bearing correction — same question, **different machines**

The tempting overreach is "they're all the same architectural move." They are **not.** They are the same *question* answered by **different constitutional processes** — each of which the Constitution already has:

| Boundary family | Already-governing process (today) |
|---|---|
| **Retention crossing** (contained → remembered) | Sanctuary Mode + consent gates (`MAIA_CONSENT_GATES.md`); no stealth memory |
| **Epistemic crossing** (observation → assertion) | *MAIA never occupies the meaning seat*; Soullab Principle (*receive fully · interpret slowly*); reception ≠ interpretation |
| **Relational crossing** (accompaniment → influence) | Sovereignty Invariants; *a portrait may be given, a relationship must be chosen*; Representation/Relationship/Governance layers |
| **Identity crossing** (possibility → definition) | Signal-not-type; *attune, don't assess*; the Oath's refusal of typing/guru-stance |
| **Release crossing** (contained → released, external/social) | **Contained/Released executor doctrine** — Footprint → Confirm → Release (`MESSAGE_EXECUTOR_SPEC`) |

These machines differ in *kind*. A **release crossing** is a member-*authorized* act with a footprint, an audience, and a recorded Release. An **epistemic crossing** is a *restraint on MAIA's own speech* — no footprint, no member authorization, nothing released; MAIA simply may not cross without warrant. Conflating them would let "the member authorized it" stand in for "MAIA earned the right to assert," or let restraint masquerade as consent. **The grammar's job is to route to the right machine — never to supply one machine for all.**

> Same question. Different machines. The grammar *classifies*; it does not *flatten*.

---

## 3. The one validated instance

Only one row is validated as architecture: the **release crossing** (agency + communication), via `MESSAGE_EXECUTOR_SPEC`. Its hardest-won object generalizes cleanly:

- **The footprint is the constitutional object.** An executor acts on a *footprint* (audience · visibility · persistence · revocability · identity · legal & social consequence), not on a channel. Transport is implementation; one footprint may have many transports.
- **One release machine.** Every *contained → released* elective — export a memory, share a journal, publish an identity, send a message — describes a footprint and routes through the *same* `Footprint → Confirm → Release` gate. This is the candidate's one concrete architectural payoff today: **don't build N parallel release flows.**

Every other row in §1 is **asserted, not validated.** They have governing processes (§2), but the *grammar over them* has not yet changed a design decision.

## 4. Promotion test (the maturation method)

| Test | Verdict (2026-06-22) |
|---|---|
| **A — Generativity** | **Strong.** Organizes memory/interpretation/relationship/identity/agency under one question; teachable; navigational. |
| **B — Compression** | **Partial.** Compresses the *release* family into one machine (§3). Does *not* compress the other families — they keep distinct processes. |
| **C — Constraint-power** | **Unproven.** Does asking "what boundary?" produce a *different, better* decision than the domain question already does — in a domain *other than* agency? Not yet demonstrated. |
| **Removal test** | If the grammar were deleted today, would any decision change? The per-family processes (§2) and the release machine (§3) would still stand. So far: **no.** |
| **Kind** | Currently **orientation / expository**, aspiring to **architecture** via *routing*. |

**Honest current standing.** This has the signature of `ecology`, `RbR`, and `PAoE` — candidates this method already found **non-promotable** (expository lenses). By the standard *maturation = constriction, not expansion*, a grammar that **broadens** scope is suspect until it **narrows** a decision. So it is **held**, exactly as those were — preserved as direction, not canonized.

**The discriminator is not elegance.** The **footprint abstraction** (§3) is an *equally* elegant unification — five transports collapsed under one release process — yet it *passed* the same removal test this grammar fails (remove it → the transport layer fragments). Elegance counted for nothing in either verdict; **removability was the whole test.** This is the safeguard against mis-reading the hold as "distrust unification": the method distrusts *elegance-as-evidence*, not unification. (And "held" tracks the *system's current shape*, not the idea's worth — if a second domain later builds on the one release machine, the grammar could become constitutive with no one changing their mind.)

**What would promote it** (falsifiable):
1. **Routing prevents a category error** in a second domain — e.g., someone designs an interpretation feature with release-style "member consent" and the grammar catches that an epistemic crossing needs *restraint*, not authorization. A real, recorded save.
2. **The one release machine is reused** — memory-export / journal-share / identity-publish actually route through the Footprint → Confirm → Release gate, proving §3's compression in code, not prose.

Either is sufficient. Until one occurs, this stays Cat 1.
