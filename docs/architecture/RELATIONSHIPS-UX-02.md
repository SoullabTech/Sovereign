# RELATIONSHIPS-UX-02 — Presence & Motion

## Purpose

`RELATIONSHIPS-UX-01` established the relational philosophy and canonical structure:

**Relationships Home → Relationship Space → Now / Story / Field**

`RELATIONSHIPS-UX-02` makes that structure behave like attention rather than static software.

The governing shift is:

> **The screen should respond as attention moves.**

Motion is not decoration. It expresses approach, focus, widening, return, and the changing foreground of relational inquiry.

## Laws

1. **Arrival before administration.** Creating a relationship is a progressive act of bringing someone or something into view, not filling out a record.
2. **The occasion enters the room.** The member's reason for bringing a relationship forward immediately shapes `Now`.
3. **Motion follows attention.** `Now`, `Story`, and `Field` transition as movements of perception, with reduced-motion preference honored.
4. **MAIA remains MAIA.** Relationship Space embeds the canonical `OracleConversation` in contained mode rather than creating a second relational chatbot.
5. **Context requires gesture.** Relational context is handed to MAIA only when the member explicitly chooses to talk or write with her.
6. **Encounter outranks apparatus.** Check-in language and results remain reflective and provisional rather than rebuilding dashboard sections.
7. **Return remains immediate.** The member can close the in-place MAIA chamber or return from Story/Field to the living encounter without leaving the relationship.

## Progressive relational arrival

The creation experience moves through:

**Who or what is here?**
→ **Who is present?**
→ **How do you know / relate to them?**
→ **What brings them to mind now?**
→ **Enter this relationship**

The same existing data is preserved. The interaction changes.

No schema change is introduced.

## Relationship Space

The member's chosen name remains the anchor.

A subtle ambient field shifts with the attentional mode:

- `Now` draws inward toward encounter.
- `Story` opens temporal depth.
- `Field` widens spatially toward relational form.

The effect must remain restrained. It should be felt before it is noticed.

## Now

If the member supplied an occasion when bringing the relationship into view, that language appears first:

**What brought [name] into view**

> member-authored words

Then:

**What feels alive about that now?**

This prevents the system from discarding the very reason the member entered.

## MAIA in place

`Now` offers two explicit gestures:

- **Talk with MAIA here**
- **Write with MAIA**

Both mount the canonical `OracleConversation` using `presentationMode="contained"` inside Relationship Space.

The relationship handoff uses the existing `relationships:thread` seed and `contextId`. The member's explicit click is the consent act that places the relationship into conversational context.

This does not create a new MAIA persona, prompt authority, voice system, or memory substrate.

## Check-in

The quiet check-in remains available as a lower-intensity doorway.

Its visible grammar becomes:

**Sense before explaining**
→ member qualities / words
→ **MAIA reflects**
→ possible pattern only when available
→ current atmosphere
→ **Something to carry**

MAIA's pattern remains a wondering, not a verdict.

## Acceptance

The slice passes when:

- relationship creation no longer presents all metadata fields at once;
- the member's original occasion is visible in `Now`;
- mode changes visibly alter the field without distracting animation;
- reduced-motion preference removes nonessential motion;
- MAIA voice/text can be entered without navigating to `/maia`;
- relational context is not injected until an explicit member gesture;
- the existing `Now / Story / Field` and epistemic laws remain intact;
- no schema, consent, retention, or production-deployment change is introduced.

## Non-goals

This slice does not yet implement:

- co-authored geometric dragging in `Field`;
- a full relationship constellation;
- cross-relationship pattern surfacing;
- new memory authority;
- new voice authority;
- new relational inference classes;
- production deployment.

Those remain later work.
