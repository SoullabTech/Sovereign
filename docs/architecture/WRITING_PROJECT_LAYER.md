# Writing Project Layer

> Ontological clarity. No UI. No schema. No flows.

## Purpose

To name the layer where Ideas become an organism — before they become structure.

The system already has:

- **Ideas** — atomic units, fragments, signals
- **Manuscripts** — fixed structure, committed sequencing, exportable form

What was unnamed: the middle-order containment where meaning organizes before form locks. This document names it.

## What a Writing Project is

A **field**: a bounded space of coherence, organized around a central tension or inquiry, where elements influence each other without fixed hierarchy, and where structure is allowed to emerge rather than be imposed.

A Writing Project is not a folder, collection, workspace, outline, or canvas.

| Concept     | What it does            |
| ----------- | ----------------------- |
| Folder      | stores                  |
| Collection  | groups                  |
| Outline     | orders                  |
| Workspace   | contains activity       |
| **Field**   | **organizes emergence** |

## What a Writing Project holds

- Clusters of Ideas in relation
- Early structural attempts (loose, reversible)
- Voice development
- Contradictions that have not yet resolved
- Returning material at different depths

## What a Writing Project is not

- A manuscript draft
- An outline
- A note collection
- A storage container
- An editorial decision

It does not commit to sequencing. It does not produce form. It does not export.

## The arc

```
Idea (signal)
   ↓
Writing Project (field)
   ↓
Manuscript (form)
   ↓
Published Artifact (expression)
```

Each layer does something fundamentally different. The Writing Project layer answers *"What is this becoming?"* — not yet *"What is this?"*

## Expansion modes

### Native mode

**Field-based** — center → resonance → organization. Structure emerges from relational density. This is the system's native mode.

### Compatible modes (external)

- **Accretion** — Ideas gather until density forms structure
- **Catalytic** — one Idea unfolds into many
- **Architectural** — a structure is imposed early; Ideas fill it

These can feed a field but do not define it. A Writing Project may receive material from any mode, but it organizes that material field-wise.

## Constraints

A Writing Project must not collapse into:

1. **A manuscript** — committing to structure too early forecloses emergence.
2. **A folder** — storage without orienting tension is collection, not field.
3. **An outline** — ordering before resonance forces premature hierarchy.
4. **A search surface** — a field is bounded by inquiry, not query.

## Recognition signals

A Writing Project is operating when:

- Material returns at greater depth, and the return is *earned* rather than duplicate
- Sequencing feels found rather than imposed
- Contradictions can be held without resolution
- The center of gravity is recognizable but not yet articulable

## Relationship to Manuscript types

Manuscripts differentiate by structural intent:

| Type             | Structural difference               |
| ---------------- | ----------------------------------- |
| Book             | linear, narrative, immersive        |
| Workbook         | modular, interactive, repeatable    |
| Retreat material | cyclical, experiential, time-bound  |
| Course           | progressive, layered, instructional |

This differentiation belongs at the **Writing Project → Manuscript transition**, not within the Writing Project itself, and not within Book Studio. A field can become any of these; the choice is downstream.

## What this layer prevents

Without this layer named, the system oscillates between fragmentation and premature coherence.

With it named:

1. Ideas can belong somewhere without being forced into structure.
2. Manuscripts arrive when ready, not when material has merely accumulated.
3. Repetition vs. recursion becomes a recognizable distinction rather than an editorial guess.

## What this document is not

This is not a feature spec. It is not a build instruction. It is not a UI proposal. It is ontological clarity for a layer the system is already operating inside.

When implementation pressure becomes specific, this document constrains what can be built. Until then, it constrains nothing — except language.
