# Soullab Writer's Studio — Flagship Visual Canon v2

Status: DESIGN AUTHORITY / implementation reference  
Purpose: bind composition, hierarchy, atmosphere, interaction feel, and cross-mode family resemblance.  
Behavioral and constitutional law remains governed by the Writer's Studio programme records.

## Governing rule

A functionally correct candidate that materially resembles the pre-flagship Writer's Studio fails visual acceptance.

Existing components carry only the guarantees they have earned. They do not carry visual authority merely because they already exist.

The manuscript is the permanent content region. Navigation chrome may persist. Outline, MAIA, review, history, related material, and developmental analysis are contextual.

## Frames

### 01 — WRITE / Resting manuscript
File: `01-write-resting.png`
- Manuscript owns the room.
- Warm literary atmosphere is structural, not decorative.
- App rail is navigation chrome only.
- No permanent outline or MAIA content panel.
- Work identity + `Guided ▾` are quiet and visible.
- Focus remains available.

Acceptance: V1 / V9 / V11.

### 02 — WRITE / Held passage + contextual MAIA
File: `02-write-contextual-maia.png`
- Member holds an exact passage.
- MAIA appears beside the locus, dismissible and non-resident.
- Opening/closing MAIA must not move the manuscript horizontally or vertically.
- Same exact place and conversation seam survive dismissal/reopen.
- `Discuss · Revise · Teach · Reason` are ways of relating to the same locus, not new products.

Acceptance: V2 / F2 / F3.

### 03 — WRITE / Alternatives
File: `03-write-alternatives.png`
- Alternatives are peer possibilities; no numbering, rank, winner, severity, or recommendation badge.
- Include `Keep my original` as a first-class option.
- Each proposal says `Read in context`.
- No Apply action exists on the alternatives list.
- Proposal breadth stays bound to the member-selected locus and does not widen by facet.

Acceptance: V3 / F5 / authorship-scope law.

### 04 — WRITE / Read in context
File: `04-write-read-in-context.png`
- Original and one exact candidate are read in the manuscript context before mutation.
- `Apply this revision` appears only here.
- `Keep my original` remains available.
- Writer sees what changed and why before applying.

Acceptance: V4.

### 05 — WRITE / Applied + history + undo
File: `05-write-applied-history-undo.png`
- Exact, calm receipt: revision applied.
- Undo is immediately available.
- Version History is on demand.
- History distinguishes current / previous / exploration without declaring a winner.
- Writer's authorship and reversibility remain obvious.

Acceptance: V5 / F6 / F7.

### 06 — DEVELOP / Flagship overview
File: `06-develop-overview.png`
- Same Soullab visual family as Write.
- Development means seeing shape, flow, patterns, and evidence — not grading.
- `Exploration Areas` are descriptive.
- `Reader perspective` means possible reader effects, not predictions or findings of fact.
- `What MAIA Read` is member-facing coverage.
- Manuscript Map and Elemental Themes render member-declared structure only.
- Undeclared structure has an honest `Not yet declared?` state.
- Read-time may appear only with an explicit calculation basis.
- No Export surface in this visual target.

Acceptance: V6 / V11.

### 07 — REVIEW / Findings
File: `07-review-findings.png`
- Review stays connected to the manuscript.
- Findings use evidence-grounded observation or explicit MAIA stance; never machine grading.
- No `key`, `strong`, `good`, `authentic`, `engaging`, or priority language as factual properties of the Work.
- `Reader perspective` remains explicitly possible/contestable.
- `Go to passage` is first-class.
- `Discuss` and `Explore` return into the same manuscript/conversation spine.
- Tabs filter admitted material; clicking a tab must not silently commission a new reading.
- `What MAIA Read` remains visible coverage.

Acceptance: V7 / F14 / no-ranking law.

### 08 — MOBILE / Write
File: `08-mobile-write.png`
- Same product semantics and vocabulary as desktop.
- Manuscript is permanent.
- MAIA is summoned contextually as a sheet/card, not a squeezed desktop column.
- Mobile primary navigation may expose `Write · Develop · Review`; other destinations appear only if actually available.
- No semantic renaming of modes on mobile.

Acceptance: V8 / V11.

## Cross-cutting corrections

1. `Write · Explore · Refine · Become` is brand language, never product navigation.
2. Product vocabulary: `Home · Write · Develop · Review`; Library/Search appear only when actual capability exists.
3. `Guided · Learning · Direct` is one intelligence over the same Work. Facet changes translation/explanation only, never observation truth, proposal breadth, authorship authority, or how much MAIA writes.
4. Reader-effect remains a permanent non-conclusion. `Reader perspective` may expose explicitly possible/contestable interpretations.
5. Elemental/spiral classification is rendered only from member-declared structure.
6. Review lenses are filters over admitted readings, not implicit commissions.
7. Alternatives are unranked and all reachable.
8. `Read in context` is required before Apply.
9. Applied state has immediate Undo and truthful History.
10. Atmosphere, typography, spacing rhythm, and warmth are part of the composition contract.
11. A visually legacy-looking candidate fails even if behavior is correct.
12. Write, Develop, Review, and Mobile must unmistakably belong to one Soullab Writer's Studio family.
