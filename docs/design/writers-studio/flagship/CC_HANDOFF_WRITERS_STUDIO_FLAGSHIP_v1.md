## North Star

> **Writer's Studio should feel like exploring a living world that happens to be your book.**

The flagship loop is:

```text
Write
→ notice something
→ follow it through the Work
→ see the larger pattern
→ return to the exact passage
→ MAIA joins there with the same observation
→ discuss / understand / teach / try a possibility
→ Read in context
→ Apply or Keep original
→ Undo / History
→ continue deeper into the Work
```

No dead-end dashboard state is acceptable.

## Immediate implementation rulings

### 1. Review finding order
Default Review finding order is **book/page order**.

Example:

`112 → 118 → 124 → 126`

No default `Most relevant`, `Highest priority`, or equivalent implied ranking.

### 2. One observation travels
A Review finding that opens a passage carries:
- one observation id;
- one canonical wording;
- one exact return address.

MAIA must **not** silently restate or re-read the passage on arrival.

The finding travels into the Work.

### 3. Return trail
`Back to Review` is first-class.

A finding may never act as a trapdoor into the manuscript.

### 4. Add your own observation
Build as a first-class member interaction.

At an exact passage:

- `Something I noticed`
- `A question`
- `A possibility`

Optional member-written note.

Primary action:

`Keep with this passage`

The resulting object:
- remains member-authored;
- retains exact address;
- can appear in Review / maps where lawful;
- is visibly distinct from MAIA observation.

### 5. Stale-reading trust state
When the Work has changed since MAIA read it:

> **This chapter has changed since MAIA last read it.**

Show:
- previous reading timestamp;
- current update/version timestamp;
- changed passages when known;
- prior reading available for reference.

Actions:
- `Read this chapter again`
- `Not now`

MAIA never silently recommissions herself.

### 6. Visualization truth
> **A visualization must be as verifiable as its form implies.**

Presence, counts, coverage, timestamps, and declared structure may look measured.

Interpretations must render as attributed, revisable MAIA readings and may not use the same measurement language as countable facts.

### 7. Provenance
Every Develop/Review pattern declares its kind visibly:

- `IN YOUR TEXT`
- `YOU NAMED THIS`
- `YOU CHOSE THE SPIRAL TEMPLATE`
- `MAIA NOTICED THIS`

`You named these` and `You chose the Spiral template` are distinct states.

### 8. No unsupported live destinations
Do not ship `Explore`, `Library`, `Search`, `Export`, or any other destination merely because it appears in a reference image.

Navigation is capability-honest.

### 9. Remove unsupported state labels
Do not render `In Progress` unless a real Work state establishes it.

### 10. No stock-like semantic imagery as evidence
Decorative atmosphere may be used as atmosphere.

A thumbnail attached to a finding/passage must not imply evidentiary meaning unless it is Work-owned or otherwise truthfully sourced.

### 11. No machine verdict language
Examples that must not appear as factual properties of the Work:
- strong / stronger
- weak
- good
- authentic
- engaging
- beautiful
- luminous
- key
- important
- readiness / ready
- priority

Use:
- evidence-grounded observation; or
- explicit first-person MAIA stance.

### 12. `Why this matters`
Do not use this heading for an author-intent / significance conclusion.

Learning facet may use it for actual craft teaching tied to evidence, e.g.:

`The sentence slows here — two short clauses follow a long one.`

### 13. Revision invitations
`Try a possibility`, `Try another rendering`, etc. enter the **same governed proposal chain** in every facet.

No shortcut around:

`Alternatives → Read in context → Apply → Undo`

### 14. Coverage
Cross-Work claims must have reachable `What MAIA Read` coverage.

Related Passage glosses require actual coverage and evidence.
