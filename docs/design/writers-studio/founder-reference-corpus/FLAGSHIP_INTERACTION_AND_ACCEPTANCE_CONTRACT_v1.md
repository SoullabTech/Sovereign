# Soullab Writer's Studio — Flagship Interaction & Visual Acceptance Contract v1

This contract accompanies `FLAGSHIP_VISUAL_CANON_v2.md`.

## Product spine

```text
Work
  → Manuscript
  → hold exact passage
  → contextual MAIA
  → discuss / understand / teach / revise
  → plural alternatives
  → Read in context
  → deliberate Apply
  → receipt + Undo + History
  → same Work / same authored place
```

Review and Develop are movements over this same Work. They never become dead-end report products.

## State laws

### WRITE — at rest
Permanent:
- application navigation chrome;
- Work identity;
- support facet control;
- manuscript;
- quiet Focus affordance.

Contextual:
- contents/outline;
- MAIA;
- Review;
- History;
- Related;
- reasoning;
- teaching;
- sources/materials.

Forbidden:
- permanent manuscript outline content rail;
- permanent MAIA content rail;
- workbench/lens/pass/range machinery as default UI;
- `Rebuild preview`;
- old `StudioModeBar` as primary product navigation.

### Passage held
The selection creates one exact locus.

Opening MAIA:
- preserves manuscript width;
- preserves selected passage vertical position;
- preserves scroll;
- preserves Work / section / range identity;
- does not mutate prose;
- does not silently create a broader commission.

Closing MAIA returns to the exact same visual location.

On mobile, the same state may use a sheet/card instead of a side-anchored card.

### Conversation
One relationship carries:
- understand;
- discuss / disagree;
- teach / explain;
- explore;
- revision discussion.

Reasoning and teaching are disclosures inside this relationship.

`Guided · Learning · Direct`:
- same observation;
- same evidence;
- same non-conclusion boundaries;
- same mutation authority;
- same proposal breadth;
- same amount of MAIA-authored prose.

Only translation, explanation, teaching depth, and visibility of governed machinery may differ.

### Alternatives
Every alternative is:
- unranked;
- reachable;
- named by purpose;
- visibly a possibility rather than a verdict.

Required peer option:
- `Keep my original`.

Forbidden:
- numbering that implies ordering;
- Recommended / Best / Strongest;
- severity or priority badges;
- Apply from the list.

Primary action on each proposal:
- `Read in context`.

### Read in context
Before Apply:
- writer sees the exact original locus;
- exact candidate is rendered in manuscript context;
- changed language is visible;
- original remains preserved;
- conversation remains reachable.

Only this state may offer:
- `Apply this revision`.

The writer may still:
- return to alternatives;
- discuss;
- keep original.

### Applied
After Apply:
- exact-locus receipt is visible;
- `Undo` is immediate;
- History is available on demand;
- previous wording remains recoverable;
- same Work and authored place are preserved.

Undo:
- restores the previous wording;
- truthfully retains lineage/history;
- returns to the same relationship seam.

## DEVELOP law

Develop exists to help a person see the Work more clearly.

Allowed:
- structure;
- arc;
- continuity;
- recurring images/themes;
- shifts in mode/cadence;
- evidence-linked patterns;
- member-declared maps;
- coverage.

Not allowed as machine facts:
- strong;
- weak;
- good;
- bad;
- authentic;
- engaging;
- beautiful;
- luminous;
- key;
- important;
- priority;
- should change.

MAIA may instead offer:
1. evidence-grounded observation; or
2. explicitly first-person relational stance.

Example:
- observation: `The image returns in four separated sections.`
- stance: `I keep returning to this passage.`

### Reader perspective
`reader-effect` remains a permanent non-conclusion.

Allowed:
- `A reader might lose the referent here because...`
- `This turn could create distance...`

Forbidden:
- `Readers will be confused.`
- `This is engaging.`
- any actual-reader claim presented as established.

UI explanatory copy:
`Possible reader effects — not predictions.`

### Structure maps
Primary/solid map:
- member-declared authored structure only.

MAIA-derived interpretation:
- must be visibly separate;
- must say that it is MAIA's observation;
- must never silently become authored structure.

Elemental classification:
- member-declared only where governing law forbids inference from prose.

### What MAIA Read
Coverage is top-level trust evidence.

It must identify the actual scope MAIA read.
It must not imply external source verification.

## REVIEW law

A Review finding must always remain connected to the Work.

Every finding needs a route such as:
- Go to passage;
- Discuss;
- Explore;
- View.

Opening a finding:
- dismisses the review layer;
- restores the exact authored locus;
- enters the same contextual MAIA/conversation spine if discussion is chosen.

Review tabs such as Structure / Voice / Continuity / Flow / Themes:
- filter already-admitted material;
- do not silently trigger new readings;
- if evidence is absent, say so and require a deliberate commission.

No ranking or priority ordering unless separately authorized.

## Capability honesty

A visible active control must map to real substrate.

If unavailable:
- hide it; or
- present an explicitly unavailable state when doing so is useful.

Never render a complete-looking active feature that 404s or has no substrate.

Navigation itself is capability-governed.
A destination appears only when the destination exists under the relevant Studio map/capability law.

## Application navigation

Brand language:
`Write · Explore · Refine · Become`

This is not product navigation.

Canonical product meanings:
`Home · Write · Develop · Review`

Other destinations may appear only when their actual substrate exists.

Desktop and mobile preserve the same semantic names.
Mobile may show a smaller immediate set; it may not rename modes.

## Atmosphere

Atmosphere is structural composition authority.

It must:
- remain quiet;
- support literary focus;
- use warm field/ground hierarchy;
- preserve accessible contrast;
- recede in Focus;
- never materially reduce manuscript working space.

Write, Develop, Review, and Mobile must share:
- typography;
- spacing rhythm;
- navigation grammar;
- surfaces;
- interaction tone;
- atmosphere;
- control language.

## Visual acceptance gates

### V1 — WRITE at rest
At 1440 and 1920:
- manuscript unmistakably primary;
- no legacy three-column content layout;
- no permanent MAIA content rail;
- no permanent outline content rail.

### V2 — Held passage + MAIA
- MAIA anchored to locus;
- opening/closing causes zero manuscript width change;
- zero selected-passage vertical displacement;
- exact location survives.

### V3 — Alternatives
- peer possibilities;
- no ranking;
- Keep my original;
- no Apply;
- Read in context present.

### V4 — Read in context
- exact candidate shown in manuscript context;
- difference understandable before mutation;
- Apply available only here.

### V5 — Applied + Undo
- explicit receipt;
- Undo obvious;
- History available;
- manuscript remains primary.

### V6 — DEVELOP
- flagship family resemblance;
- descriptive exploration, no machine grading;
- member-declared structure truth;
- visible What MAIA Read.

### V7 — REVIEW
- findings tied to evidence and manuscript;
- direct Go to passage;
- no dead-end report state;
- no silent reading commission from filter tabs.

### V8 — MOBILE
- manuscript primary;
- contextual sheet/card behavior;
- no squeezed desktop columns;
- semantic navigation parity.

### V9 — LEGACY SHAPE FALSIFIER
Fail if rendered candidate contains the old primary-experience shapes:
- `Rebuild preview`;
- permanent three-content-column composition;
- permanent MAIA content rail;
- old `StudioModeBar` as primary experience;
- dense workbench machinery as ordinary chrome.

### V10 — FOUNDER SIDE-BY-SIDE
Required:
- approved reference;
- rendered candidate;
- same viewport;
- founder PASS / REVISE.

No automated check may proxy this judgment.

### V11 — CROSS-MODE FAMILY
Write, Develop, Review, and Mobile must unmistakably be one Soullab Writer's Studio.

### V12 — NON-PRO-WRITER ACCESSIBILITY
A creative/helper who does not know editorial terminology can identify the next meaningful act without selecting machinery.

Defeat examples:
- required lens selection;
- required pass/range mechanics;
- unexplained editorial jargon;
- controls whose labels describe implementation rather than writer intent.

## Release rule

A candidate fails release acceptance if:
- it violates behavioral/constitutional law; OR
- it materially diverges from the approved flagship composition; OR
- it materially reproduces the legacy Writer's Studio aesthetic.

No production-deployment act should be authorized until the founder visual gate is PASS.
