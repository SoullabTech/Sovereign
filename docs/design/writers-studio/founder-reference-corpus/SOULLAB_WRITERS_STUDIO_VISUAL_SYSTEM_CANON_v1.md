# SOULLAB WRITER'S STUDIO
# Visual System Canon v1

Status: FLAGSHIP VISUAL / COMPOSITION AUTHORITY  
Purpose: translate the approved Soullab Writer's Studio visual language into stable implementation rules so Write, Develop, Review, and Mobile cannot drift into unrelated products or back toward the legacy workbench.

This canon is additive to:
- Flagship Experience Canon
- V10 Founder Visual Acceptance
- First Arrival + Onboarding Canon
- Intent-First Entry + First Ten Minutes
- accessibility / constitutional law

It does not authorize implementation, package installation, merge, or deployment.

---

# 1. Visual North Star

> **Warm literary foundation. Cool lucid interaction. Restrained gold. Work-connected atmosphere.**

The Studio should feel:

- literary;
- calm;
- spacious;
- intelligent;
- human;
- premium;
- alive;
- trustworthy;
- quietly contemporary.

It should not feel:

- dark-tech;
- generic SaaS;
- corporate productivity software;
- luxury-brown dashboard;
- editorial control room;
- game UI;
- New Age ornament;
- clinical analytics software.

---

# 2. The Visual Equation

```text
WARMTH
paper / parchment / natural ground
        +

CLARITY
cool-blue interaction / selection / navigation
        +

MEANING
serif Work typography
        +

RESTRAINT
clean sans UI typography
        +

LIFE
Work-connected atmosphere / imagery
        +

AGENCY
obvious reversible controls
```

No single ingredient becomes the entire identity.

---

# 3. Color Roles — Not Decoration

Colors must communicate stable roles.

## FOUNDATION — Warm neutral

Used for:
- main ground;
- manuscript field;
- quiet cards;
- literary space.

Characteristics:
- warm off-white / parchment / stone;
- low chroma;
- readable for long sessions;
- never yellow enough to feel vintage;
- never gray enough to feel institutional.

---

## INTERACTION — Cool lucid blue

Used for:
- active navigation;
- current selection;
- links;
- focus;
- actionable state;
- selected map cell where appropriate;
- active tabs.

Characteristics:
- clear;
- contemporary;
- calm;
- high enough contrast for accessibility;
- not electric/neon.

Blue means:
> **this is active / actionable / selected**

not:
> **this is important / better**

---

## THRESHOLD / WARM ACCENT — Restrained gold

Used sparingly for:
- Focus;
- meaningful threshold moments;
- selected Work identity accents;
- quiet MAIA warmth;
- subtle visual continuity with Soullab.

Gold must not become:
- the default button color everywhere;
- an evaluative "premium / best" color;
- a score;
- a severity indicator.

Gold means:
> **warm attention**

not:
> **winner / quality / priority**

---

## TEXT — Ink hierarchy

Use:
- near-black/navy ink for primary reading;
- softer slate/charcoal for secondary content;
- subdued metadata;
- accessible disabled state.

Never rely on opacity so low that text becomes decorative rather than readable.

---

## STATUS COLORS

Status colors are reserved for actual state:

- error;
- warning;
- success;
- stale;
- unavailable.

Do not reuse them for manuscript evaluation.

Red/orange must never mean:
> weak writing / serious problem.

Green must never mean:
> good writing / ready.

---

# 4. Dark Rail

A dark Soullab rail may persist as application chrome.

Its job:
- orient;
- hold product identity;
- contain mode navigation;
- recede from Work.

It must not:
- become the visual center;
- carry analytical content;
- dominate manuscript contrast;
- become a permanent content region;
- use decorative density.

At wide desktop, visual weight should still resolve toward:
> **the Work**

not:
> **the rail**

---

# 5. Typography Roles

## WORK TYPE

Use an elegant readable serif for:
- Work title;
- manuscript;
- passage quotations;
- major literary headings where appropriate.

Purpose:
> preserve the feeling of writing and reading a book.

Requirements:
- comfortable long-form reading;
- strong italics;
- readable punctuation;
- robust at enlarged text sizes;
- no overly ornamental display serif for body copy.

---

## PRODUCT TYPE

Use a clean sans-serif for:
- navigation;
- controls;
- metadata;
- tabs;
- provenance;
- coverage;
- status;
- buttons;
- helper copy.

Purpose:
> make the system legible and quiet.

---

## TYPE SEMANTICS

Serif:
> the Work / reading / authored material.

Sans:
> the system / navigation / action / trust metadata.

Do not mechanically apply serif to every heading.
Do not make manuscript prose look like generic product body copy.

---

# 6. Type Scale

All user-facing typography must use scalable units.

Requirements:
- rem/em where appropriate;
- survives browser text enlargement;
- hierarchy remains clear at 125%, 150%, and practical 175%;
- no fixed-height containers clipping enlarged copy.

The product may become taller.
It must not hide meaning to preserve a screenshot.

---

# 7. Manuscript Measure

The manuscript reading measure is a protected product value.

It should:
- remain comfortable for sustained prose;
- not stretch across an ultra-wide display;
- not collapse because side panels appear;
- remain stable when MAIA opens;
- enlarge appropriately when contextual layers dismiss.

The exact measure may use existing Studio tokens.

Visual law:
> **the prose never feels like a dashboard column.**

---

# 8. Spatial Hierarchy

At first glance the eye should find:

1. Work / current place;
2. manuscript or primary Work intelligence;
3. immediate next move;
4. contextual system detail.

Never reverse this hierarchy.

Bad:

```text
controls
tabs
filters
metadata
panels
manuscript
```

Good:

```text
Work
manuscript / Work object
quiet invitation
contextual controls
```

---

# 9. Write Composition

WRITE remains:

> **manuscript-first**

Permanent:
- app chrome;
- Work identity;
- manuscript;
- quiet mode/facet state;
- Focus.

Contextual:
- outline;
- MAIA;
- History;
- Related;
- teaching;
- Review.

Forbidden primary composition:
```text
outline | manuscript | MAIA
```

as three permanent content regions.

---

# 10. Contextual MAIA

On desktop:

- MAIA appears anchored near the held locus;
- she uses reserved contextual space;
- she does not push or cover the passage;
- she dismisses cleanly;
- she shares the warm/cool visual system;
- she is not a dark utility sidebar.

On mobile:
- sheet/card;
- manuscript remains primary;
- no squeezed rail.

MAIA should feel:
> **present**

not:
> **installed beside the Work**

---

# 11. Review Composition

Founder ruling:

> **Review intelligence + manuscript context** is lawful.

At desktop:

```text
Review intelligence | Manuscript context
         contextual MAIA
```

Rules:
- both panes belong to the same Work;
- manuscript remains visibly alive;
- selected finding highlights exact locus;
- finding and passage feel relational;
- no permanent third MAIA content rail.

Review must not resemble:
- a report;
- an admin dashboard;
- a list of cards floating in empty space.

The Work must visually answer:
> **where does this finding live?**

---

# 12. Develop Composition

Develop must feel like:
> **seeing the Work from another altitude**

not:
> analytics.

Primary visual objects may include:
- Continuity Map;
- declared structure;
- evidence-linked patterns;
- Work coverage;
- chapter/section relations.

Use:
- generous white/warm space;
- clear addresses;
- restrained color;
- visible provenance.

Avoid:
- dense KPI tiles;
- scorecards;
- "health" indicators;
- red/green manuscript performance;
- dashboard clutter.

---

# 13. Continuity Map

The Continuity Map should visually communicate:

> presence across the Work.

It may use:
- intensity/frequency;
- discrete count/presence states;
- horizontal scroll on narrow screens;
- exact clickable cells.

It must not visually imply:
- quality;
- importance;
- emotional intensity;
- recommendation.

Legend language:
- Often
- Sometimes
- Once or twice
- Not present

not:
- Strong
- Weak
- High
- Low

unless the quantity literally measures a neutral count with an explicit definition.

---

# 14. Visualization Grammar

## MEASURED / VERIFIED

May use:
- grid;
- count;
- simple bar;
- line only for genuinely ordered quantitative measures;
- labels;
- scale;
- explicit source.

Visual tone:
- crisp;
- objective;
- restrained.

---

## MAIA INTERPRETATION

Should use:
- prose;
- attributed cards;
- annotated thread;
- soft relational grouping;
- reversible map overlay;
- evidence links.

Visual tone:
- interpretive;
- attributed;
- conversational.

Never make an interpretation look like telemetry.

---

# 15. Provenance Grammar

Provenance must be quiet but visible.

Examples:

### IN YOUR TEXT
neutral/cool factual badge.

### YOU NAMED THIS
warm/member-owned treatment.

### YOU CHOSE THE SPIRAL TEMPLATE
distinct member-choice treatment.

### MAIA NOTICED THIS
MAIA-attributed treatment.

They should be distinguishable without becoming loud labels.

Do not use identical styling for all provenance kinds.

---

# 16. Cards

Cards are contextual containers, not the product itself.

Use cards when they help:
- contain an observation;
- separate evidence;
- create an invitation;
- hold trust information.

Avoid:
- card-on-card-on-card;
- every line in a bordered rectangle;
- KPI tile walls;
- excessive rounded rectangles.

If the page can be understood without a card, consider removing the card.

---

# 17. Borders, Radius, Shadows

Use:
- restrained radius;
- subtle edge separation;
- minimal shadow.

The product should feel tactile enough to navigate, not bubbly.

Avoid:
- oversized pill everything;
- heavy glassmorphism;
- deep shadows;
- neon glow;
- thick divider grids.

---

# 18. Atmosphere

Atmosphere is structural.

Preferred order:

1. member-selected / Work-owned imagery;
2. member-approved Work visual identity;
3. neutral Soullab environmental atmosphere;
4. abstract warm gradient / texture;
5. no image.

Generated imagery must not masquerade as:
- manuscript evidence;
- an actual place in the Work;
- declared visual identity.

Decorative atmosphere must remain decorative.

---

# 19. Photography

Photography is optional.

When used:
- authentic to Work or member choice;
- quiet crop;
- low informational dominance;
- does not steal manuscript attention.

Avoid:
- generic stock "author at desk";
- cinematic AI landscape that appears to define the book;
- imagery repeated on every surface regardless of Work.

---

# 20. Focus Mode

Focus mode strips the system back.

Preserve:
- manuscript;
- Work identity;
- minimal return;
- writing controls needed for authorship.

Reduce:
- atmosphere;
- map;
- Review;
- secondary metadata;
- persistent prompts.

Focus is not a different visual theme.
It is the Studio becoming quieter.

---

# 21. Buttons

Primary actions:
- clear;
- calm;
- limited in number.

Secondary:
- textual / subtle.

Danger/destructive:
- explicit;
- not visually confused with ordinary dismissal.

Avoid:
- five competing primary buttons;
- giant CTA treatment inside manuscript reading;
- reward-like button styling.

Button labels describe member intent.

Prefer:
- Read in context
- Keep my original
- Go to passage
- Talk it through
- Read this chapter again

Avoid:
- Execute
- Run
- Process
- Optimize
- Generate output

---

# 22. Links vs Buttons

Use link-like treatment for navigation:
- Go to passage
- Back to Review
- View evidence
- See what MAIA read

Use button treatment for consequential actions:
- Apply this revision
- Read this chapter again
- Keep with this passage

Visual language should help the member distinguish:
> **move**

from:
> **do**

---

# 23. Tabs

Tabs are for filtering/perspective, not commissioning.

Primary labels may be plain language:

- Everything
- How it's put together
- Whether the thread holds
- How it sounds
- Whether it stays consistent
- How it moves
- How it might land

Secondary craft labels may appear discreetly:
- Structure
- Continuity
- Voice
- Flow
- Reader perspective

Tabs should not look like a complex pro-editor toolbar.

---

# 24. Facet Control

`Guided · Learning · Direct`

Placement:
- quiet;
- near Work identity;
- not a large segmented control dominating the page.

The control communicates:
> **how MAIA meets me**

not:
> skill level.

No beginner/intermediate/expert visual cues.

---

# 25. Empty States

Empty states get space.

Example:

> **This appears only here so far.**

One message.
One or two next actions.

Do not fill empty states with decorative analytics.

Whitespace is valid information.

---

# 26. Stale Reading

Unacknowledged:
- visible;
- impossible to confuse with current;
- prominent enough to protect trust.

Acknowledged / Not now:
- compact persistent strip;
- does not dominate the room;
- remains reachable.

The stale-warning treatment should use status language, not danger theater.

---

# 27. Error Visuals

Errors are:
- calm;
- local;
- specific;
- recoverable.

Do not:
- replace whole room with red error page when local recovery is possible;
- use alarming color when Work is safe;
- center technical codes.

Always pair with:
- Work status;
- recovery;
- return path.

---

# 28. Loading

Loading should preserve structure.

Prefer:
- skeleton/state placeholder in the exact region;
- current manuscript remains visible;
- old lawful reading remains visible while refresh occurs.

Avoid:
- blanking the Work;
- blocking spinner over entire Studio;
- fake progress bars.

---

# 29. Motion

Motion is functional.

Use for:
- contextual reveal;
- sheet transition;
- passage focus;
- return to locus;
- subtle state acknowledgement.

Avoid:
- celebratory animation;
- gamified bounce;
- motion after Apply suggesting "success" as a quality judgment;
- decorative parallax around manuscript.

Respect reduced-motion preferences.

---

# 30. Accessibility Visual Rules

- visible keyboard focus;
- focus color has sufficient contrast;
- no critical meaning conveyed only by hue;
- selected/unselected differs by more than subtle color;
- text contrast supports sustained reading;
- provenance distinguishable without relying on color only;
- status icons have text or accessible label;
- maps work at enlarged text;
- hover never contains exclusive critical information.

Accessible design is the flagship design.

---

# 31. Mobile

Mobile should feel intentionally composed.

Use:
- one content column;
- bottom/top mode nav where appropriate;
- contextual sheets;
- scrollable data maps;
- sticky return only if it aids place;
- manuscript-first reading.

Do not:
- shrink desktop sidebars;
- hide essential trust information;
- rename modes;
- collapse map labels beyond comprehension.

---

# 32. Desktop Width Behavior

## 1920
Do not allow manuscript or Review copy to become an ultra-wide empty field.

Use:
- protected measure;
- meaningful Work context;
- balanced composition.

## 1440
Primary target should feel complete, not cramped.

## Laptop
Contextual regions may collapse/dismiss before manuscript suffers.

Never protect side panels at the expense of readable Work.

---

# 33. Cross-Mode Family Test

A screenshot with the labels removed should still plausibly belong to the same product.

Shared:
- ground;
- type;
- interaction blue;
- gold restraint;
- radius;
- spacing;
- rail;
- provenance;
- control language;
- atmosphere.

Develop must not look like a different analytics product.
Review must not look like a report generator.
Write must not look like a bare text editor.

---

# 34. Visual Density

The Studio should carry enough information to invite exploration without becoming visually exhaustive.

Preferred rhythm:

```text
recognition
space
primary Work object
space
one next move
supporting detail
```

Not:

```text
header
toolbar
subtoolbar
tabs
filters
cards
cards
cards
controls
footer controls
```

---

# 35. Legacy Visual Falsifiers

Immediate visual REVISE if the candidate materially reproduces:

- permanent three-content-column layout;
- permanent MAIA sidebar;
- permanent outline rail;
- narrow manuscript wedged between utilities;
- `Rebuild preview`;
- technical workbench vocabulary as chrome;
- dark/black dominant workspace;
- too much empty black space;
- right-side machinery stack;
- UI that feels alien / impersonal / overly technical.

---

# 36. Generic SaaS Falsifiers

Also REVISE if the candidate becomes:

- pure white/blue enterprise dashboard;
- grid of pastel KPI cards;
- generic AI copilot sidebar;
- stock productivity app;
- analytics-first interface;
- interchangeable with Notion/Linear-like software.

Soullab must retain literary warmth and relationship.

---

# 37. Over-Luxury Falsifiers

REVISE if:

- brown/gold overwhelms the Work;
- dark rail dominates the composition;
- serif used for system controls excessively;
- atmosphere feels like boutique hotel branding;
- every action becomes gold;
- visual restraint turns into solemnity.

Warmth must still feel alive and contemporary.

---

# 38. Reference / Candidate Protocol

Every V10 visual submission includes:

```text
reference id
candidate commit
same viewport
same product state
known intentional deviations
known unresolved visual laws
```

Do not compare:
- different viewports;
- different states;
- reference overview vs candidate substate.

No judging from memory.

---

# 39. Visual Acceptance Gates

## VS1 — WARM LITERARY FOUNDATION
Ground and Work typography feel literary and human.

## VS2 — COOL INTERACTION CLARITY
Interactive state is lucid and contemporary.

## VS3 — GOLD RESTRAINT
Gold does not become evaluation or visual noise.

## VS4 — WORK DOMINANCE
The eye finds the Work before system machinery.

## VS5 — MANUSCRIPT MEASURE
Long-form reading remains comfortable.

## VS6 — CONTEXTUAL MAIA
MAIA is present without becoming a permanent utility rail.

## VS7 — REVIEW RELATIONSHIP
Review finding and manuscript context remain visibly connected.

## VS8 — DEVELOP NOT ANALYTICS
Develop reveals relationships without KPI/dashboard language.

## VS9 — PROVENANCE VISIBLE
Member/Text/Template/MAIA origins are distinguishable.

## VS10 — VISUALIZATION TRUTH
Measured vs interpretive objects look epistemically different.

## VS11 — ACCESSIBLE HIERARCHY
Scaling/contrast/focus preserve meaning.

## VS12 — MOBILE INTENTIONAL
Mobile is composed, not crushed.

## VS13 — CROSS-MODE FAMILY
Write / Develop / Review / Mobile unmistakably belong together.

## VS14 — NO LEGACY
Old Writer's Studio composition cannot visually survive.

## VS15 — NO GENERIC SAAS
Soullab remains distinctive.

# 40. Token-Implementation Rule for CC

Before changing concrete tokens, CC should audit:

- existing `studioTheme` tokens;
- current flagship candidate tokens;
- approved reference roles;
- contrast;
- dark rail;
- serif/sans assignments;
- existing spacing/radius.

Then propose the **smallest token normalization** that satisfies this canon.

Do not scatter per-component magic colors or font sizes.

Prefer named semantic tokens:

```text
ground.work
ground.system
surface.quiet
surface.raised

text.work
text.primary
text.secondary
text.muted

action.primary
action.hover
action.focus

accent.warm

status.stale
status.error
status.success

provenance.member
provenance.text
provenance.maia
provenance.template
```

Exact naming is implementation-owned.
Semantic roles are product law.

>

>
