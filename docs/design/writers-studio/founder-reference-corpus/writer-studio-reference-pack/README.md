## Implementation rule

Use the current repository as authority for data, APIs, storage, memory, auth, revisions, import, and existing intelligence.
Use these images as authority for experiential hierarchy, spatial composition, density, visual priority, and relationship between Work / Materials / Structure / MAIA.

Do not hard-code screenshot data. Bind the real product substrate.
Do not preserve a weak existing layout merely because it already exists. Preserve capability; replace weak presentation.

## Acceptance loop

For each target field:

1. Render the actual implementation at the reference viewport.
2. Capture a screenshot.
3. Compare against the corresponding reference.
4. Fix the largest differences in hierarchy, proportions, density, typography, spacing, and panel relationships.
5. Repeat until the running UI is recognizably the same designed product.

Functional tests alone are not acceptance.
