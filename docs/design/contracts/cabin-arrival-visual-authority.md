# Cabin Arrival — Visual Authority

## 1. Core visual ruling

Cabin Arrival should feel like entering a living interior, not opening software.

The visual center remains intentionally spacious.

The continuity field is perceived around the member rather than displayed as a
collection of records.

The governing experience is:

    presence → orientation → choice

not:

    data → cards → action menu

## 2. Relationship to House

Cabin shares the Soullab family with House:

- editorial serif hierarchy;
- warm dark materiality;
- restrained bronze/gold wayfinding;
- quiet rules and thresholds;
- holoflower geometry used sparingly;
- readable human-language copy;
- generous negative space.

Cabin does **not** copy House literally.

Do not carry forward:

- the House architectural photograph;
- the House public-platform rail;
- House-specific world-card grid;
- public navigation chrome;
- House background artwork as Cabin scenery.

Cabin should feel like the sovereign interior behind the House threshold.

## 3. Composition

### Desktop

Use a full-height field with four visual zones:

1. **Quiet identity band** — small Soullab/Cabin mark and a restrained return/control
   area. No navigation bar.
2. **Arrival field** — a large central area with the welcome/orientation statement
   and substantial negative space.
3. **Continuity ring** — three quiet domain doorways arranged around the central
   field: Work, Relationships, Memory.
4. **MAIA threshold** — a distinct, quieter threshold available without competing
   with the three domain doorways.

The domain doorways are not equal-sized dashboard cards. They should read as
places in one field.

### Mobile

The same field becomes vertical without becoming a stacked card dashboard.

Order:

    identity
    welcome
    continuity presence
    domain doorways
    MAIA threshold
    return

Preserve the same negative-space rhythm and visual hierarchy.

## 4. Material language

Primary field:

- deep warm charcoal / near-black;
- subtle tonal depth rather than a flat fill;
- faint atmospheric gradient;
- no literal landscape or narrative imagery.

Surface material:

- translucent warm-dark membranes;
- fine low-contrast rules;
- soft bronze/gold edge accents;
- restrained shadow depth;
- no glossy glassmorphism;
- no bright white cards.

The field should feel tactile and architectural without pretending to be a
physical room.

## 5. Typography

Primary editorial voice:

- House Crimson / equivalent approved Soullab editorial serif;
- light to regular weights;
- generous line height;
- large welcome statement with calm scale.

Supporting interface language:

- clean sans-serif;
- small uppercase labels only where orientation benefits from them;
- generous tracking;
- never programmer language;
- never database terms;
- never product-management labels.

The typography should make the member feel addressed, not administered.

## 6. Color

Cabin uses one restrained warm accent for primary orientation.

Do not assign Work, Relationship, and Memory separate elemental colors in the
arrival surface. Doing so would turn domain presence into semantic coding that
the arrival layer does not own.

Permitted accent behavior:

- thin rules;
- quiet doorway glow;
- focused control state;
- holoflower wayfinding.

Forbidden:

- traffic-light status colors;
- colored severity;
- progress colors;
- rainbow domain coding;
- color used to imply importance.

## 7. Domain doorway behavior

Each doorway has:

- domain name;
- one short human-language orientation phrase;
- a subtle presence treatment when the domain is present;
- a quiet empty treatment when it is empty;
- an explicit enter gesture.

It does not show:

- counts;
- recent items;
- titles from every carried object;
- summaries;
- relationship names;
- memory bodies;
- rankings;
- recommendations.

A doorway is a threshold, not a card containing the room.

## 8. Presence states

### Unavailable

The field remains calm.

Do not show a technical error.
Do not search another source.
Do not suggest that continuity has been lost.

Visual treatment: the domain doorways remain available as places, with no false
continuity signal.

### Empty

Empty is quiet rather than deficient.

Use absence of the presence treatment rather than an error state.

### Present

Presence may be represented by:

- a faint luminous edge;
- slight material depth;
- a small non-symbolic point or halo;
- restrained typographic emphasis.

Presence must never become a count or notification badge.

## 9. Work law

Multiple Works remain multiple.

The arrival surface must never visually privilege one Work merely because it is
first, newest, largest, or easiest to render.

If the member has explicitly chosen a Work, that choice may be carried into the
destination. The arrival surface does not manufacture that choice.

## 10. Relationship law

Relationship presence is represented as a doorway, not a social graph.

No avatars, names, relationship scores, or relational summaries appear here.

The relationship room owns relational meaning.

## 11. Memory law

Memory presence is represented as continuity, not recall.

No memory text, memory cards, timelines, or recalled passages appear on arrival.

Memory recall begins only after an explicit member act inside the appropriate
experience.

## 12. MAIA visual presence

MAIA is represented as a threshold rather than an avatar.

Preferred language:

- subtle luminous field;
- holoflower or restrained abstract geometry;
- text/voice threshold.

Avoid:

- face;
- human figure;
- guru/guide imagery;
- chat transcript on arrival;
- unsolicited MAIA speech;
- ambient model-generated interpretation.

MAIA is available to be entered, not already speaking.

## 13. Motion

Motion is atmospheric, nearly subconscious.

Allowed:

- 15–30 second field breathing;
- 1–2% scale drift;
- slow opacity movement;
- extremely subtle parallax;
- doorway settling after explicit selection.

Forbidden:

- pulsing notifications;
- attention-seeking particles;
- spinning sacred geometry;
- motion synchronized to inferred emotion;
- animated status indicators;
- automatic movement that competes with reading.

Reduced-motion mode preserves the same composition through static depth and light.

## 14. Accessibility

Visual quiet must not become interaction ambiguity.

Every doorway must:

- be keyboard reachable;
- have a visible focus state;
- have a meaningful accessible name;
- remain usable without hover;
- preserve readable contrast;
- retain meaning with reduced motion;
- preserve the same order on narrow screens.

## 15. Copy grammar

Copy should use human language.

Prefer:

- Welcome home.
- What you carried is here.
- Work
- Relationships
- Memory
- Meet MAIA
- Enter

Avoid:

- context package;
- mounted state;
- projection;
- local authority;
- synchronization;
- source assembly;
- memory atom;
- runtime refresh.

The implementation may know these things. The member-facing room does not need
to expose them.

## 16. Visual falsifiers

F1 — dashboard collapse: the arrival becomes a grid of information cards.
F2 — object privilege: one Work receives stronger visual emphasis without explicit choice.
F3 — memory leakage: memory content appears at arrival.
F4 — relationship leakage: relationship names or interpretation appear at arrival.
F5 — MAIA leakage: MAIA speaks or generates cognition without an explicit threshold act.
F6 — technical chrome: runtime/custody terminology appears in member-facing copy.
F7 — public-House copy: Cabin becomes a duplicate of the House rather than a sovereign interior.
F8 — symbolic determination: colors or imagery tell the member what a domain means.
F9 — activation coupling: entering or viewing arrival causes refresh, remount, discovery, or fetch.
F10 — mobile collapse: mobile becomes a vertically stacked dashboard rather than the same living field.

## 17. Exact implementation law

H4.1 authorizes **visual conformance prototyping only**.

The first implementation must:

1. use fixture-only state;
2. render unavailable / empty / mounted variants;
3. render desktop and mobile;
4. use no real Work, Relationship, Memory, or MAIA cognition;
5. capture visual evidence;
6. stop before binding real Cabin data.

## 18. Acceptance

H4.1 was visually accepted after founder review of the fixture-only arrival
surface on 2026-10-01. No visual changes were requested at adjudication.

This authority now governs H4.2 implementation. It still does not itself admit
member-facing production code; H4.2 must bind the real mounted context without
crossing the semantic and activation boundaries above.
