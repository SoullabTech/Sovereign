# An account threshold, not a second Home

The House remains the experience the member knows. Home and House server responses
are deliberately neutral; a cookie authenticates the server request but cannot
attest to the previous browser owner's local state. Once the current person and
server identity agree, the client retrieves only that member's authorized Work
and preferences as private no-store JSON. The screen never invites a stranger
to claim or erase older local information.

A first-use browser receives an explicit Continue gesture. A mismatch receives
one neutral explanation and the choice to sign out or return to public Soullab,
without displaying either person's name, moving local writings, or manufacturing
a consent gesture. The separate per-account storage namespace governs *new*
client-local House data; legacy unscopeable browser information remains held for
consented stewardship rather than silently migrating to someone else.

A script executing in the same origin with a valid member cookie retains the
server-authenticated rights of that session. The browser account check is a
UI continuity and custody protection, **not** an XSS-proof cryptographic
attestation. A real human security reviewer must approve the threat model.
