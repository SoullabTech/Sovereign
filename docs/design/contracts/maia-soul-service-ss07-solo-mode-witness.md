## Purpose

SS-07 tests a core planned-obsolescence requirement:

> Soullab must remain useful when MAIA recedes.

Solo Mode is not an error state, reduced tier, or failed engagement state.

It is a member-agency mode.

## Solo Mode includes

- source access;
- field orientation;
- member-visible presences;
- member writing / reflection space;
- no generated interpretation.

## MAIA invitation

MAIA appears only after an explicit:

> **Invite MAIA into this exact context**

The prototype states that MAIA receives only the context intentionally brought into the interaction.

MAIA does not rewrite the source or member note.

## Return to Solo Mode

Leaving MAIA hides the AI panel while preserving member-authored work.

The member does not lose their note or source state by returning to Solo Mode.

## Planned-obsolescence significance

Solo Mode provides a future way to test whether a member can:

- orient;
- compare;
- map;
- write;
- synthesize;

without generated interpretation.

Reduced MAIA use must not automatically count as lower engagement or failed retention.
