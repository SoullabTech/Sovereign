# Writer’s Studio — Beta Consent & Custody

These surfaces make two different member acts legible.

## Consent threshold

The writer is told what participating in this small beta means before Studio access is treated as complete. Consent is an explicit act recorded by the server; simply possessing an invitation, signing in, or opening a URL is not consent.

The screen must make the consequence understandable without legalistic clutter or pressure. Refusal or withdrawal must not quietly convert into continued editorial access.

## Custody

The writer can see the Work the beta currently holds for them and deliberately export or delete it. Destructive action requires an explicit confirmation. The interface must not claim that a source has been destroyed unless the server has durably completed the deletion obligation.

Backup retention and live Studio custody are distinct. Copy must not describe live deletion as erasing every historical backup when that has not been established.

## House / room boundary

**Same House:** recognizable Soullab identity, calm typography, truthful consequences, and member sovereignty.

**Distinct room:** these are operational thresholds around an authored writing relationship. They do not expose other members, widen cohort admission, create public registration, infer consent from use, or turn manuscript custody into a generic settings dashboard.

## Beta acceptance

Before real writers are invited, the exact R7 build must demonstrate: invitation → password setup → sign-in → consent → Studio; and authenticated custody listing/export/deletion with owner isolation. Desktop and narrow/mobile presentation are checked as part of that same release walk.
