# LIVING-FIELD-RETURN-CONTINUITY-LAW-01

**Date:** 29 September 2026
**Status:** governing local integration law
**Runtime authority:** only within explicitly authorized local witness candidates

> **Return restores the member's prior orientation, not the system's preferred starting state.**

Return is not merely navigation.

It is the inverse movement of entering a Living Field presence.

## Continuity dimensions

### 1. Identity continuity

The opened presence must remain recognizably the same presence through entry and return.

Where supported, the same stable transition identity should be used across both states.

### 2. Topological continuity

Return restores the field state the member left:

- quiet remains quiet;
- widened remains widened;
- the same surrounding neighborhood remains available;
- return does not silently reset the field.

### 3. Attentional continuity

Keyboard focus returns to the exact presence opener when possible.

The member should not have to rediscover where they were.

### 4. Viewport continuity

Return restores the prior page position rather than jumping to the top or another system-selected location.

### 5. Epistemic continuity

Temporary MAIA apertures, comparisons, and rejected suggestions do not become durable truth through return.

In this pilot:

- kept aperture = current entered-presence visit only;
- rejected aperture = no residue;
- unresolved = no forced synthesis;
- leaving the presence clears aperture state.

### 6. Temporal continuity

Returning later may recover source history or previously member-kept state under separately authorized memory rules.

This law does not authorize that persistence.

Current 02R1 return is current-navigation continuity only.

## Reversibility

The entry and return movements should feel like two directions through one continuous field.

Return should not feel like:

> close page → reconstruct context

It should feel like:

> widen back into the field I came from.

## View Transition admission

02R1 may use the View Transitions API only because it directly serves:

- identity continuity;
- spatial continuity;
- reduced context loss.

Requirements:

- semantic DOM remains authoritative;
- unsupported browsers fall back cleanly;
- reduced-motion preference bypasses animated transition;
- no meaning depends on the animation;
- transition identity cannot imply unsupported importance.

## Failure conditions

Return fails if it:

- resets widened / quiet state;
- loses the exact source identity;
- jumps the member to an unrelated scroll position;
- drops keyboard focus into the document root without need;
- persists rejected MAIA apertures;
- treats a kept-for-visit lens as durable memory;
- requires motion to understand what happened.

## Acceptance sentence

> **I can go deeper and come back without having to reconstruct where I was.**
