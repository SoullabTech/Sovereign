## Purpose

SS-06 tests whether relation can become a member-shaped cognitive act rather than a generic AI graph edge.

The prototype distinguishes three relation standings:

- **you connected this** — member-authored;
- **you confirmed** — member-confirmed;
- **MAIA sees a possible connection · not yet yours** — model candidate.

## Required member acts

The prototype allows the member to:

- create a relation;
- name it;
- revise its label;
- accept and rename a MAIA candidate;
- reject a MAIA candidate;
- release an existing relation.

## Release semantics

Release removes the relation from the local field.

It does **not** remove either source object.

No source history is rewritten.

## MAIA-candidate semantics

The candidate relation between Elemental Alchemy and Relational Geometry is dashed and textually marked:

> **MAIA sees a possible connection · not yet yours**

If accepted, standing changes only after the member supplies / accepts wording.

If rejected, the candidate disappears.

Rejection is not recorded as resistance or incomplete insight.

## Visual law

Line style is supplemental.

Textual standing remains visible, so authorship does not depend on color or line appearance alone.

## Acceptance questions

1. Can the member tell who authored each connection?
2. Does accepting a MAIA candidate feel like conferring standing rather than uncovering hidden truth?
3. Does rejecting a candidate feel complete?
4. Can a label be revised without rewriting either source?
5. Does releasing a relation leave both sources intact?
6. Does creating a relation feel like an act of thought rather than settings management?
7. Are member-authored and member-confirmed standings meaningfully distinct?
8. Does the field remain legible when a relation disappears?
9. Would the member understand that relation history and source history are different?
10. Does this advance generative mapping without becoming a generic mind-map editor?
