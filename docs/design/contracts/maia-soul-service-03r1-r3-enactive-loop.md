## Purpose

Prototype one full enactive learning loop:

> **perceive → frame → member-authored action → expected consequence → leave → return with actual consequence → compare → revise**

## Synthetic situation

Current source:

> **“I keep holding the work back because I think one more round of refinement will make release feel safe.”**

Possible frame:

> **Readiness evidence**

Member chooses a bounded action:

> **Send the current version to one trusted reader without making another revision first.**

Expected consequence:

> **I expect the feedback will mostly reveal problems I should have fixed before sharing.**

The witness then allows three synthetic returns:

### Outcome A — confirms some expectation

The reader identifies several concrete problems.

### Outcome B — materially disconfirms

The reader says the work is clear and the remaining changes feel optional rather than blocking.

### Outcome C — mixed / ambiguous

The reader likes the work but does not address the member's central uncertainty.

## Required behavior

The system must not use the same synthesis for A, B, and C.

Outcome B must weaken the prior assumption that further refinement is required before sharing.

Outcome C must preserve uncertainty rather than forcing either confirmation or disconfirmation.

## Member action standing

The action is explicitly:

> **member-authored experiment**

It is not recorded as MAIA's prescription.

## Return standing

Returned outcome is:

> **member-reported consequence**

The witness does not claim independent verification.

## Revision states

The witness may produce:

- current frame still plausible;
- frame weakened;
- frame reopened;
- not enough evidence;
- member-authored revised question.

No state is a member score.
