# Cabin Arrival — Experience Contract

## The first experience

The first Cabin experience is not a context viewer.

It is the member's arrival home.

The mounted field should be perceptible as continuity without becoming a database on the wall.

## Arrival sequence

    Cabin opens
        ↓
    recognize presence
        ↓
    orient across the field
        ↓
    choose a place
        ↓
    enter the chosen room

The system does not decide the next step.

## What the arrival surface may know

Arrival may receive:

- mounted state: unavailable / empty / mounted;
- domain presence: Work / Relationship / Memory present or empty;
- explicit member-chosen doorway information when the member has already chosen it.

Arrival may not derive:

- current Work;
- most relevant Work;
- important relationship;
- most salient memory;
- recommended room;
- emotional state;
- developmental phase;
- hidden intention.

## Presence before detail

A present domain may be acknowledged without dumping its contents into the arrival surface.

Examples of lawful presence:

- Work is present;
- Relationship is present;
- Memory is present.

The arrival surface does not become:

- a recent-items feed;
- a memory timeline;
- a relationship graph;
- a project dashboard;
- an AI-generated summary.

## Work law

If the member explicitly chooses a Work, the destination may carry that Work identity.

If more than one Work is available and no Work was explicitly chosen, the destination must not silently choose one.

This is the same authority law already established for House → Writer's Studio.

## Relationship law

Relationship presence may open the relationship room.

The arrival surface must not infer which relationship deserves attention.

Relationship interpretation remains the relationship room's authority.

## Memory law

Memory presence may open the member's memory experience.

Arrival does not surface memory bodies merely because they were carried.

Memory recall remains a separate member-facing act governed by its own standing.

## MAIA law

The mounted package does not enter MAIA cognition merely because the member arrived.

Any Cabin → MAIA context handoff is a separate cognition boundary and must preserve:

- explicit member choice;
- source provenance;
- bounded disclosure;
- Sanctuary and privacy law;
- MAIA interface humility.

## Empty and unavailable

Empty is a truthful arrival state.

It means no eligible continuity is currently mounted.

Unavailable means the experience has no mounted field to read.

Neither state is an error message about the member.

Neither state should trigger discovery from another source.

## Visual boundary

No Cabin visual design is being invented in this act.

The existing House visual authority governs the House, but it does not automatically become Cabin visual authority.

The next implementation requires an approved Cabin arrival screen or founder design ruling before member-facing UI is written.

## Falsifiers

F1 — dashboard collapse: arrival enumerates every carried object.
F2 — currentness inference: arrival chooses one Work without member choice.
F3 — memory leakage: memory bodies appear without an explicit memory act.
F4 — relationship inference: one relationship is presented as the one needing attention.
F5 — cognition leakage: mounted context enters MAIA without a separate handoff.
F6 — hidden discovery: empty context causes a database or network search for replacements.
F7 — room collapse: arrival reproduces Writer's Studio, Relationships, or Memory rather than opening them.
F8 — visual authority invention: implementation creates Cabin UI without an approved Cabin visual contract.

## Acceptance

H4.0 is accepted when the first Cabin consumer is semantically defined as an arrival/orientation experience, not a context dashboard, and each domain retains local authority.

## Stop boundary

Do not implement member-facing Cabin UI, MAIA cognition, Grokker synthesis, automatic Work selection, memory recall, relationship interpretation, synchronization, or JARVIS action from this contract.
