# GROKKER-LIVING-FIELD / TECHNOLOGY-LAYER-01
## Emerging Technology Evaluation for Grokker

**Status:** pre-implementation evaluation doctrine
**Date:** 29 September 2026
**Implementation authority:** none

Grokker is the Living Field Architecture surface allowed to work nearest the technological edge.

That permission is constrained by:

> **technical possibility does not define experiential purpose.**

## Rendering tiers

### Tier 1 — Semantic DOM

Carries:

- text;
- labels;
- accessible controls;
- provenance;
- MAIA dialogue;
- keyboard navigation;
- focus management;
- inspectable relation standing.

This is the semantic truth layer.

### Tier 2 — Spatial SVG / Canvas

Carries most first serious spatial behavior:

- relations;
- clustering;
- paths;
- topology;
- ordinary semantic zoom;
- animated rearrangement;
- membranes;
- stable spatial identity.

### Tier 3 — GPU Field

Use WebGPU only when scale or visual computation genuinely requires it:

- very large relational fields;
- thousands of visible objects;
- fluid topology;
- sophisticated geometry;
- force / field visualization where the force actually represents governed structure;
- dense real-time relational rendering.

The GPU layer is enhancement.

It is never the epistemic substrate.

> **GPU renders the field. It never owns the field.**

## Technology evaluation matrix

### View Transitions

Potential value:

- preserve identity across page/state transition;
- make semantic zoom continuous;
- reduce page-replacement feeling;
- support truthful return.

Candidate uses:

- House → room → House;
- constellation → presence;
- work → thread → exact source;
- Grokker zoom between stable identities.

Admission test:

> Does the transition preserve recognizability and orientation better than an immediate swap?

Reject if:

- transition becomes decorative;
- motion implies importance;
- continuity breaks under reduced motion.

### CSS Anchor Positioning

Potential value:

- physically tether explanation to the object it concerns;
- reduce detached inspector-panel behavior;
- preserve relation between MAIA insight and exact source.

Candidate uses:

- Why this?;
- provenance;
- connection labels;
- MAIA possible frame;
- passage annotation;
- relation explanation.

Admission test:

> Does physical tethering reduce search and ambiguity?

Fallback:

- ordinary DOM placement near the referenced source.

### Scroll-driven animation

Potential value:

- member movement controls temporal unfolding;
- motion responds to exploration rather than autoplay;
- developmental histories can reveal and recede reversibly.

Candidate uses:

- timeline;
- manuscript history;
- gradual relation revelation;
- semantic-depth storytelling where scroll is already meaningful.

Reject if:

- scrolling becomes mandatory choreography;
- essential content exists only at a particular scroll fraction;
- reduced-motion behavior loses information.

### SVG / Canvas

Default spatial rendering tier for first serious Grokker.

Use for:

- graph edges;
- membranes;
- relation labels;
- topology;
- spatial continuity;
- moderate-scale semantic zoom.

Requirements:

- DOM-accessible equivalents;
- keyboard-selectable nodes;
- textual standing;
- inspectable source relation.

### WebGPU

Potential value:

- very high object count;
- rich real-time topology;
- fluid visual computation;
- spatial field effects at scale.

Admission threshold:

Use only when SVG/Canvas demonstrably cannot meet:

- object-count performance;
- interaction latency;
- topology complexity;
- visual computation requirements.

Do not use merely to make the interface look more advanced.

Fallback must retain semantic truth.

### Spatial Web Audio

Potential value:

- optional orientation cue;
- relative location;
- crossing / approach / return.

Not:

- soundtrack;
- mood engineering;
- subliminal importance.

Requirements:

- optional;
- user controllable;
- nonessential;
- meaning survives silence.

### Native haptics / Core Haptics

Potential value:

- crossing;
- settling;
- confirmation;
- apply;
- undo;
- release;
- zoom threshold.

Use haptics for bodily meaningful transitions, not generic tap decoration.

Requirements:

- sparse vocabulary;
- consistent semantics;
- user setting / platform accessibility;
- visual equivalent.

## Powerful combinations

### Stable identity + View Transitions

A work, person, or presence remains visibly itself while moving between contexts.

This is an implementation of spatial and semantic continuity.

### Anchor Positioning + MAIA

MAIA's insight stays attached to the exact node, relation, source, or contradiction it concerns.

This supports epistemic locality.

### Scroll-driven motion + temporal depth

The member controls unfolding and reversal.

This supports enactive temporal exploration.

### Spatial audio + field orientation

Optional cues can help indicate relative position or traversal direction.

They never encode psychological meaning.

### Haptics + thresholds

Boundary crossings become bodily legible without turning every interaction into vibration.

## Performance and density law

Rendering complexity must scale with actual need.

Suggested progression:

```text
DOM
 ↓ when spatial relation needs explicit geometry
SVG / Canvas
 ↓ only after measured performance threshold
WebGPU
```

Do not begin with Tier 3.

## Prototype-before-adoption rule

Every candidate technology must be tested against:

1. continuity;
2. embodiment;
3. revelation;
4. presence;
5. performance;
6. accessibility;
7. epistemic perception;
8. reduced-motion / no-audio fallback.

Only then may it enter a surface implementation.

## Exact stop

This document authorizes evaluation and prototypes only.

It does not authorize production adoption of any listed technology.
