## 1. CF-D5b — who may author the lens?

**The question, narrowed** (per the attachment record §7): *who may create a temporary
interpretive layer around a universal capability?* It does **not** decide ownership,
persistence, identity, or context survival — those are closed above it.

| | Option | Consequence |
|---|---|---|
| A | **Core ships a closed vocabulary set; practitioner selects** | ⛔ Violates universal §3 (*practitioners own the vocabulary*) and §0 — a practice whose language is not in the set must distort itself to fit. The universal field starts dictating domain language. |
| B | **Practitioner authors, unconstrained** | ⛔ Re-opens `Practice → Assignment`. Violates constraint authority (§1) — the label changes the authority model with it. |
| C | **Practitioner authors within an enforced constraint envelope** | ✅ Only option satisfying both §1 (constraint flows down) and §3 (naming flows up). |
| D | **Member authors the lens** | ⛔ Conflates the two naming layers (§3 lean). The member layer *complements* the expression layer; it does not replace it. A member cannot author the lens of a relationship they did not create. |

### ⭐ Recommended: **C** — with a consequence that must be ruled alongside it

> **C is only real if the constraint is a mechanism. If it is a document, the boundary is a
> description.** (Standing rule: *documentation as false control surface*.)

The enforceable part and the unenforceable part are **not the same part**, and pretending
otherwise is the failure mode:

| Layer | Enforceable? | How |
|---|---|---|
| **Verb binding** — every practitioner label binds to exactly **one** universal verb | ✅ **mechanically** | Authority attaches to the **verb**, not the string. The render firewall guarantees the stored object carries the verb, so the system's behaviour is fixed regardless of the word rendered. |
| **String semantics** — does the word *import compliance*? | ❌ **not mechanically decidable** | `Practice → Assignment` is still an invitation *to the system* if bound to the Practice verb — but the **member reads compliance.** This needs a human review gate, and must be named as one. |

⛔⛔ **Do not claim CF-D5b is enforced by the verb binding alone.** The binding closes the
authority hole; it does not close the language hole. Ruling C means accepting a human review
gate on label strings — or explicitly accepting the language risk.

## 2. Attachment model — which entity carries the vocabulary

**The settled rules already determine the shape.** Two of them, read together:

- **§5 render firewall** — vocabulary resolves at read time ⇒ attachment is a **lookup**, not
  an owner.
- **§4.4 release triggers** — *relationship ends · practitioner access withdrawn · member
  leaves the practice · practitioner vocabulary changes.* Each trigger names a **different
  entity**.

> 🔴 **No single carrier satisfies all four triggers.** That is why every candidate in the
> record §2 has a fatal risk column. The record was asking the wrong shape of question:
> *which entity* rather than *in what order*.

### ⭐ Recommended: a read-time resolution chain, first match wins

```
1  Member personal vocabulary      (member gesture)        ⏳ defer to v2 — see below
2  Program-scoped override         (specialization)
3  Practice-field / relationship   (the practitioner family)
4  Universal verbs                 (default — always resolves)
```

Each ruled release trigger then maps without special-casing:

| Trigger | Behaviour | Migration? |
|---|---|---|
| program ends | layer 2 drops · layer 3 still resolves | none |
| member leaves the practice | 2 and 3 drop · falls to 4 (member's own words) | none |
| practitioner changes vocabulary | layer 3 changes for everyone at once | **none** — and if it ever looks like one, write-time substitution has crept in |
| member returns | 3 resolves again · ownership never moved (§4.5) | none |

This is the founder instinct (*practitioner family + program specializes + member
personalizes*) made mechanical. ⚠️ It is a **derivation from settled rules, not a ruling** —
it needs the founder's yes.

**Defer layer 1 to v2.** §4.3 requires a member gesture for any *addition* of meaning, and no
such gesture exists. Shipping layer 1 without it would manufacture the gesture.

### Three ledger items this ruling also closes, by derivation

| Ref | Question | Derived answer |
|---|---|---|
| universal §6.2 | Default vocabulary when none is supplied? | **Layer 4.** Universal verbs. Vocabulary is **not** mandatory at field creation. |
| record §7 | Two naming layers — ruled or lean? | **Ruled by the chain** — layers 1 and 3 coexist and resolve in order. |
| universal §6.3 | May a practitioner **suppress** a layer? | ⛔ **No.** Suppressing a universal capability is **re-authorization**, not relabeling — the exact line §1 forbids. *A layer with no content does not render* (Phase 1) already handles the real case; that is emptiness, not suppression. |

## 3. Navigation model — how the Field becomes the environment

**This item had no artifact.** Framing it is most of the work.

The platform-root question is **already ratified**: the Member Field is the platform root.
So the open question is narrower than "what is the navigation model":

> **Is the Client Field a second root, or is it the Member Field seen through an active
> practitioner relationship?**

| | Reading | Consequence |
|---|---|---|
| A | **Sibling environment** — the client has a Client Field *and* a Member Field | ⛔ The member has **two homes**, and the practitioner relationship created the second one. A lens became the owner's name for the environment. **Fails the invariant.** |
| B | **The Member Field rendered under an active relationship** | ✅ The relationship adds a lens to the one environment. When it ends, the lens releases and the member keeps their home — identical to §4.1 applied to navigation instead of artifacts. |

### ⭐ Recommended: **B**

> **The Client Field is not a place the member goes. It is what their field looks like while
> a relationship is live.**

This makes navigation a **consequence** of the vocabulary chain rather than a separate
system: §2 layer 3 resolving is exactly what "the Client Field is active" means. ⛔ If B is
ruled, no separate client-side navigation model may be built — building one would recreate
the second root the ruling rejected.
