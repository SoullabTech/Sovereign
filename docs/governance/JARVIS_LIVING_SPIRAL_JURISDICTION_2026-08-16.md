# JARVIS Living Spiral — jurisdiction

**Founder ruling · 2026-08-16 · RATIFIED**
**Status:** binding. Inherited by **JOP-05A immediately**; **JOP-02 remains queued** behind the
observational fabric and does not open by virtue of this ruling.

> Ruled *before* the observational fabric is built, deliberately: cheap to establish now, expensive
> to untangle afterward. A naming boundary retrofitted after a data model exists is a migration.

---

## Disposition

| | |
|---|---|
| Surface | **RULED — JARVIS / operator only** |
| Placement inside MAIA | **REFUSED** |
| Individual-member inferred nodes | **REFUSED** |
| Shared Fire/Water/Earth/Air/Aether vocabulary | **REFUSED** |

## R1 — Operator domain only

The JARVIS Living Spiral is an **operator instrument** representing the organization and its
operational reality: programmes, work units, agents, systems, dependencies, governance, custody,
evidence, deployments, holds, failures, attention.

Primary surface: **JARVIS Desktop.** A read-only remote operator view may exist later under its own
disclosure and authentication rules. ⛔ **It does not live inside MAIA.**

## R2 — A member is never an inferred node

The Spiral **may** represent operational facts concerning member-facing systems:

```
MAIA voice service        DEGRADED
Studio onboarding         RUNNING
Member support queue      4 unresolved
Continuity service        VERIFIED
```

It **may not** turn those facts into claims about an individual:

```
⛔ Kelly is in Water
⛔ Sophie is withdrawing
⛔ Member 381 is stagnant
⛔ This member needs intervention
⛔ Silence indicates disengagement
```

⭐ **The boundary holds even when the inference is statistically plausible.**
*Operational observation is not authority to interpret a person's inner state.*

## R3 — Silence about a person is never system motion

This is where the negative-evidence work becomes load-bearing.

| | |
|---|---|
| `no system heartbeat` | **may** contribute to an operational warning |
| `no member activity` | **may not** become a psychological or Spiralogic interpretation |

The Operator may know *"No session has been observed in 30 days."*
It may **not** promote that into *"The member is withdrawing"* — unless the member explicitly
authored that meaning in a member-owned context.

## R4 — Separate the vocabularies

⛔ **Fire / Water / Earth / Air / Aether are NOT the canonical vocabulary of the JARVIS graph.**
An explanatory footnote saying *"these mean something different here"* is **too weak**. We already
know how easily identical names collapse distinct referents — this programme has produced several
instances of exactly that failure. Those terms stay inside MAIA/Spiralogic where they carry their
established member-facing meaning.

**JARVIS operational phenomenon names (initial vocabulary):**

| Term | Meaning |
|---|---|
| **TRANSFORMATION** | something is becoming / changing |
| **FLOW** | something is moving between organs |
| **STANDING** | something is being held / persisted / established |
| **DISCERNMENT** | something is differentiating / selecting / evaluating |
| **INTEGRATION** | multiple things are forming a larger whole |

These still produce a spiral. They simply do not claim an infrastructure event is *"Fire"* in the
same semantic system MAIA uses to speak with a member about Fire. Glyphs, motion patterns and palette
may develop independently. ⛔ **No elemental alias may be required to understand the graph.**

**Artifact name:** *JARVIS Living Spiral — operational field of the Soullab organism*, never bare
*"Living Spiral."*

## R5 — MAIA may eventually have a different spiral

A **Member Reflective Spiral** is a legitimate future object, and is **constitutionally separate**.
It would show only what the member has **authored · kept · declared · explicitly adopted · chosen to
relate together** — member-owned, reflective, non-diagnostic, non-surveillant. It would not consume
JARVIS's inferred attention state or silently import operator classifications.

⛔ **The JARVIS Living Spiral is not the backend model for a future MAIA member spiral.** They may
share visualization primitives someday. They do **not** inherit one another's semantics.

## What JOP-05A must carry from the start

Jurisdiction is a **field on the observation**, not a convention the visualization is trusted to
remember. This prevents the problem at the data-model layer.

```
observation
  subject_domain:
    operational_system | programme | work_unit | agent
    deployment | governance | aggregate_member_service
  source
  observed_at
  freshness
  disclosure_class
  evidence
  interpretation_scope: operator
```

**Hard refusal — not representable as an operator-spiral claim type:**

```
⛔ individual_member_inner_state
⛔ individual_member_element
⛔ inferred_member_intention
⛔ inferred_member_engagement_quality
```

⭐ Enforce structurally. *Asking the visualization to remember good manners is not a control.*

## The boundary

```
                   JARVIS — OPERATIONAL DOMAIN
    systems ─ programmes ─ agents ─ governance
                        ↓
                 EPISTEMIC FIELD
     evidence · provenance · freshness · uncertainty
              motion · attention
                        ↓
              JARVIS LIVING SPIRAL

──────────── constitutional boundary ────────────

                    MAIA — MEMBER DOMAIN
   authored experience · memory · reflection · relationship
              Spiralogic language
                        ↓
               MEMBER EXPERIENCE
```

The boundary makes both sides stronger: **JARVIS gets permission to be rigorous, operational,
diagnostic and attention-seeking about the organization. MAIA stays relational, inhabitable and
non-surveillant toward the person.**

## Consequence for existing artifacts

The JOP-02 concept artifact published 2026-08-16 used Fire/Water/Earth/Air/Aether as its element
axis. **That artifact is non-conforming under R4** and is superseded by this ruling. It is a concept
piece, not a build; conforming it removes a live confusion hazard rather than changing any shipped
behavior.
