## How to use this

For each article below, mark **one** bucket. After completing the pass, send the marked-up file back and Claude will:

1. delete the cut entries from the manifest allowlist + the component data
2. regenerate `lib/community-library/manifest.generated.ts`
3. (later) restructure the surviving articles into Foundations / Archetypal Maps / Practice sections

## Bucket key

| Mark | Layer | Standard |
|---|---|---|
| **F** | Foundations | Calibration-grade. Original thought. Withstands scrutiny. Feels authored. Defines the field. |
| **A** | Archetypal Maps | Referential (Jung, alchemy, traditions). Framed as map, not doctrine. Has ethical guardrails. |
| **P** | Practice | Applied. Tied to MAIA's actual architecture. NOT generic wellness. |
| **I** | Internal / Move | Keep, but not on the public shelf — moves to product docs, /about, or internal notes. |
| **X** | Cut | Filler, generic, no original insight, no clear authorship, or breaks field coherence. |

## Filter rules (use these to decide)

Cut if **any** of:

- No original insight
- No clear authorship (placeholder, "community-commons team" without a person)
- No connection to MAIA's actual architecture
- Reads like filler wisdom
- Could exist unchanged on a generic blog → it does not belong here
- Stub: under ~150 words and saying nothing distinctive
- Product documentation pretending to be a paper

## Calibration object

> _"Would encountering this immediately after `presence-continuity` strengthen or weaken the experience of that piece?"_

If it weakens — cut or move internal.
