# Design Review Guides

This collection is not canon. It does not define what is true — that is the
job of `docs/canon/` (the Oath, the Sovereignty Invariants, the constitutional
principles). This collection defines **how we discover whether we're living
up to those truths.**

A design review guide operationalizes an existing constitutional claim into a
repeatable test a reviewer can actually run against a real build. It doesn't
assert anything new about what MAIA is; it gives a reviewer a lens to check
whether a specific piece of software, as built, embodies what's already been
claimed.

Deliberately not filed under "UX" — UX has accumulated too much baggage
around engagement, optimization, and efficiency, which are not what these
guides are testing for. This is closer to design criticism: a set of lenses
for evaluating whether an interface embodies its own values. That also makes
these guides useful beyond MAIA — any future platform built on AIN OS can be
reviewed through the same lenses.

## Format

Each guide is small — 2–5 pages, not 30 — and shaped like a repeatable
protocol: a stated purpose, a test a reviewer actually performs (usually
"walk the experience and record what happens"), and a small set of
questions. The compliment a guide is built to elicit is never "beautiful
interface" — it's some form of "I forgot there was an interface."
