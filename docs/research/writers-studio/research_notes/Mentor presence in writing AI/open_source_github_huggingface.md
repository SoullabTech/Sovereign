# Open-source projects, datasets, models and code for a mentor-style AI writing companion (GitHub / Hugging Face / arXiv)

Method note: repository metadata (licence SPDX id, last push date, stars, archived flag) was read live from the GitHub REST API via `gh api` on 2026-11-09; Hugging Face metadata from the public Hub API the same day. "Pushed" = last push to any branch, which shows only that the repo is maintained; it is not a release date. Where a licence field reads "none", GitHub found no licence file: by default that means **all rights reserved** until the authors say otherwise. Items not confirmed by a live check are marked UNVERIFIED.

## Q1. Open-source writing editors/UIs with anchored or inline AI feedback; React/Next.js compatibility

### Takeaway
Only one of the research systems that matter most, **AnchoredAI** (span-anchored AI comments), has published code: none was linked from its arXiv page or HTML full text, and the same is true of **Writor** (non-directive, writing-centre feedback) and the proactive thought-partner probe. What can be reused is (a) the editor substrates (Tiptap/ProseMirror, Lexical, Plate, BlockNote, Yjs), most MIT-licensed and React-native, and (b) a few research prototypes (Wordcraft, CoAuthor, InkSync, ABScribe, Textfocals). Every one of those prototypes is wired to OpenAI or Gemini by default, so each would need its model backend replaced. For anchoring that survives edits, the W3C Web Annotation tooling (Hypothesis, Recogito) is the mature prior art.

### Cited Findings
**Research systems (anchored, feedback-first)**
- **AnchoredAI** (Lou, Crowley, Dodson, Yoon; arXiv 2509.16128, 19 Sep 2025). It anchors AI feedback to text spans through an "Anchoring Context Window" (unique, context-rich references) and "update-aware context retrieval that preserves the intent of prior comments after document edits". Compared with a chat interface, it led to more targeted revisions and stronger writer agency and ownership. **No code link was found** in the abstract page or the HTML full text — [arXiv](https://arxiv.org/abs/2509.16128). Fit: the closest published design to "feedback anchored to passages". Reimplement it from the paper.
- **Writor** (Liu, Gallagher, Sterman, August; arXiv 2602.04047, 3 Feb 2026). Its design guidelines come from writing-centre pedagogy and interviews with 10 writing tutors. The prototype helps writers revise by "setting goals, providing balanced feedback, and engaging in conversations without generating text". **No code link was found** — [arXiv](https://arxiv.org/abs/2602.04047). Fit: very high on philosophy (no prose generation, voice preservation). The guidelines can be reused; no code is available.
- **InkSync** (Salesforce; UIST 2024 "executable and verifiable text editing"): [github.com/SalesforceAIResearch/inksync](https://github.com/SalesforceAIResearch/inksync). Licence Apache-2.0; pushed 2026-06-02; 6 stars. Python/Flask app (`app_inksync.py`, `templates/`, `static/`), with `utils_openai.py`. The README requires `OPENAI_API_KEY`. Fit: a useful pattern for showing edits as verifiable, accept/reject-able diffs. Python plus server-rendered templates, so it is not React. ⚠️ Uses OpenAI (see Q5).
- **Wordcraft** (Google PAIR): [github.com/PAIR-code/wordcraft](https://github.com/PAIR-code/wordcraft). Apache-2.0; pushed 2026-06-23; 355 stars; README says it is "powered by generative models such as Gemini". Fit: story-writing editor focused on generation, which goes against the no-unasked-prose constraint. Its controls/operations architecture is worth reading; the code itself is not a fit. Not React, per its README.
- **CoAuthor interface** (Lee, Liang, Yang; CHI 2022): [github.com/minalee-research/coauthor-interface](https://github.com/minalee-research/coauthor-interface). MIT; pushed 2024-05-24; 102 stars. The README says the backend supports OpenAI by default ("To use other models, you will need to modify the backend"). The dataset and session replay are at coauthor.stanford.edu. Fit: keystroke-level session logging and replay is valuable for studying writer behaviour. The suggestion UI is generation-centred. ⚠️ OpenAI by default.
- **ABScribe** (Reza et al.): [github.com/mohireza/abscribe](https://github.com/mohireza/abscribe). MIT; pushed 2024-06-02; 21 stars; "exploring and organizing multiple writing variations with LLMs". Fit: low, because it generates variations. Its pattern of keeping several versions side by side without overwriting could inform a "your versions" history.
- **Textfocals**: [github.com/Cabroek/Textfocals](https://github.com/Cabroek/Textfocals). GPL-3.0; pushed 2024-07-12; 0 stars; no description. UNVERIFIED as the official artefact of the Textfocals paper (it is identified by name only). GPL-3.0 is copyleft, which matters before any code is merged.
- **PaperWeaver**: the GitHub repos returned under that name (e.g. Mon-Ben/Paperweaver, yindaheng98/PaperWeaver) are unrelated 2026 personal projects. **No official PaperWeaver code was found** — [GitHub search](https://github.com/search?q=PaperWeaver&type=repositories).

**Editor substrates (React/Next.js)**
- **Tiptap** (ProseMirror-based, headless, React bindings): [github.com/ueberdosis/tiptap](https://github.com/ueberdosis/tiptap). Core is MIT; pushed 2026-11-08; 39,000 stars. **Comments and AI extensions are Pro and paid**: they are published in Tiptap's private npm registry and the licence lasts only while the subscription does. The AI Suggestion extension is "being phased out in favor of the AI Toolkit" — [Tiptap Pro licence](https://tiptap.dev/docs/pro-license); [Tiptap pricing](https://tiptap.dev/pricing); [AI Suggestion docs](https://tiptap.dev/docs/ai/deprecated/suggestion/install). Fit: best ecosystem. Build comments and anchoring in-house on the MIT core rather than depend on the Pro cloud, which would add a vendor in the data path.
- **Lexical** (Meta): [github.com/facebook/lexical](https://github.com/facebook/lexical) (now `meta/lexical`). MIT; pushed 2026-11-09; 24,004 stars. React-first. Fit: strong, permissive choice. UNVERIFIED in this pass: the commenting plugin in its playground (not opened).
- **Plate**: [github.com/udecode/plate](https://github.com/udecode/plate). Repo LICENSE is MIT; pushed 2026-11-08; 16,693 stars; described as "Rich-text editor with AI and shadcn/ui". Fit: shadcn/Next.js-native and ships AI, comment and suggestion plugins. UNVERIFIED: the licence of each individual AI/comment package. The GitHub API returned "NOASSERTION" for the repo, although the LICENSE file is MIT.
- **BlockNote** (Notion-style on ProseMirror/Tiptap): [github.com/TypeCellOS/BlockNote](https://github.com/TypeCellOS/BlockNote). `packages/core` is **MPL-2.0**; `packages/xl-ai` is **"GPL-3.0 OR PROPRIETARY"** (read from package.json); pushed 2026-11-09; 10,366 stars. Fit: good React editor. Its AI package is copyleft or commercial-only.
- **Novel**: [github.com/steven-tey/novel](https://github.com/steven-tey/novel). Apache-2.0; last push 2025-01-18 (no activity for about 22 months); 16,464 stars; "Notion-style WYSIWYG editor with AI-powered autocompletion". Fit: low. It is built around autocompletion (prose generation) and appears dormant.
- **Yjs** (CRDT; relative positions keep anchors stable through concurrent edits): [github.com/yjs/yjs](https://github.com/yjs/yjs). Licence file recorded as NOASSERTION by the API (widely described as MIT, but UNVERIFIED here); pushed 2026-11-05; 23,038 stars. Fit: a standard way to keep comment anchors stable through edits, even with a single user.

**Anchoring/annotation prior art**
- **Hypothesis `h`** (W3C Web Annotation server): [github.com/hypothesis/h](https://github.com/hypothesis/h). BSD-2-Clause; pushed 2026-11-06; 3,189 stars. Its text-quote and position selectors are the standard approach to re-anchoring after edits. The small library [hypothesis/dom-anchor-text-quote](https://github.com/hypothesis/dom-anchor-text-quote) is MIT but **archived** (last push 2022-06-02).
- **Recogito text-annotator-js**: [github.com/recogito/text-annotator-js](https://github.com/recogito/text-annotator-js). BSD-3-Clause; pushed 2026-10-12; 106 stars. JavaScript library for span annotation. Fit: a candidate layer for margin comments over rendered text.
- **factgenie** (self-hosted span annotation): [github.com/ufal/factgenie](https://github.com/ufal/factgenie). MIT; pushed 2026-09-18; 45 stars. Fit: an internal tool for annotating MAIA's feedback spans during evaluation.

### Inferences
- The highest-value design (AnchoredAI's ACW plus update-aware retrieval) has to be **reimplemented from the paper**. A practical stack: Tiptap MIT core or Lexical/Plate for the editor; anchors built on Web-Annotation-style TextQuote + TextPosition selectors (the Hypothesis approach) or Yjs relative positions; comments stored in self-hosted Postgres.
- Avoid the Tiptap Pro comments/AI and BlockNote `xl-ai` packages unless the licensing (subscription, GPL/proprietary) and any cloud dependency have been accepted deliberately.
- Every research prototype found defaults to OpenAI or Gemini. Treat them as reference designs, not as drop-in code.

### Gaps
- No public code was found for AnchoredAI, Writor, PaperWeaver, or the proactive thought-partner probe. Contacting the authors may be the only route.
- The ABScribe and Textfocals repos were not opened past metadata; their framework (React or otherwise) is unconfirmed.
- Licences of individual Plate packages and of Yjs were not confirmed file by file.

## Q2. Datasets of editorial/writing feedback, revision intent, Socratic questioning, and creative-writing evaluation

### Takeaway
The most directly relevant new resource is **FOXGLOVE** (2026): span-anchored instructor feedback compared with LLM feedback on essays. Its licence is **CC BY-NC-SA 4.0**, so it can be used for research and evaluation but not commercially. Revision-intent corpora (IteraTeR, ArgRewrite) are permissively licensed and useful for teaching the system *what kind* of revision a passage needs without producing the rewrite. Socratic corpora (SoQG, SocraTeach, MathDial) cover questioning, but not literary or developmental editing. Several popular creative-writing critique sets on Hugging Face carry no licence tag.

### Cited Findings
- **FOXGLOVE** (arXiv 2606.06271, 4 Jun 2026): 696 comments by trained writing instructors on 69 twelfth-grade argumentative essays, plus 1,644 comments from four frontier LLMs; 2,340 comments in total, all anchored to sentences. Studied dimensions: goal-orientation, anchoring, prioritization — [arXiv](https://arxiv.org/abs/2606.06271). The earlier search summary reported that instructors rated LLM feedback higher on most dimensions, and that much of the advantage appears attributable to longer comments — [arXiv PDF](https://arxiv.org/pdf/2606.06271.pdf). Data: [github.com/yijunliu23/foxglove_data_release](https://github.com/yijunliu23/foxglove_data_release), pushed 2026-06-03, **CC BY-NC-SA 4.0** per README. Fit: very high as an evaluation set for anchored, prioritized, goal-oriented feedback. The length confound is a lesson for any judge model.
- **IteraTeR** (revision-intent taxonomy: fluency, coherence, clarity, style, meaning-changed): code at [github.com/vipulraheja/IteraTeR](https://github.com/vipulraheja/IteraTeR), Apache-2.0, last push 2023-11-15. HF datasets `wanyu/IteraTeR_full_sent`, `_human_sent`, `_human_doc`, `_full_doc`, `_v2`, all tagged apache-2.0 — e.g. [wanyu/IteraTeR_human_doc](https://huggingface.co/datasets/wanyu/IteraTeR_human_doc). Fit: good for classifying the kind of revision a passage invites. Its sources are Wikipedia, news and arXiv, so it has no fiction or memoir.
- **ArgRewrite V2** (annotated argumentative revisions corpus): [github.com/omidkashefi/ArgRewrite](https://github.com/omidkashefi/ArgRewrite), CC-BY-4.0, last push 2022-01-14. Fit: student essay drafts with revision purposes. Small and old, but permissive.
- **CoEdIT**: the dataset [grammarly/coedit](https://huggingface.co/datasets/grammarly/coedit) is Apache-2.0 (2,122 downloads, 101 likes). The model `grammarly/coedit-large` is **CC-BY-NC-4.0**. The code repo [vipulraheja/coedit](https://github.com/vipulraheja/coedit) has **no licence file**. Fit: low. It is an instruction-tuned *rewriting* system, the opposite of feedback-not-rewrite. Useful only as a negative example or for detecting surface issues.
- **CoAuthor dataset** (1,445 GPT-3 co-writing sessions at keystroke level): distributed via coauthor.stanford.edu, per the [interface README](https://github.com/minalee-research/coauthor-interface). Licence not verified here (UNVERIFIED).
- **SoQG / SocratiQ** (EACL 2023): about 110K Socratic questions with type labels and contexts, drawn from r/changemyview. Data at [github.com/NUS-IDS/eacl23_soqg](https://github.com/NUS-IDS/eacl23_soqg) (no licence file; pushed 2026-03-04) — [ACL Anthology](https://aclanthology.org/2023.eacl-main.12). Fit: a question-type taxonomy (clarification, probing assumptions, implications, and so on) that transfers to developmental-editing questions. Reddit-derived and unlicensed, so treat it as reference only.
- **Socratic question generation with DPO** (BEA 2024): [github.com/umass-ml4ed/socratic-quest-gen](https://github.com/umass-ml4ed/socratic-quest-gen), no licence, last push 2024-05-07 — [ACL BEA 2024](https://aclanthology.org/2024.bea-1.10.pdf). Domain: programming debugging.
- **SocraTeach / SocraticLM** (NeurIPS 2024 spotlight): [github.com/Ljyustc/SocraticLM](https://github.com/Ljyustc/SocraticLM). README badges: code Apache-2.0, **data CC BY-NC 4.0, weight diff CC BY-NC 4.0**. Domain: math teaching.
- **MathDial** (teacher–student tutoring dialogues with pedagogical properties): [eth-nlped/mathdial](https://huggingface.co/datasets/eth-nlped/mathdial), CC-BY-4.0, modified 2025-02-26. The code repo [eth-nlped/mathdial](https://github.com/eth-nlped/mathdial) has no licence file. Fit: a model for not revealing the answer and scaffolding instead. Math domain.
- **SocraticChat** (50,728 samples from a `Socratic` user simulator talking with GPT-3.5-turbo): [FreedomIntelligence/SocraticChat](https://huggingface.co/datasets/FreedomIntelligence/SocraticChat), Apache-2.0. ⚠️ OpenAI-generated content. The Socratic role here is the *user* simulator, not a tutor, so fit is low.
- **LitBench** (creative-writing preference/verification benchmark built from Reddit story comparisons; paper arXiv 2507.00769): [SAA-Lab/LitBench-Train](https://huggingface.co/datasets/SAA-Lab/LitBench-Train) and `-Test`/`-Test-Release`, **no licence tag**. The card asks comment authors to request removal. Fit: evaluating literary-quality judgement. Licence unclear, and its framing as a quality judgement sits uneasily with the no-grading constraint (see Q5).
- **WildChat creative-writing critique sets** (e.g. [kevinshin/wildchat-creative-writing-3k-critique-v2](https://huggingface.co/datasets/kevinshin/wildchat-creative-writing-3k-critique-v2), 854 downloads) and [sam-paech/wildchat_creative_writing_annotated_10k](https://huggingface.co/datasets/sam-paech/wildchat_creative_writing_annotated_10k): **no licence tags**. They derive from WildChat (ChatGPT logs). Fit: reference only.
- **Peer review**: [allenai/PeerRead](https://github.com/allenai/PeerRead) (no licence file; HF `allenai/peer_read` licence "unknown"). Several 2025–26 OpenReview ICLR review scrapes exist on HF (e.g. `smallari/openreview-iclr2024-peer-reviews-RAW`) without licence tags. Fit: academic reviewing. A different genre from developmental editing.
- **IELTS writing feedback** sets (e.g. `Jackrong/IELTS-writing-feedback-reasoning`, Apache-2.0) — [HF](https://huggingface.co/datasets/Jackrong/IELTS-writing-feedback-reasoning). Fit: low. They are score-oriented, which is exactly the grading the constraint excludes.
- **Prometheus Feedback Collection** (rubric-based feedback plus score data for training judges): [prometheus-eval/Feedback-Collection](https://huggingface.co/datasets/prometheus-eval/Feedback-Collection), CC-BY-4.0. Fit: a template for rubric-driven *evaluation of MAIA's own comments*.

### Inferences
- No public dataset found matches the target: developmental-editor feedback on long-form creative or nonfiction manuscripts, anchored to passages, in question form. FOXGLOVE is the nearest, but it covers school argumentative essays and is NC-licensed. The team will probably need to author its own small gold set (for example, founder- or editor-written anchored comments on consenting writers' text) and use FOXGLOVE and SoQG as structural templates.
- Revision-intent taxonomies (IteraTeR) and Socratic question types (SoQG) can be reused as *label vocabularies* for MAIA's observations without reusing any text.

### Gaps
- None of these turned up: ASAP-feedback, an "F2 fine-grained feedback" dataset, or an open r/WritingPrompts *critique* corpus with a clear licence. The search was limited and they may exist under other names.
- The CoAuthor and LitBench licence terms were not confirmed.
- No writing-domain (as opposed to math or code) Socratic tutoring dialogue dataset was found.

## Q3. Models and evaluation frameworks: feedback-not-rewrite, Socratic tutoring, sycophancy, voice preservation, homogenization

### Takeaway
There is usable evaluation infrastructure. Tutor-quality taxonomies (MRBench: "revealing of the answer", "providing guidance", actionability) map closely onto "feedback, not rewrite". Sycophancy evals exist from Anthropic and from Sharma/Tong et al. Open authorship-style embeddings (LUAR, StyleDistance) can measure whether a writer's voice drifts. The Padmakumar & He homogenization study publishes materials, but they amount to a similarity script, not a packaged library. Open judge models (Prometheus 2) can run locally under Ollama-class hosting.

### Cited Findings
- **MRBench / Unifying AI Tutor Evaluation** (Maurya et al., NAACL 2025): eight pedagogical dimensions, including mistake location, revealing of the answer, providing guidance, actionability, coherence, tutor tone, human-likeness. 192 conversations and 1,596 responses from seven LLM and human tutors, built on MathDial and Bridge. The paper also assesses Prometheus2 as an evaluator. Code at github.com/kaushal0494/UnifyingAITutorEvaluation (linked from the paper; **not opened in this pass, licence UNVERIFIED**) — [arXiv](https://arxiv.org/abs/2412.09416). Fit: high as a rubric template. A "does not reveal the answer" check becomes "does not write the prose".
- **Prometheus 2** judge models: [prometheus-eval/prometheus-7b-v2.0](https://huggingface.co/prometheus-eval/prometheus-7b-v2.0) and `-8x7b-v2.0`, both Apache-2.0. Code: [github.com/prometheus-eval/prometheus-eval](https://github.com/prometheus-eval/prometheus-eval), Apache-2.0, pushed 2025-04-25, 1,121 stars. The repo description mentions GPT-4 as an alternative judge. Fit: local, open-weights rubric judging of MAIA's comments, consistent with the local-only constraint.
- **Sycophancy**: [meg-tong/sycophancy-eval](https://github.com/meg-tong/sycophancy-eval), datasets from "Towards Understanding Sycophancy in Language Models". The repo has no licence file; the HF copy [meg-tong/sycophancy-eval](https://huggingface.co/datasets/meg-tong/sycophancy-eval) is tagged MIT; last push 2023-10-25. [anthropics/evals](https://github.com/anthropics/evals) is CC-BY-4.0, last push 2024-07-02; the HF mirror [Anthropic/model-written-evals](https://huggingface.co/datasets/Anthropic/model-written-evals) is CC-BY-4.0 and includes sycophancy subsets. Fit: adapt the feedback-sycophancy pattern from Sharma et al. (praise shifts when a user says "I wrote this / I love this") to manuscript feedback.
- **Homogenization**: Padmakumar & He, "Does Writing with Language Models Reduce Content Diversity?" (ICLR 2024). Writing with InstructGPT, but not base GPT-3, significantly reduced diversity — [arXiv](https://arxiv.org/abs/2309.05196). Materials at [github.com/vishakhpk/hai-diversity](https://github.com/vishakhpk/hai-diversity): **no licence file**, last push 2023-08-31, contents `logs/`, `processed_data/`, `similarity/`, `summarize_essays.py`. Fit: a reference implementation of between-author similarity metrics that can be reimplemented to watch for MAIA flattening writers' voices. Unlicensed, so do not copy the code.
- **Voice/style consistency metrics**: LUAR authorship embeddings, code [github.com/llnl/LUAR](https://github.com/llnl/LUAR) (Apache-2.0, pushed 2024-08-12) and model [rrivera1849/LUAR-MUD](https://huggingface.co/rrivera1849/LUAR-MUD) (Apache-2.0, 65k downloads, modified 2026-05-07). [StyleDistance/styledistance](https://huggingface.co/StyleDistance/styledistance) (MIT, 24k downloads). [AnnaWegmann/Style-Embedding](https://huggingface.co/AnnaWegmann/Style-Embedding) (no licence tag). Fit: compute the style distance between a writer's pre- and post-session drafts to detect voice drift. Small models that run locally.
- **Creative-writing benchmarks**: [EQ-bench/creative-writing-bench](https://github.com/EQ-bench/creative-writing-bench) has **no licence file**, pushed 2026-06-24. Its README recommends Claude Sonnet 4.6 as judge for leaderboard parity and uses OpenAI/OpenRouter-format endpoints. [EQ-bench/EQ-Bench](https://github.com/EQ-bench/EQ-Bench) is MIT, last push 2024-07-26. [X-PLUG/WritingBench](https://github.com/X-PLUG/WritingBench) is Apache-2.0, pushed 2025-12-19, "Benchmark for Generative Writing". Fit: they measure an LLM's *generation* quality, which is not MAIA's job. At most, their judge-bias mitigations (length, position, verbosity) are reusable.
- **SocraticLM** (a fine-tuned Socratic math teacher; weight diff CC BY-NC 4.0) — [GitHub](https://github.com/Ljyustc/SocraticLM). Fit: an approach reference, not a deployable model.
- **LearnLM**: the HF model id `google/learnlm-1.5-pro-experimental` returned HTTP 401. No open weights were found, so it cannot be self-hosted. (Inference from the failed lookup, UNVERIFIED beyond that.)

### Inferences
- A plausible evaluation harness: an MRBench-style rubric adapted to writing ("did MAIA write prose?", "is it anchored?", "is it a question or an observation?", "does it impose an external standard?"). Score it with a local Prometheus 2 or Claude as judge, add a sycophancy probe, and add a LUAR/StyleDistance voice-drift metric over session drafts.
- FOXGLOVE's finding about the length confound means any judge needs length control.

### Gaps
- No open benchmark was found that specifically tests "the model withholds rewriting" in creative-writing feedback.
- The MRBench repo licence and contents were not checked.

## Q4. Open-source proactive/ambient agent timing code

### Takeaway
The key 2026 paper, Zhang et al.'s "Designing Proactive Thought Partners for Writing", has **no code link**. Its finding that intrusiveness depended more on *presentation* (a lightweight cue, non-directive phrasing) than on timing alone is directly usable. The only active open-source proactive-agent codebase found, THUNLP's ProactiveAgent, is generic rather than writing-specific.

### Cited Findings
- **Designing Proactive Thought Partners for Writing** (Chao Zhang, Abe Davis, Chih-Wei Chen, Chin-Chia Hsu; arXiv 2609.01588, 1 Sep 2026): a technology probe with 16 participants over one week. Users configured partners' roles and proactivity, and the partners act as users write. **No GitHub link was found in the arXiv HTML** — [arXiv](https://arxiv.org/abs/2609.01588). The search summary reported that intrusiveness depended more on presentation (lightweight visual cue, non-directive phrasing) than on timing, and that users configured support prospectively — [arXiv PDF](https://arxiv.org/pdf/2609.01588).
- **Towards Cognitive Process-Aware Proactive Writing Support** (Yoshida, Kobayashi, Tateno, Chen; arXiv 2608.30424, 31 Aug 2026): maps the Flower & Hayes cognitive processes to support types. Timing is inactivity-based plus user-initiated. No code link found — [arXiv](https://arxiv.org/abs/2608.30424).
- **Users Mispredict Their Own Preferences for AI Writing Assistance** (arXiv 2601.04461): per the search summary, it cites prior work that proactive help timed to natural breakpoints lowers interruption costs, and notes that email assistants rarely report validated timing policies — [arXiv PDF](https://arxiv.org/pdf/2601.04461). Not opened directly.
- **ProactiveAgent** (THUNLP): [github.com/thunlp/ProactiveAgent](https://github.com/thunlp/ProactiveAgent). Apache-2.0; pushed 2026-05-12; 690 stars; "A LLM-based Agent that predict its tasks proactively". Fit: medium. It offers a reward-model and event-stream pattern for deciding *whether* to offer help, and is not writing-specific.

### Inferences
- The timing logic will most likely be built in-house: inactivity and natural-breakpoint heuristics (paragraph end, pause), with offers presented as quiet, non-directive margin cues the writer can ignore. This matches both Zhang et al. and the "presence without intrusion" goal.

### Gaps
- No released code for any writing-specific proactive-timing system was found.

## Q5. Conflicts with project constraints (Anthropic Claude or local Ollama only, no OpenAI, self-hosted, no Supabase, no unasked prose, no grading)

### Takeaway
Most research prototypes conflict with the constraints, in two ways: they default to OpenAI or Gemini, and several are generation-centred. Several datasets are non-commercial or unlicensed, and several benchmarks are built around scoring writers. Permissive editor substrates and local judge or style models are the clean parts.

### Cited Findings
- **OpenAI by default**: InkSync README requires `OPENAI_API_KEY` ([repo](https://github.com/SalesforceAIResearch/inksync)). The CoAuthor interface defaults to the OpenAI API ([repo](https://github.com/minalee-research/coauthor-interface)). Creative-writing-bench uses OpenAI/OpenRouter-format endpoints, though it recommends a Claude judge ([repo](https://github.com/EQ-bench/creative-writing-bench)). SocraticChat data was generated with GPT-3.5-turbo ([HF](https://huggingface.co/datasets/FreedomIntelligence/SocraticChat)).
- **Gemini by default**: Wordcraft ([repo](https://github.com/PAIR-code/wordcraft)).
- **Prose generation is the core feature** of Wordcraft, CoAuthor, ABScribe, Novel ("AI-powered autocompletion") and CoEdIT (a rewriting model), per the repos cited above.
- **Paid, cloud or copyleft editor pieces**: Tiptap Pro comments/AI require a subscription via a private registry ([Pro licence](https://tiptap.dev/docs/pro-license)). BlockNote `xl-ai` is GPL-3.0 OR PROPRIETARY ([repo](https://github.com/TypeCellOS/BlockNote)). Textfocals is GPL-3.0 ([repo](https://github.com/Cabroek/Textfocals)).
- **Licence restrictions on data/models**: FOXGLOVE CC BY-NC-SA 4.0; SocraTeach data and SocraticLM weights CC BY-NC 4.0; `grammarly/coedit-large` CC-BY-NC-4.0. No licence at all: SoQG, hai-diversity, sycophancy-eval (GitHub copy), creative-writing-bench, LitBench (HF), the WildChat critique sets — sources as cited in Q2 and Q3.
- **Grading orientation**: IELTS feedback sets are score-oriented. LitBench, WritingBench and the EQ-Bench creative-writing bench rate writing quality. If used, they should evaluate *MAIA's outputs* or train calibration, and never score the writer.
