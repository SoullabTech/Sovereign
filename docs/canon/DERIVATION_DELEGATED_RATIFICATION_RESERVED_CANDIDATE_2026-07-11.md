# DERIVATION DELEGATED, RATIFICATION RESERVED — Solo-Founder Governance Mode

**Status**: CANDIDATE — proposed 2026-07-11, awaiting Kelly's ratification. Describes a practice already demonstrated; ratification converts demonstrated practice into declared constitution.

## The constraint this answers honestly

The author≠approver discipline assumes two humans; this project has one. Kelly Nezat is the entire build function and the entire ratification function, with Nathan ramping toward member/client support. Branch protection and covenant gates cannot manufacture a second approver who doesn't exist — and pretending otherwise (author-self-approval deadlocks, rubber-stamp rituals) is worse than naming the real structure.

## The invariant

> **Derivation may be delegated to bounded agent sessions; ratification never leaves the founder.**

- **Derivation** — reading, tracing, inventorying, reconciling, drafting, proposing: delegable to agent sessions that are (a) bounded in scope, (b) evidence-producing (findings bind to a stated ref; every claim carries its file reference), and (c) read-only by default, with write acts limited to what a standing direction has already authorized (e.g., "found by census, closed pre-ratification" fixes executed under an explicit founder disposition).
- **Ratification** — the act that converts a derivation into standing (canon status, claim stamps, freeze lifts, gate openings, outward copy): reserved to Kelly, never delegable, never inferred from silence.

## Why this is constitution, not process trivia

The week of 2026-07-07 demonstrated the mode at full scale: a grounding census, a docs reconciliation, and a constitutional trace — all derived by bounded agent sessions, all committed as evidence *awaiting* ratification, with pre-ratification closures executed only under explicit founder dispositions and recorded as such. The apparatus converts a bus-factor liability into a documented practice:

1. **Evidence outlives sessions.** Derivations are committed documents bound to refs, not conversation state.
2. **The founder's bandwidth is the declared rate limiter.** Ratification is protected above building — building can pause and resume; an unratified evidence base decays as the tree moves.
3. **The Steward model** (Cat 1, held) is the eventual distribution path for ratification load; until it matures, this invariant is the honest description of how authority works here.

## What this does NOT authorize

- Agent sessions ratifying anything, including "obvious" statuses.
- Treating a founder's forwarded analysis as ratification of its every clause — dispositions must be named to be executed.
- Describing the project outwardly as having governance structures (review boards, dual approval) that this document exists to honestly replace.
