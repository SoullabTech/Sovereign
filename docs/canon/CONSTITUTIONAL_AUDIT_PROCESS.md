# Constitutional Audit Process

## Canon Reference Document

### Soullab / Spiralogic / MAIA

> **Status:** Canonical procedural doctrine.
> This document defines the constitutional audit instrument used to verify that other canon, architecture, and operational documents remain faithful to the system's governing constraints at every altitude. It is the audit instrument applied to its own definition.

---

# 1. Purpose

A constitutional audit is not a normal proofreading pass.

It is a structured review asking:

> Does the document remain faithful to the architecture's governing constraints at every altitude?

Not just *"is this true?"* — but:

> Is this claim being made at the correct level, with the correct evidence, without drifting into inflation, mythology, or substrate confusion?

The audit protects against:

> coherent reflection becoming self-sealing mythology

by keeping doctrine, architecture, implementation, runtime, and aspiration properly separated.

In MAIA's case specifically, the audit protects **mirror fidelity** by ensuring the architecture never claims more awareness, participation, sovereignty, differentiation, or developmental efficacy than it can actually support.

---

# 2. The Five Correction Classes

| # | Class | What it catches |
|---|-------|-----------------|
| A | **Altitude conflation** | mixing doctrinal, operational, runtime, or developmental layers |
| B | **Category inflation** | presenting Cat 1-3 substrate as Cat 6 runtime reality |
| C | **Metaphor outrunning measurement** | symbolic language implying unverified operational claims |
| D | **1:1 collapse** | collapsing fields/modes/engines into rigid mappings |
| E | **Silent convergence** | plurality claimed while dimensionality actually collapses |

**Potential sixth class (held operationally, not yet formalized):**

| F | **Measurement mythology** | trusting the telemetry apparatus itself without verification |

Formalization of (F) is conditional on independent recurrence under audit pressure. Hold operationally until that condition is met.

# 3. Cat 1–6 Classification

| Category | Meaning |
|----------|---------|
| **Cat 1** | orientation / aspiration |
| **Cat 2** | canonical primitive exists |
| **Cat 3** | built substrate, weak participation |
| **Cat 4** | reachable but dormant |
| **Cat 5** | partially observable runtime |
| **Cat 6** | verified live runtime participation |

Example progression:
- *"VoiceDistinctionScorer exists"* → Cat 2-3
- *"The system verifies differentiated cognition"* → inflation unless trace-wired telemetry exists (Cat 6 requires runtime evidence)

# 5. The Six-Step Audit Process

## Step 1 — Read the document once normally

Goal: understand the intended meaning. Do not start correcting immediately.

Identify:
- the document's altitude
- purpose
- audience
- dominant claim type

This determines the acceptable language range.

## Step 2 — Identify major claims

Highlight or extract sentences that make substantive claims. Focus on:

> claims with ontological or operational weight

Ignore stylistic prose, transitions, framing language.

## Step 3 — Classify each claim

For every major claim, fill:

| Field | Question |
|-------|----------|
| **Altitude** | What level is this claim operating at? |
| **Category** | Cat 1–6? |
| **Evidence** | What supports it? |
| **Risk** | Which correction class applies? |
| **Action** | Keep / qualify / downgrade / rewrite |

## Step 4 — Run the five correction checks

For each claim ask:

- **A. Altitude conflation?** Is a future-state or doctrinal claim being read like runtime reality?
- **B. Category inflation?** Are we presenting aspiration or substrate as verified participation?
- **C. Metaphor outrunning measurement?** Does symbolic language imply runtime proof we do not have?
- **D. 1:1 collapse?** Did we collapse dynamic fields into rigid mappings? *(element = engine, field = lane, cognition = personality)*
- **E. Silent convergence?** Are we assuming dimensionality survived integration without evidence?

## Step 5 — Produce delta list

Output format:

```text
Claim:        [the claim text]
Altitude:     [canon/architecture/operational/runtime/future-state]
Category:     [Cat 1–6]
Evidence:     [what supports it]
Risk:         [correction class A–E]
Action:       [keep / qualify / downgrade / rewrite]
Adjustment:   [proposed revision if needed]
```

For full-coverage visible audits, include clean items (Action: keep) so audit completeness is inspectable. This prevents the audit from looking like selective criticism rather than systematic verification.

## Step 6 — Stop when stable

The audit is **not** infinite recursive refinement.

Stopping condition:

> all major claims operating at correct altitude
> + claims match evidence level
> + drift modes bounded
> + no major inflation remains
> → ship the document
