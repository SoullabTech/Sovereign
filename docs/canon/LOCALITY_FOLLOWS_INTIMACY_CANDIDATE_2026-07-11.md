# LOCALITY FOLLOWS INTIMACY, NOT TIER — Doctrine Candidate

**Status**: CANDIDATE — awaiting Kelly's ratification. Derived from ratified practice, not invented: the code already enforces every instance cited below. Ratification is recognition, not legislation.
**Sitting order**: rule this AFTER the census ratification pass, so this text cites census stamps as evidence rather than assertion (evidence-before-doctrine).
**Coupled ratification**: ADR-013 (Context Assembly). §3's composition rule names context assembly as its enforcement point; this doctrine and ADR-013 should ratify together or the dependency be explicitly carried — neither should ratify half-grounded.

## 1. The rule

> **Locality follows intimacy, not tier.**

Sovereignty, as this constitution has always ratified it, lives in data locality, substitutability, and provenance honesty — never in compute locality. Honestly-labeled cloud frontier inference is therefore acceptable indefinitely for any processing *tier*. Hard locality obligations attach instead to **intimacy classes** of data — and migrate over time to the member edge (member-sovereign horizon), which is the only place "your most intimate material never leaves hardware you control" was ever going to be fully kept. A founder rack never satisfied that promise either.

## 2. The intimacy-class registry (what makes the rule structural, not instructional)

"Intimate" must be a property the code can test — exactly as `sacred_protected` already is. The registry couples each class to its schema marker and enforcement point. **Three rows today; the table grows only by ratification.**

| Class | Marker (schema/request) | Enforcement points (census/trace-witnessed) | Locality obligation |
|---|---|---|---|
| **Sanctuary session** | per-request `sanctuary` flag (interim); server-side mode row = specced structural fix | orchestrator spine skips memory read/writeback; TTS route refuses cloud voice; oracle keep sidecar skips entirely (`af35fbf5f`) | Nothing persists anywhere; no cloud voice; cloud inference transits only with the flag honored end-to-end — the structural fix closes the gap between "honored" and "guaranteed" |
| **Raw audio** | `member_settings.storage_consent.audioServer` (default-deny) | journal audio routes: 402 unpaid, 403 unconsented | Raw audio persists only on owned hardware, only with standing consent; never to third-party storage |
| **Sacred register** | `member_memory_atoms.primary_register` / `registers[]` = `sacred_protected` | affinity indexer skips; Living Field computation excludes; atom loaders exclude | Never enters prompts, indexes, derived views, or any cloud-bound assembly |

Adjacent consent axes (`return_preference`, `surface_preference`, usage-authority ladder) govern *surfacing*, not locality — they stay in their own registry. A future class (e.g., minor-related data, if teen environments ever open) enters by ratification with all three columns filled, or it does not enter.

## 3. The composition rule (where the doctrine will actually be tested)

The subtle case is never "which tier runs where" — it is **high-tier generation over intimate inputs**. A portrait draws on the member's whole field; the tier is cloud-acceptable, but if assembly pulls a sacred-marked atom into the prompt, the rule is violated invisibly.

> **Intimacy class attaches to data and propagates through any pipeline. A cloud-bound call must be provably free of intimacy-class inputs — enforced at context assembly, not at call sites.**

Consequences:
- Context assembly (ADR-013 jurisdiction) is the single enforcement point; per-call-site discipline is Grade-C and prohibited as the primary mechanism.
- Provenance labels must survive derivation: an embedding, summary, or affinity row computed from sacred-class data inherits the class (the F2 fix — purging affinity rows derived from sealed atoms — is this principle already enforced one axis over).
- "Provably free" means testable: the assembly seam exposes what entered a prompt, so a refusal test can assert the absence of intimacy-class inputs on cloud-bound paths. Candidate refusal-registry entry once implemented.

## 4. What this doctrine does NOT authorize

- Running under-quality local models to claim "local" (provenance theater — prohibited by claim discipline).
- Treating tier-locality (e.g., "CORE runs local") as a sovereignty claim.
- Adding intimacy classes without ratification, or enforcing them anywhere but the registry's named points.

## 5. Economic consequence (endorsed by the infra staging candidate)

Funded dollars route to the three compounding assets — Stage 0 reliability, H1 front doors, Stage 3 trust infrastructure (provenance attestation, key management, sync) — not depreciating silicon. Stage 2 may never buy GPUs. Reversibility is already structural via provider governance; ruling deep-tier-must-localize later costs only the rental sizing step.
