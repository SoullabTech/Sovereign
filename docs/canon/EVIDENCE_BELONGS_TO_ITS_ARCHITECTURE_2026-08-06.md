# Evidence Belongs to the Architecture That Generated It — candidate method instrument

**Founder-authored, 2026-08-06.** ⚠️ **Candidate**, ⛔ not ratified canon.

> ⭐⭐⭐ **PROVENANCE OF AUTHORITY — cite it this way, ⛔ never as a general principle.**
> *"This rule was extracted from a single measured situation in the practitioner publishing lane
> (2026-08-06): practitioners are actively using the platform, while the publishing model has no
> authorized substrate — so their activity could have been read as validating an architecture it
> never touched."*
>
> ⛔ It was **not** reasoned to from theory. ⭐ Its authority is **earned by that case and extends
> exactly as far as the case does.** ⛔ Do not strip the case out to leave a clean maxim — without
> it the rule reads as an elegant abstraction, and a future reader will treat it as optional.

---

## The rule

> ⭐⭐⭐ **Evidence belongs to the architecture that generated it.**
>
> ⛔ **Evidence is not fungible.** Success in one architecture cannot be imported as validation for
> another merely because the two share **users, data, or screens**.

### The corollary that makes it operable

> ⭐⭐⭐ **Any claim of adoption or validation must name which architecture was inhabited.**

⭐ The rule forces the **missing referent**. ⛔ A claim that omits it is not weak evidence — it is
**not yet a claim**.

---

## The laundering it prevents

> ⛔ *"People are using the product, therefore this architecture has been validated."*

⚠️ This is the everyday form. It is persuasive precisely because **the first clause is true**.
⭐ The defect is the *therefore*: it moves evidence across an architectural boundary that the
evidence never crossed.

### Worked referents

| Observed activity | ✅ Evidence **for** | ⛔ Evidence for **nothing else** |
|---|---|---|
| Members actively using **Now What?** | the Now What? architecture | — |
| Practitioners actively using **Session Room** | Session Room | — |
| Writers actively using **Writer Canvas** | Writer Canvas | — |
| Coaches actively using today's practitioner portal | the **current practitioner system** | ⛔ **not** Practitioner Publishing |

⭐ None of these becomes evidence for **Practitioner Publishing** until the publishing architecture
is **what they are inhabiting**.

---

## Why this is not pedantry

⭐ The overlap is **increasing, not decreasing**. MAIA, Writer Studio, Practitioner Portal, Now What?
and future products meet inside **the same user journeys** — the same person, the same session, often
the same screen. ⛔ That overlap is exactly what makes the laundering feel reasonable.

> ⭐⭐⭐ **Without this rule, one mature subsystem lends unearned credibility to a newer one simply
> because the same people interact with both.**

⚠️ The damage is not merely a wrong sentence in a deck. ⭐ An unearned validation claim **removes the
pressure that would have produced real evidence** — the newer architecture stops being measured
precisely when measuring it still matters.

---

## The discipline

1. ⭐ **Name the architecture in the claim itself**, ⛔ never in a footnote — *"evidence for Session
   Room"*, never bare *"evidence that practitioners have adopted this."*
2. ⛔ **Shared users are not shared evidence.** Neither are shared tables, shared routes, or a shared
   surface. ⭐ Ask what the person was **actually inhabiting**, not what they were near.
3. ⛔ **An architecture with no authorized substrate cannot have inhabitation evidence** — there is
   nothing there to inhabit. ⭐ Check substrate authorization *before* accepting adoption evidence.
4. ⭐ **Duration is not transfer.** *"For months"* strengthens a claim only about the architecture
   that was running for those months.
5. ⛔ **Never let an imported validation become a premise.** ⭐ Re-check the referent at the moment
   the claim starts carrying weight.
