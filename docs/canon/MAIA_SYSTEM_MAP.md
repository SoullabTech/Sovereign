# MAIA System Map

## Modes, Layers, Flows, and Architecture

This document provides a single-page structural map of how MAIA functions as an integrated intelligence system. It aligns product, design, engineering, and strategy around the same architecture.

---

## 1. The Core View

MAIA consists of interacting layers:

- **Relational MAIA** -- the field of attunement, process, and meaning
- **Ask MAIA** -- the doorway into clarity, conceptual inquiry, and structured understanding
- **Knowledge Field** -- the library and cross-domain mapping layer

These are coordinated dimensions of one intelligence, not separate products.

---

## 2. The Three Primary Layers

### A. Relational MAIA

The primary field of contact. Meets the person, tracks process, reflects meaning, supports integration through relationship. This is the default stance.

### B. Ask MAIA

The explicit doorway into direct inquiry. Answers clear questions, provides conceptual structure, orients the member within larger systems of meaning. A stance shift, not a new identity.

### C. Knowledge Field

The cross-domain intelligence layer. Holds domains, frameworks, and traditions. Supports domain-aware answers. Preserves distinctions while enabling integration.

---

## 3. The Basic User Flows

### Flow 1 -- Speak with MAIA

**User intent:** "Meet me in my process."

User speaks or types -> MAIA stays relational -> response centers process, emotion, pattern -> closes with reflective question.

### Flow 2 -- Ask MAIA

**User intent:** "Help me understand."

User selects Ask MAIA (or system detects conceptual inquiry) -> MAIA shifts to orientation -> Knowledge Field activates -> response is structured and domain-aware -> turn resets after answer.

### Flow 3 -- Future: Contrast

**User intent:** "Show me another way to see this."

Response lands -> invitation appears -> user opens second lens -> MAIA offers alternate perspective -> user integrates.

---

## 4. The Internal Architecture

### Layer 1 -- Input Detection
Interprets member intent: emotional/process vs conceptual/direct vs mixed.

### Layer 2 -- Response Stance
Determines how MAIA should answer: relational or orientation/Ask MAIA.

### Layer 3 -- Prompt Stack
System prompt assembled from: base prompt, stance block, Knowledge Field block, environment blocks, theme/context blocks, relational layers.

### Layer 4 -- Knowledge Field
12 domains with concepts, mappings, and cross-domain relationships.

### Layer 5 -- Response Generation
One voice, different emphasis based on stance and active blocks.

### Layer 6 -- Return to Default
After Ask MAIA, system returns to relational mode.

## 5. Member-Facing Modes

From the member's perspective:

### Speak with MAIA
For: process, reflection, guidance, emotional and symbolic inquiry.
Feeling: "I am being met."

### Ask MAIA
For: clarity, learning, comparison, understanding how systems relate.
Feeling: "I understand how this fits."

---

## 6. Response Pattern by Stance

### Relational
attune -> reflect -> deepen -> integrate -> invite further exploration

### Ask MAIA
answer directly -> frame in domain -> compare/map -> preserve distinctions -> integrate -> close with one grounded question

---

## 7. Guardrails

### Relational
- do not become generic coaching
- do not flatten symbolic material
- do not lose attunement

### Ask MAIA
- do not become a generic explainer bot
- do not overclaim knowledge
- do not flatten traditions
- do not lose MAIA voice
- do not stay active across turns

### Knowledge Field
- preserve lineage and difference
- avoid synthetic authority
- support integration, not information overload
