## The two defects this cut closes

1. **Detection too narrow.** Only bare anchored commands match (`keep this`, `save this as an idea`). Natural forms — `keep this: X`, `remember this: X`, `save this: X` — fail and capture nothing.
2. **Speech-act ungated (covenant-critical).** MAIA's "kept" is generated by the language model, decoupled from whether anything persisted. Pre-existing; independent of the keep plumbing. A promise with no record is the broken covenant.

Closing **#1 alone is not enough** — even with perfect detection, any phrasing that misses (or any write that fails) still lets the model say "kept." **#2 is the floor.**

## Workstream A — Broaden explicit detection + capture the referent

File: `lib/psyche/conversational-keep.ts` (`parseFilingInstruction` / `FILING_PATTERNS`). The live route already calls it; no route change needed beyond passing the captured content through.

- Add **colon-form patterns** that capture the content *after* the delimiter as the atom's substance (not the command phrase):
  - `keep this: <X>` → destination `keep`, **excerpt = `<X>`**
  - `remember this: <X>` / `remember: <X>` → `keep`, excerpt = `<X>`
  - `save this: <X>` → `keep`, excerpt = `<X>`
  - (extend the existing `as an idea` / `as a decision` etc. forms to also accept inline content)
- **Precision guardrails** (entrustment is *declared*, never over-captured): require an explicit filing verb + a delimiter (`:` strongly preferred) + non-empty content; do not match questions (`remember when…?`), negations, or bare verbs with no object. Colon forms = high confidence; verb-without-delimiter = low confidence → confirmation, not auto-write.
- **Referent (no-colon) `keep this`** — capturing what "this" points to (the prior turn) is *conversation-atom context tracking*; keep it a **follow-on**, not in this cut. This cut fixes the inline-content forms (the ones Kelly actually used).
- **Receipt:** unit test — `keep this: blue cedar lantern` → `{destination:'keep', confidence:'high', excerpt:'blue cedar lantern'}`; and the negative — `remember when we talked?` → null.

## Workstream B — Gate the acknowledgment (the floor)

Two parts, both required; the model cannot be trusted to self-suppress alone.

1. **Prompt floor (negative capability rule).** Audit the live prompt path (`buildMaiaWisePrompt` / `appendAllContextAddenda` — see `project_interface_humility_guardrail`) for any existing keep-claim rule; it is currently insufficient (it let "kept" through). Strengthen to an explicit, standing rule: *"You cannot save, keep, or remember anything on your own. Never tell the member you have kept / saved / stored / remembered something. Persistence is handled separately and confirmed by the system."*
2. **Deterministic truthful acknowledgment (system-driven, from the write result).** The acknowledgment comes from `keepIntent`, never from free generation:
   - `kind === 'filed'` (write confirmed) → *"Kept: '<content>'."*
   - `kind === 'filing_confirmation'` (low-confidence) → *"I can file that — confirm?"* (Yes/No)
   - detection fired but the write **failed/uncertain** → the honest fallback: *"I received that, but I can't confirm it was kept yet."*
   - no keep detected → model stays silent on keeping (per the floor rule)
- Surface: this is where the deferred `KeepAffordance` render earns its place — **reframed from cosmetic Visibility to covenant enforcement.** It (or a server-appended status line) renders the truthful acknowledgment; the `NEXT_PUBLIC_CONVERSATIONAL_KEEP_ENABLED` flag gates it.
- **Receipt (eval):** with the floor rule live, the model no longer emits "kept/saved/remembered" on its own for keep-shaped inputs (deterministic detector eval over keep-shaped prompts); the only "kept" the member sees is the system-rendered one, and it appears **iff** an atom row exists.
