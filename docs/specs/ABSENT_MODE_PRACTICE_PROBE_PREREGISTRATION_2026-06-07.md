# Absent-Mode Practice Probe — Pre-Registration

**Status:** FROZEN 2026-06-07 · v1 · NOT RUN · candidate instrument, not a discipline
**Scope-lock:** Tests the *practice* (deliberately attending the under-attended mode), **not** the *ontology*.
A negative result kills the practice claim. It does **not** touch the constitutive-dependence question
("can whole-awareness arise without multiplicity?") — that is a separate probe with a separate falsifier.
Do not let the two collapse into each other.

**Revision rule (Air precedent):** no *quiet* changes once sessions accumulate. Changes before any run are
permitted only as an explicit, dated version bump. After the first session, the design is sealed.

---

## Claim under test

Attending the **absent mode** changes what a person brings home (self-reported) **more than**
attending a **random mode**, and more than holding generically.

## Arms (register held constant across 1 and 2)

1. **Absent-mode audit** — MAIA surfaces a clarification toward the *least-present* element.
2. **Random-mode audit** — same template, same length, same register, toward a *randomly chosen* element.
   This is the arm with teeth: it isolates *absence-targeting* from "elemental prompting in general."
3. **No audit** — generic holding. Baseline: isolates "did anything specific happen at all."

## Three blinding layers (all required — one open layer disputes any negative result)

- **Reader-blind** (downstream): blind readers score the brought-home account; they never know the arm.
- **Elicitor-invariant** (the closed hole): the closing elicitation is a **frozen identical string**,
  delivered by construction — **not** generated from session context. A context-generated elicitation is a
  *reading* that covaries with the arm; a frozen string is an *invariant* that cannot signal it. If a human
  elicits instead, that human is blind to arm. (The unavoidable contextual difference of asking the same
  question after different interventions *is the treatment effect* — that is the IV, not a confound.)
- **Participant-blind** — achievable **only for arm 1 vs arm 2**, because they are register-matched: the
  participant sees "a clarification toward [element]" in both and cannot tell which *selection rule*
  produced it. Arm 3 is distinguishable (feels like nothing deliberate happened) → demand-characteristic asterisk.

## Endpoints (consequence of the blinding analysis)

- **PRIMARY: absent vs random.** Fully closed end-to-end (register-matched → participant-blind;
  elicitation invariant; readers blind). The claim lives or dies here.
- **SECONDARY: absent vs none.** Carries the demand-characteristic asterisk. Supporting, not deciding.

## Outcome measure

The participant's **own account** of what they are leaving with — never MAIA's inference (no emitted
coherence verdict). Blind readers score for **content**: did a new action / meaning / orientation appear
that was not present at session start? (Blind-reader method ported from the Air probe; method-validity
already passed there.)

## Falsifier

The claim survives only if **absent > random** on the primary endpoint in blind scoring.
**absent ≈ random ⇒ absence carries no weight ⇒ the practice is decorative.** A result that can return negative.

## Analysis plan (pre-specified; no post-hoc endpoint switching)

- Direction + threshold fixed before unblinding; primary endpoint is absent-vs-random only.
- Design: between-subject preferred; within-subject only if counterbalanced (note carryover/learning).
- Target N/arm set before run (Air ran 6/arm and still falsified a strong claim; self-report is noisier — size up).

## Binding constraint (the honest sentence)

The **instrument** is tractable. The **cohort** is not there yet — engaged members live in member-facing MAIA;
session volume is the gate, not the design. The probe is **gated on volume, not cleverness.**

## Buildable now (without a cohort)

The register-controlled three-arm generator **plus the frozen elicitation string**, as a repro harness
(Fire-lens-shaped). Building the instrument ≠ running the probe ≠ validating the practice. Three separate things.
