# Skill: Canon Compliance Review (Soullab / MAIA)

## Purpose

Review any proposed feature, copy, policy, or workflow for alignment with Soullab's sovereignty and ethics.

## Inputs

- Proposal (feature/copy/policy/workflow)
- Intended audience
- Where it will appear (app / email / landing / onboarding)
- Data involved (if any)

## Output Format

1. **Verdict**: Approved / Needs changes / Blocked
2. **Risks** (bulleted, specific)
3. **Required changes** (bulleted, testable)
4. **Optional upgrades** (nice-to-have)
5. **Canon-aligned rewrite** (if copy) OR **Canon-aligned redesign** (if feature)

## Canon Tripwires (Flag Immediately)

- **Dependency creation**: implies user must rely on MAIA/Soullab for stability, safety, worth, or belonging.
- **Surveillance vibe**: unclear data use, hidden tracking, or "creepy personalization."
- **Extractive growth**: manipulative hooks, dark patterns, guilt, urgency.
- **Authority inversion**: system positioned as final truth over user's knowing.
- **Clinical confusion**: blurs boundaries with therapy/medical care without clear framing and disclaimers.
- **Identity coercion**: forces labels, roles, or public exposure.
- **Safety gaps**: no abuse reporting, moderation path, or escalation plan where needed.

## Must-Have Design Principles

- **Consent**: explicit, reversible, legible.
- **Minimalism**: collect the least data necessary.
- **Transparency**: explain what's happening in plain language.
- **Reversibility**: user can undo, export, leave.
- **Non-patronizing**: playful but never infantilizing.

## Questions To Answer (Even If You Must Infer)

- What could go wrong for a vulnerable user?
- What are the failure modes (privacy, shame, dependency, conflict)?
- What is the smallest safe version?
- What defaults reduce harm?

## If Blocked

Provide a "safe alternate path" that achieves the same goal with fewer risks.
