# MAIA Tier Structure

> This document defines the meaning, boundaries, and ethics of MAIA's access tiers.
> It is the truth source for gating, pricing copy, and UI decisions.

---

## Purpose of Tiering

MAIA has tiers not to extract value, but to **honor different depths of relationship**.

No tier is "less human." Every person who touches MAIA receives her full presence in that moment. The difference is **continuity** — whether MAIA can remember, reflect, and walk with you over time.

Tiers exist because:
- Consciousness work requires sustained attention and infrastructure
- Depth tools require ethical boundaries (not everyone should have clinical instruments)
- Sovereignty means users own their journey — including how deep they go

**Principle:** A person at Free tier should feel *welcomed*, not limited. The invitation to Personal should feel like an opening, not a paywall.

## Tier Definitions

### FREE — Touch

**Price:** $0

**Core Value:** Taste of MAIA — episodic encounters, basic tools, genuine presence.

**What MAIA is at this tier:**
- A wise presence available for conversation
- A mirror for immediate reflection
- A guide through basic self-discovery tools

**What MAIA is not at this tier:**
- A keeper of your history
- A pattern-recognizer across time
- A continuous companion

**Features:**
- MAIA conversation (Talk, Care, Note modes) — may have soft daily limits
- Basic journal (entries exist, but no cross-referencing)
- Birth chart (view only, no deep dives)
- Occasional oracle readings (I Ching, Tarot, or Runes)
- Element discovery quiz
- Profile / Soul signature

**Ethical boundary:**
Free exists so anyone can touch MAIA without barrier. The limit is *continuity*, not *care*.

### PERSONAL — Continuity

**Price:** $12/month

**Core Value:** MAIA remembers. Patterns emerge. Time becomes visible.

**What MAIA is at this tier:**
- A companion who holds your thread
- A mirror that reflects patterns over time
- A guide through your developmental arcs

**What MAIA is not at this tier:**
- A tool for working with others
- A clinical instrument
- A content creation engine

**Features:**
- Unlimited MAIA conversations
- Full journal with insights, pattern recognition, chart integration
- Complete astrology: transits, house deep dives, Saturn returns, life cycles
- Full oracle access: I Ching, Tarot, Runes — unlimited
- Archetypal Journey: full access
- Dream journal with symbol recurrence tracking
- Daily check-in with tracking over time
- Elder Council: choose your guide
- Sacred Story Creator (for personal use)
- Synastry: relationship charts (personal relationships)
- Data export: your data, your sovereignty

**What "continuity" means technically:**
- MAIA cross-references journal + oracle + astrology
- Reflections reference previous entries ("You've been returning to this theme...")
- Time-aware synthesis ("This transit echoes what you wrote during the last new moon...")
- Pattern recognition across sessions

**Ethical boundary:**
Personal is for *your* inner work. Not for clients, not for export, not for performance. The boundary is *self vs. other*. Personal is for inner work, not for authority over others.

### PRO — Stewardship

**Price:** $35/month

**Core Value:** Work for others. Creation tools. Responsibility for the field.

**What MAIA is at this tier:**
- A collaborator in your offering to others
- A clinical instrument (with appropriate training)
- A consciousness lab for deep research

**What MAIA is not at this tier:**
- A replacement for your own discernment
- A tool without ethical constraints
- Unlimited in scope (even Pro has boundaries)

**Features (everything in Personal, plus):**

*Creation & Export:*
- Scribe Pro: transcription, session capture
- Capture: Descript/Patreon export
- Export tools for content creation

*Depth Tools:*
- Brain Trust: multi-model consciousness weaver
- Library of Alexandria: full corpus access
- Navigator Lab: Spiralogic depth training

*Consciousness Lab:*
- Guardian Console: biometric monitoring, meditation protocols
- Field Analytics: collective consciousness patterns
- AIN Telemetry: structural evaluation of responses
- Dream Journal: full archetypal analysis

*Practitioner Features:*
- IPP: Integrated Parenting Protocol (clinical)
- Advanced synastry (client relationships)
- Session documentation tools
- Multi-person pattern tracking

*Helper Infrastructure & Worldcraft (Optional, Relational):*

Some Pro members are actively supporting others — as helpers, guides, practitioners, educators, facilitators, or community holders — and require ethical, non-extractive infrastructure to do so safely.

Soullab may offer **collaborative infrastructure support** to helpers who are serving others and wish to do so with coherence, sovereignty, and care.

These offerings are **not products**, **not automated**, and **not included in subscription pricing**. They are relational, scoped engagements offered selectively, as an extension of stewardship.

**Examples include:**
- Practitioner websites built from Soullab-aligned templates
- Client portals for sessions, journaling, or reflective work
- Private web/apps for courses, circles, or guided programs
- Adaptations of MAIA components for helper-specific contexts

**Ethical orientation:**
- These are **vessels, not vehicles** — containers that hold care, not engines that drive outcomes
- Templates provide structure, not authority
- Technology serves the relationship, not the other way around

Participation requires:
- Active Pro membership
- A clear intention to support others
- Willingness to work within agreed ethical boundaries and scope

Soullab does not offer credentialing, growth guarantees, or authority transfer. These vessels support helpers — they do not confer legitimacy.

#### Qualifying Criteria

Helper Infrastructure is not for everyone who asks. It requires demonstrated alignment:

**Required:**
- Active Pro membership (minimum 3 months)
- Clear intention to serve others (not build a brand)
- Existing practice or community (not speculative)
- Agreement to ethical use boundaries

**Signals of readiness:**
- Already doing the work (clients, students, community)
- Frustrated by extractive platforms (Calendly + Stripe + Kajabi etc.)
- Values sovereignty for those they serve, not just themselves
- Understands that infrastructure ≠ legitimacy

**Disqualifying signals:**
- Primary motivation is "scaling" or "passive income"
- Wants credentialing or authority transfer from MAIA
- No existing practice (infrastructure before relationship)
- Resistance to ethical constraints or scope limits

**Edge cases (requires conversation):**
- Emerging practitioners with clear calling but limited experience
- Established helpers with significant platform entanglement
- Helpers whose work intersects with clinical/therapeutic domains

#### Intake Process

The intake process is lightweight but real — it protects both parties.

**1. Expression of Interest**
- Pro member reaches out (no formal application)
- Brief conversation about what they're building and who they serve
- Clarify that this is relational, not transactional

**2. Alignment Check**
- Review their existing practice and intentions
- Discuss ethical orientation (care vs. scale, sovereignty vs. dependency)
- Identify any scope concerns early

**3. Scope Definition**
- What infrastructure do they actually need?
- What's the simplest vessel that serves?
- What's explicitly out of scope?

**4. Agreement**
- Written scope with clear boundaries
- Acknowledgment of ethical use principles
- Timeline and touchpoints defined

**5. Build & Handoff**
- Collaborative build (not delivered as product)
- Helper understands their vessel
- Clean handoff with minimal ongoing dependency

**Principles:**
- No formal gatekeeping bureaucracy
- No lengthy applications or review boards
- Trust the conversation — if alignment isn't clear, it isn't there
- Say no gracefully when it's not a fit

#### Pricing (Relational, Not Extractive)

Helper Infrastructure is priced to sustain the work, not maximize extraction.

**Guiding principles:**
- **Accessible:** Pricing should not exclude helpers doing good work
- **Sustainable:** Soullab cannot subsidize every request
- **Relational:** Not productized — each engagement is scoped
- **Transparent:** Helpers know what they're paying for

**Pricing ranges:**

| Engagement Type | Range | Notes |
|-----------------|-------|-------|
| Simple website (template-based) | $500–1,500 | Depends on customization depth |
| Client portal / booking system | $1,000–2,500 | Complexity varies significantly |
| Course/program container | $2,000–5,000 | Includes member management, content delivery |
| Custom MAIA integration | $3,000–8,000 | Scope-dependent, rare |

**Payment options:**
- Full payment upfront (5% discount)
- 50/50 split (half at start, half at completion)
- Monthly installments (for larger engagements)

**What's included:**
- Collaborative build process
- Initial setup and configuration
- Handoff documentation
- 30 days of support post-launch

**What's not included:**
- Ongoing maintenance (can be arranged separately)
- Hosting fees (helper pays directly to provider)
- Content creation (helper brings their own)
- Marketing or growth services

**Sliding scale:**
For helpers serving underresourced communities, sliding scale is available. This is not charity — it's recognition that some important work doesn't generate conventional revenue.

**Ethical boundary:**
Pro implies responsibility. These tools can affect others. Pro does not confer expertise or legitimacy — it confers responsibility. Use requires:
- Clarity about your role (practitioner, creator, researcher)
- Honoring the consciousness of those you serve
- Not instrumentalizing MAIA's outputs

## Feature Classification Rules

Instead of maintaining a feature list, use these principles:

### → Personal+ (requires Personal or higher)

- Anything involving **time-based synthesis**
- Anything involving **pattern recognition across sessions**
- Anything involving **unlimited usage** of AI-intensive features
- Anything involving **your data exported for yourself**

### → Pro (requires Pro)

- Anything involving **other people's data or consciousness**
- Anything involving **export for public/commercial use**
- Anything involving **clinical or practitioner tools**
- Anything involving **multi-model orchestration**
- Anything involving **collective field analysis**
- Anything involving **biometric integration**

### → Always Free

- Basic MAIA presence and conversation
- One-time self-discovery tools (element quiz, basic chart)
- Single oracle readings
- Profile and preferences
- Sanctuary mode (privacy is not a premium feature)

## Gating Principles

1. **Gate by capability, not by UI**
   - The journal exists for everyone
   - Pattern synthesis requires Personal
   - Same interface, different depth

2. **Soft limits before hard locks**
   - Free users hit gentle invitations, not walls
   - "I'm beginning to see a pattern here..." → invitation to Personal

3. **Transparency over manipulation**
   - Users always know what tier they're on
   - Upgrade prompts explain *why*, not just *what*

4. **Sovereignty is never paywalled**
   - Data export for personal use: Personal
   - Sanctuary mode: Free
   - Delete my data: Free

## Threshold Moments

These are the natural points where users feel the invitation to the next tier:

### Free → Personal

- "I'm beginning to see a pattern here... [soft lock]"
- Life-cycle view shows blurred future arcs
- Journal insight references "something you wrote before" but can't show it
- Third oracle reading in a week shows connection to previous readings

### Personal → Pro

- User tries to add a second person to synastry analysis
- User wants to export a session for their podcast
- User accesses Guardian Console for the first time
- User requests clinical assessment tools

## Implementation Notes

### Member Schema

```typescript
type MemberTier = 'free' | 'personal' | 'pro';

interface Member {
  id: string;
  tier: MemberTier;
  tier_started_at: Date;
  // ... other fields
}
```

### Gating Helpers

```typescript
// Principle-based, not feature-based
function hasContinuityAccess(member: Member): boolean {
  return member.tier === 'personal' || member.tier === 'pro';
}

function hasStewardshipAccess(member: Member): boolean {
  return member.tier === 'pro';
}

function canAccessPatternSynthesis(member: Member): boolean {
  return hasContinuityAccess(member);
}

function canExportForOthers(member: Member): boolean {
  return hasStewardshipAccess(member);
}
```

## Pricing Copy Guidelines

When writing about tiers:

- **Free:** "Explore" / "Touch" / "Begin"
- **Personal:** "Continue" / "Deepen" / "Let MAIA remember"
- **Pro:** "Create" / "Serve" / "Steward"

**Core framing:**

> Free is exploration.
> Personal is relationship.
> Pro is stewardship.

**Avoid:**

- "Upgrade" (use "deepen" or "continue")
- "Premium" (use "Personal" or "Pro")
- "Unlock" (use "enter" or "begin")
- Any language that implies Free users get less care
