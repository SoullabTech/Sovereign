# Developmental Gates — CANDIDATE

**Status:** CANDIDATE — not canonical. Validated in one domain (homepage evolution, 2026-06-30). Watch for independent instances before promoting.

**Promotion condition:** The same five gates naturally describe independent domains — Practitioner Portal, Vision Studio, constitutional governance, model capability promotion, onboarding, runtime architecture, institutional decision-making — without being forced. If the pattern proves predictive rather than merely explanatory across multiple independent cases, it earns canonical standing.

---

## The sequence

> **Discovery → Coherence → Simplicity → Translation → Accountability**

Each outward move depends on an inward one having earned it.

### Gate questions

| Stage          | Gate question                                                              |
| -------------- | -------------------------------------------------------------------------- |
| Discovery      | Have we observed enough to distinguish what is actually here?              |
| Coherence      | Does the architecture consistently explain the observations?               |
| Simplicity     | Can the essentials now be stated without distortion?                       |
| Translation    | Can someone encountering this for the first time understand it faithfully? |
| Accountability | Are we willing to be held publicly to what we've just said?                |

### Failure modes

Every stage contains its own failure mode when skipped:

| Stage          | Failure if skipped                                        |
| -------------- | --------------------------------------------------------- |
| Discovery      | Mistaking assumptions for observations                    |
| Coherence      | Explaining contradictions away instead of resolving them  |
| Simplicity     | Compressing before understanding                          |
| Translation    | Public language that overstates or distorts reality       |
| Accountability | Promises the institution cannot actually keep             |

A mature methodology doesn't just describe good practice — it helps identify *where* something went wrong.

---

## The unifying principle

The same epistemic discipline expressed at different layers of the project:

- The **runtime** shouldn't interpret before it understands.
- The **methodology** shouldn't canonize before it observes.
- The **public voice** shouldn't translate before it coheres.
- The **institution** shouldn't promise before it is prepared to answer.

These aren't separate rules. They're one discipline at different scales.

---

## Relationship to existing methodology

This sequence governs **transitions**, not objects. Most existing methodology governs what objects are (observations, recognitions, interpretations, specifications, decisions). This asks: under what conditions is it justified to move from one developmental state to the next? That makes it closer to a constitutional *process* than a constitutional *principle*. The distinction may matter over time.

## Predicted independent domains

*Written 2026-06-30, before evidence from these domains exists. The value of recording predictions now: if the patterns appear, they strengthen the candidate because they were anticipated rather than recognized only in hindsight. If they fail to appear, that is equally useful — it means the sequence is narrower than it seemed.*

| Domain               | Predicted observation                                                                                          |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Capability promotion** | Translation hesitates until runtime coherence is demonstrated. "Wired" and "working" remain explicitly separate until verified under real load. |
| **Onboarding**           | Consent is delayed until sufficient understanding has been established. A member cannot meaningfully agree to something they have not yet encountered. |
| **Governance**           | Public commitments follow demonstrated institutional practice rather than aspiration. The covenant is an example; future governance language should exhibit the same pattern. |
| **Model evaluation**     | A model or capability becomes "production" only after surviving contact with evidence, not because it is technically impressive or architecturally complete. |

**A fifth prediction, kept separate because it is one level more general than the others:**

> As the project matures, practitioners will continue to exhibit the sequence *before* consciously invoking it. Explicit reference to the framework will tend to occur after the developmental transition has already begun, serving recognition more often than direction.

This prediction can fail in a useful way. If every future instance only occurs because someone deliberately applies the framework, the sequence is a governance tool — valuable, but not yet evidence of an underlying developmental regularity. If practitioners repeatedly rediscover the same hesitation independently, the sequence is describing something about how institutional maturation actually moves, not prescribing it. That is a much stronger claim. The document does not make it yet.

The observation behind the prediction: the homepage and capability promotion both show the pattern operating before it had language. "A mature methodology is recognized before it is referenced" is a hypothesis worth watching, not a conclusion to draw from two instances.

---

**Capability promotion** is the cleanest early test. The gates are already operating implicitly — instrumentation before influence, `emitted: true` before calling something live, explicit refusal to collapse "wired" into "verified." If the next capability promotion cycle names those stages as it moves through them and the sequence holds without forcing, that is the second independent domain.

**Onboarding** is structurally different from capability promotion: the former concerns technical truthfulness, the latter relational truthfulness. If the same gates appear in both — especially the question of whether someone has encountered enough, in the right order, to give meaningful consent — the sequence has crossed an important threshold. It would be explaining two different kinds of maturation with the same underlying discipline.

## First observed instance

**Homepage evolution, 2026-06-30.**

The architecture had been working through Discovery and Coherence for months. It reached Simplicity when the essential commitments could be stated without hedge or distortion. Translation became possible when the sequence of encounter was rearranged to match how understanding actually develops in a first-time visitor. Accountability arrived with the covenant — public language the platform can now be held to.

The homepage is one application. The methodology is the more durable potential contribution.

---

## How to apply

Before any outward move — publishing a claim, shipping a feature, naming a capability, writing onboarding copy, adding a homepage section — identify which stage that move belongs to and verify the prior stage has been genuinely cleared.

If Discovery is incomplete, Coherence is premature.  
If Coherence is unstable, Simplicity will distort.  
If Simplicity hasn't been earned, Translation will mislead.  
If Translation hasn't been tested, Accountability is reckless.

The pressure to skip stages is greatest when something feels important. That's when the sequence matters most.
