# Journey Composition Guide
### An architect's handbook for composing developmental journeys

**Status:** CANDIDATE methodology (design-reasoning standard). 2026-07-07.
**Audience:** any Field designer. Larry is the first practitioner, but he is not the methodology — write and read this practitioner-agnostically; use Larry only as example.

## Where this sits — the design stack

```
Constitution        (what may never be violated — inherited, non-disableable)
   ↓
Field               (the tenant — one practitioner's world)
   ↓
World Design        (the place: atmosphere, rhythm, boundaries, culture)
   ↓
Journey Composition (the lived path through the place)
   ↓
Experience          (what a person actually feels, in sequence)
   ↓
Interface           (the thinnest visible expression of all the above)
```

**The distinction that names this discipline:** the opposite of *feature design* is not *world design* — it is **journey composition**. World Design gives the **place**; Journey Composition gives the **lived path** through it. They are complementary: a place with no path is a museum; a path with no place is a workflow.

## The composer's questions (the handbook)

Ask these of every journey, in this order:

**Entry**
- What world is someone entering? (Whose way of seeing, asking, practicing?)
- What is the *first feeling* — before any feature is understood?
- Does the entry feel like the practitioner's work, or like generic software?

**Boundaries** (the constitutional core)
- What belongs *only* to the practitioner? (composition, their own notes, opt-in analytics)
- What belongs *only* to the participant? (private memory, unshared reflection, sovereignty over recognition)
- What remains *shared* — and only because the participant chose to bring it into relationship?

**Time**
- What changes over months? (The Field matures with the practitioner; it is never "finished.")
- Does a returning participant meet accumulated wisdom, not replaced material?

**Humanity** (the non-automation line)
- What should *never* be automated?
- Where must a human always appear? (Recognition, welcome, the moments that carry weight.)

**Disappearance**
- What should disappear? (The architecture, the module inventory, the sense of "using an app.")
- Success test: *"I never really thought about the software — the work was just there when I needed it."*

## The proving journey (smallest unit that exercises the whole constitution)

A single loop, composed once, proves more than any screen:

```
Invitation → Welcome → First MAIA conversation → Reflection → One practice → Resource → Return to practitioner
```

Walk it and check every constitutional question at once:

| Beat | Question it answers | Invariant under test |
|---|---|---|
| Invitation / Welcome | Does onboarding feel like *this practitioner*? | World Design; cultural identity |
| First MAIA conversation | Does the companion *belong in this world* without impersonating the practitioner? | Apprentice-not-imitation (Inv 14; never synthesis) |
| Reflection → practice | Does the participant remain the author? | Sovereignty; recognition belongs to the person |
| Resource | Are shared resources explicit, not inferred? | Consent (per-thread gesture) |
| Return | Does the practitioner receive *only what was shared*, and does it feel *alive*? | Consent boundary; continuity |
| The whole | Did it disappear into the experience? | Simplicity/harmony; interface humility |

If that loop feels natural, the *architecture* is proven — and, if it was composed from existing capabilities rather than new primitives, the Field-tenancy hypothesis is strengthened (its falsifier: a journey that required new primitives).

## Discipline

- This guide is at the **design-reasoning** standard. A composed journey earns **Live** only by being deployed, walked, *and felt* (build → verify → experience → expand).
- Evidence discipline for any claim that a journey *produces development*: freeze the experience, the instrument, and the interpretation protocol before observing (see the Frozen-inquiry methodology).
- Related: World Design principle — *the world presents what people have chosen to bring into relationship; it does not narrate who they are becoming.*
