# Zen Mod — Capability Surface & Feasibility

**Status:** Investigation (option B — docs pulled, real CSS scoped, feasibility evaluated).
**Last updated:** 2026-05-30
**Companion doc:** `docs/integrations/ZEN_BROWSER.md` (Phase 2 = the Mod).

Purpose: before designing in abstraction, establish what a Zen Mod can *actually touch*, and
evaluate whether the three atmospheric interventions — **Quiet Chrome**, **Unified Tempo**,
**Breathing Threshold** — are implementable within Zen's mod architecture, or whether some
pieces belong in the future (Phase 3) extension.

All findings below are grounded in primary sources (Zen docs + real shipped mods), cited at the
bottom. **They are source-grounded, not yet runtime-verified in a live Zen install** — see
Verification Boundary.

---

## 1. What a Zen Mod is (verified)

A mod is a folder in `github.com/zen-browser/theme-store` containing:

- `chrome.css` — the styles (the whole mod, effectively)
- `preferences.json` (optional) — user-configurable options
- `theme.json` — metadata (**auto-generated by the bot**; you don't hand-write it)
- `readme.md`, `image.png`

**Submission:** open a GitHub issue with the `create-theme` template → a bot generates the files
and opens the PR. Updates = a PR. There is no manual `theme.json` authoring and no review
pipeline beyond the maintainers.

**License:** every theme in the store is **CC-BY-NC-SA 4.0 (NonCommercial)**. Contributing the
Mod is fine as a free community gift, but the Mod's CSS itself cannot later be commercialized.
This actually reinforces the "gift, not product" framing.

**The load-bearing constraint:** `chrome.css` is injected into the **browser chrome (the UI around
the web content). It cannot style web page content.** Styling the actual page requires
`userContent.css` or an extension. *This single line decides what is a Mod vs. what is the Phase 3
extension.*

Mods may use **Zen's own CSS variables** plus **any Firefox userChrome selector**. Live iteration
is supported: enable `toolkit.legacyUserProfileCustomizations.stylesheets` in `about:config`, edit
`chrome/userChrome.css`, hot-reload via Zen's CSS live-editing tools.

## 2. Capability surface — the questions, answered

| Can a Mod… | Verdict | Evidence | Confidence |
|---|---|---|---|
| animate transitions? | **Yes** | `Better Unloaded Tabs`: `transition: filter 0.3s ease, opacity 0.3s ease` | **Verified** (shipped mod) |
| adjust sidebar / chrome spacing? | **Yes** | `#navigator-toolbox`, `.browserSidebarContainer` (margin/padding/radius are plain CSS) | **Verified** selectors |
| affect tab activation states? | **Yes** | `.tabbrowser-tab[selected] .tab-content`, `.tabbrowser-tab[pending] .tab-content` | **Verified** (shipped mod) |
| create custom focus states (chrome)? | **Yes** | `#urlbar[focused]`, `:focus-within` (standard userChrome) | High — not fetch-verified |
| modify workspace indicators? | **Likely** | workspace UI *is* chrome, so styleable in principle; exact selectors not yet pulled | Medium — confirm in live-editing |
| style focus / anything **inside** a web page? | **No** | `chrome.css` cannot reach content | **Verified** (the boundary) |

**Verified real selectors** (use these confidently; sources cited):

```css
/* frame / threshold — from "sleek border" */
#navigator-toolbox       { border-radius: 12px !important; }
.browserSidebarContainer { border-radius: 12px !important; opacity: 0.98; }
#tabbrowser-tabpanels    { background: transparent !important; }

/* tab state + transition — from "Better Unloaded Tabs" */
.tabbrowser-tab[pending] .tab-content {
  filter: grayscale(100%) !important; opacity: 0.7 !important;
  transition: filter 0.3s ease, opacity 0.3s ease !important;
}
.tabbrowser-tab[selected] .tab-content { filter: none !important; opacity: 1 !important; }
```

## 3. The three interventions — feasibility + real CSS

### 3.1 Quiet Chrome — **fully implementable** (lowest risk)

Recede the frame: desaturate / lower contrast, soften loud active states. This is just theming —
the most native of the three.

```css
/* baseline mechanism (same as the verified grayscale approach, softer) */
#navigator-toolbox { filter: saturate(0.85) contrast(0.97) !important; }
/* quiet secondary chrome; keep the active tab legible */
.tabbrowser-tab:not([selected]) .tab-content { opacity: 0.78 !important; }
```

Refinement: prefer overriding Zen's `--zen-*` color variables over blunt `filter:` (resolve exact
names via the live-editing inspector). Expose a "Calm intensity" preference. **Respect the user's
chosen Zen theme — match, don't override** (the native idiom; see §4).

### 3.2 Unified Tempo — **~70–80% implementable** (your estimate confirmed)

One easing curve + slightly slower duration across chrome state changes. CSS transitions on chrome
are **verified to work**.

```css
@media (prefers-reduced-motion: no-preference) {
  .tabbrowser-tab .tab-content,
  #navigator-toolbox, .browserSidebarContainer, #urlbar {
    transition: background-color .22s ease, opacity .22s ease,
                transform .22s ease, filter .22s ease !important;
  }
}
```

**In reach:** tab activation, hover, URL-bar focus, sidebar expand/collapse, compact-mode reveal.
**Out of reach (the missing 20–30%):** JS-timed internal animations Zen drives itself, and
*content-area* transitions (how a website paints) — that's content, not chrome.
**Risk:** specificity / `!important` wars with Zen's own transition definitions; blanket selectors
can cause jank. Higher craft than Quiet Chrome.

### 3.3 Breathing Threshold — **splits cleanly across the chrome/content line**

The "content sits in a held inside" feeling has two halves:

- **Frame / inset half — implementable as a Mod (verified).** Rounded webview corners, a soft
  container edge, a breathing margin between chrome and the web view:

  ```css
  #navigator-toolbox       { border-radius: 14px !important; }
  .browserSidebarContainer { border-radius: 14px !important; margin: 8px !important; }
  #tabbrowser-tabpanels    { background: transparent !important; }
  ```
  (Zen also ships a native content-separation/padding setting the Mod can lean on — confirm the
  pref key in live-editing.)

- **Overlay / vignette half — NOT a Mod.** A vignette or focus-dim painted *over the page* touches
  content → `userContent.css` / **Phase 3 extension** only.

## 4. preferences.json — verified schema

Real shape (from `Better Find Bar`), adapted, including the **theme-match idiom**:

```json
[
  { "property": "uc.maia.intensity", "label": "Calm intensity", "type": "dropdown",
    "options": [ {"value":"soft","label":"Soft"}, {"value":"medium","label":"Medium"}, {"value":"deep","label":"Deep"} ],
    "defaultValue": "soft" },
  { "property": "uc.maia.tempo",       "label": "Gentle transitions",    "type": "checkbox", "defaultValue": true },
  { "property": "uc.maia.threshold",   "label": "Breathing margin (px)", "type": "string",   "defaultValue": "8" },
  { "property": "uc.maia.match-theme", "label": "Match your Zen theme",  "type": "checkbox", "defaultValue": true }
]
```

Types: `checkbox` (bool), `dropdown` (string), `string`, `number`. Each writes an `about:config`
key and appears in the Mod's settings panel inside Zen. **The exact syntax for branching `chrome.css`
on a pref value (`@media -moz-pref(...)` vs. a reflected `:root[...]` attribute) is not yet
confirmed — verify in live-editing before finalizing.**

## 5. One mod, three mods, or extension?

- **Technically, a Mod is one `chrome.css`.** All three interventions fit in a single file, gated by
  `preferences.json`. So "three mods" is a *distribution/discoverability* choice, **not** a technical
  requirement.
- **The residual ~20–30% → Phase 3 extension:** content-area overlays, per-page focus dimming,
  anything reading or styling the actual web page, and any continuity feature needing state.

**Recommended sequence (matches "be a good Zen citizen first"):**

1. **Mod 1 — Handshake.** One narrow, genuinely-useful mod, no MAIA/Soullab branding. Two candidates:
   - *Quiet Chrome* — lowest risk; showcases `preferences.json` + theme-match fluency.
   - *Gentle Transitions* — more *felt*, more differentiated (no tempo mod in the store today),
     higher craft/risk.
2. **Mod 2 — The Field.** **One** mod, three preference-gated layers (Quiet Chrome + Unified Tempo +
   Breathing Threshold) — coherent by default, tunable. Coherence is the point, so keep it a single
   install rather than a scattered trio.
3. **Phase 3 — Extension.** Absorbs the content-touching residual under the page-context consent rule.

Division of labor for the partnership narrative: **Zen protects attention; MAIA protects continuity.**
