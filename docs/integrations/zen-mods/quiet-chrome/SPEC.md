# Quiet Chrome — Mod Spec (Handshake Mod 1)

**Status:** draft, source-grounded, **not yet runtime-verified in a live Zen install.**
**Role:** the first Zen *handshake* mod — a small, genuinely-useful community gift with
no MAIA / Soullab branding. Establishes that we can be a good Zen citizen before any
intelligence integration.
**Grounded in:** [`../../ZEN_MOD_CAPABILITY_SURFACE.md`](../../ZEN_MOD_CAPABILITY_SURFACE.md)
(verified mod surface, real selectors, preferences schema) and
[`../../ZEN_BROWSER.md`](../../ZEN_BROWSER.md) (Phase 2 = the Mod).

The bundle: `chrome.css` (the mod), `preferences.json` (one setting), `theme.json`
(metadata), `readme.md`, plus `image.png` (to be captured — see Submission).

---

## 1. Goal

Let the browser frame recede so attention stays with the work. Quiet the chrome —
desaturate/soften the toolbar, dim inactive tabs, rest the URL bar until focused —
*without adding any feature.* Of the three interventions scoped in the capability
surface (Quiet Chrome / Unified Tempo / Breathing Threshold), this is the lowest-risk
and most native, so it goes first.

## 2. Explicit non-goals

Quiet Chrome deliberately does **not**:

1. **Read, parse, observe, or style web page content.** It styles browser *chrome*
   only. The chrome/content line is exactly the Mod-vs-extension boundary
   (capability surface §1); crossing it is Phase 3, under the page-context consent rule.
2. **Carry any MAIA / Soullab / Spiralogic / Holoflower / oracle / consciousness
   branding** — no naming, imagery, palette, or copy. No protected Soullab IP. Even the
   `about:config` namespace is neutral (`uc.quiet-chrome.*`, *not* the `uc.maia.*` used
   as a placeholder in the capability surface draft).
3. **Impose its own colors.** It only adjusts saturation / contrast / opacity *relative
   to the user's chosen Zen theme* — match, don't override.
4. **Add features, panels, buttons, network calls, telemetry, or state.** Pure
   declarative CSS plus one preference.
5. **Introduce new motion.** The only transition is a settle on the properties it
   already quiets, and it is disabled under `prefers-reduced-motion`.
6. **Touch functional chrome** — tab muting, find-bar, workspace logic. Atmosphere only.
7. **Funnel toward MAIA.** It is a free gift; MAIA discoverability is not its job. The
   relationship value is in *being a good contribution*, not in advertising.

## 3. theme.json reconciliation (read before submitting)

The capability surface (§1) establishes that in the Zen theme-store, **`theme.json` is
auto-generated by the submission bot** — you don't hand-author and commit it. The
`theme.json` in this folder is therefore **not** a file to push to the store; it is the
**metadata to paste into the `create-theme` GitHub issue** (name, description, author,
tags, image). Keeping it here gives us one source of truth for that metadata.

## 4. Submission notes (Zen theme-store)

- **Where:** `github.com/zen-browser/theme-store`.
- **How:** open a GitHub issue with the **`create-theme`** template. A bot generates the
  files and opens the PR. Updates later = a PR. There is no review pipeline beyond the
  maintainers.
- **Files the submission uses:** `chrome.css`, `preferences.json` (optional), `readme.md`,
  `image.png`, plus the metadata fields (from `theme.json` here).
- **Author:** set your real GitHub handle in the issue (this draft uses
  `<your-github-handle>` as a placeholder).
- **`image.png`:** required, and **not yet created** — capture it from a live Zen install
  as a clean before/after of the quieted chrome. It must contain **no** MAIA/Soullab
  branding.
- **License:** contributing means **CC-BY-NC-SA 4.0 (NonCommercial)**. The CSS, once
  contributed, can't later be commercialized — which is consistent with the "gift, not
  product" framing. This is the reason no core Soullab IP goes in.

## 5. Verification before submission (runtime-unverified items)

Everything here is source-grounded but **not yet confirmed in a live Zen build**
(capability surface §6). Before opening the issue, verify via live-editing
(`toolkit.legacyUserProfileCustomizations.stylesheets` → edit `chrome/userChrome.css` →
hot-reload):

- [ ] Selectors behave in current Zen: `#navigator-toolbox`, `.tabbrowser-tab[selected] /
      [pending] / :not([selected]) .tab-content`, `#urlbar[focused]`.
- [ ] **Pref→CSS binding** for `uc.quiet-chrome.intensity`. Confirm whether the
      attribute form (Candidate A) or a string-pref media query (Candidate B) is what Zen
      honors; keep one, delete the other. **If neither works today, ship Soft-only** —
      drop or mark the dropdown inert rather than claim intensity that doesn't bind.
- [ ] `filter:` on `#navigator-toolbox` doesn't break popup/panel anchoring (`filter`
      creates a containing block). If anchoring breaks, scope the filter to inner toolbar
      elements instead of the whole `#navigator-toolbox`.
- [ ] Active tab stays fully legible at every intensity; no color is imposed on any theme.
- [ ] `prefers-reduced-motion` suppresses the transition.
- [ ] *(Optional refinement, capability surface §3.1)* once exact `--zen-*` color variable
      names are resolved in the inspector, consider overriding those instead of the blunt
      `filter:` for an even more native result.
- [ ] Capture `image.png` from the live install.

**Do not write the `create-theme` submission issue until this gate passes _and_ the mod has
been lived-in for several days.** Sequence (inhabit first, extend later): verify runtime →
capture screenshots → dogfood several days → refine → submit → join the community
conversation → only then discuss the larger "Field" mod. If it doesn't survive these tests,
you learn before the community does.

**The real acceptance test is atmospheric, not technical.** After several days, turn the mod
off. If nothing changes, it failed. If the browser suddenly feels more restless, more
visually demanding, more fragmented, it succeeded. "Do I miss it when it's gone?" outranks
selector validity — it's a harder criterion, and the one that actually matters.

## 6. After the handshake

Per capability surface §5, the follow-on is **one** "Field" mod with three
preference-gated layers (Quiet Chrome + Unified Tempo + Breathing Threshold), kept as a
single coherent install. The content-touching residual (page overlays, focus dimming)
stays in the Phase 3 extension, under the consent canon. Division of labor for the
partnership narrative: **Zen protects attention; MAIA protects continuity.**
