## The bookend invariant

Experimental configuration must remain invariant across the **entire** arm, not merely be
correct at the instant it begins.

Plugin installation and marketplace configuration are **user-scoped**: any other Claude Code
session can change them mid-arm. On 2026-08-24 the `soullab` marketplace was silently
repointed by another lane between one observation and the next, and the plugin itself became
uninstalled by an unwitnessed route. A preflight check alone would not have caught either.

So an arm is valid only if the state matches **before and after** the session:

```
BEFORE                                    AFTER
candidate checkout   dfbdef18d...         still dfbdef18d...
checkout             detached             still detached
tree                 clean                still clean
soullab-jarvis       (arm-defined state)  unchanged
marketplace source   /Users/soullab/jarvis-bench-dfbdef18   unchanged
model / CLI          recorded             unchanged
```

**If any bookend differs, VOID the arm.** Do not reason about whether the change mattered —
that reasoning is exactly the inference the instrument's guards exist to refuse.

### Operational requirement

No other Claude Code session may install, uninstall, enable, disable, add, remove or repoint
the `soullab` marketplace or plugin while an arm is running. Sessions that are genuinely
read-only with respect to plugin configuration may stay open. If that cannot be guaranteed,
close them for the duration of the arm.

it to anything, so Arm B on 2.1.243 would have been adjudicated ADMISSIBLE and
the pair would have differed in **two** variables — plugin *and* CLI — while

an environment fact present in the record but not gated.

### Amendment (freeze `8235fdb885b0` broken for this repair, then re-frozen)

Fail-closed, per arm — read from the **transcript**, which stamps `version` on
its records, so this is launch state and not machine state at postflight time:

```
record.cli_version == transcript.version     (also: one CLI across the whole arm)
record.model       == transcript model
record cli_version and launcher.version agree
```

Fail-closed, cross-arm (`arm-postflight.py --cross-check A.json B.json`):

```
A.cli_version == B.cli_version
A.model       == B.model
A.launcher.sha256 == B.launcher.sha256
```

The launcher is bound as `{path, realpath, version, sha256}` because this machine
carries mixed installs — `~/.local/share/claude/versions/2.1.243` on PATH beside
an app bundle at `2.1.237`. "The CLI version" is a property of the binary that
launches the arm, not of the machine. **Equivalence is never inferred from a
version string:** same version + different bytes is refused.
